# Feature Specification: FlowText Sole Editor — 以全自绘编辑器作为唯一正文编辑面

**Created**: 2026-10-05  
**Status**: Draft  
**Input**: User description: "确认「无法用原生富文本编辑器实现纯纯写作的全部写作体验」后，选择路线②：以 FlowText 全自绘编辑器作为唯一正文编辑面；正文范围＝纯文本＋基础行内格式（不含图片内联）；单篇目标 5 万字以内；打字机默认关闭；完成后移除原生引擎（真单引擎）。"

## Overview

Weaver 的正文编辑面目前可在两种实现间切换：系统原生富文本编辑器（默认）与自绘 FlowText（动画模式）。经官方 API 全面核验（含最新 API 版本）与真机验证，两类"标志性写作体验"能力——**打字机式「当前段垂直居中 / 滚动跟随」**与**「字符级动画（逐字淡入、光标动画、翻页过渡）」**——属于系统编辑组件能力边界之外，无法由原生方案实现（其全 API 面既无滚动定位，也无字符级动画；"外层滚动容器"变通亦实测不可行）。

本特性将自绘 FlowText 提升为**唯一**正文编辑面，交付三类能力：(1) 打字机居中/滚动跟随与字符级动画；(2) 达到系统级可用性的编辑正确性（输入法组合输入、光标、选区、命中）；(3) 正文基础行内格式（粗体/斜体/标题）。既有全部写作功能与数据流不变，完成后移除原生引擎与切换入口。

**已定案的关键决策**：正文范围＝**纯文本 + 基础行内格式（粗体/斜体/标题）**（**不含图片内联**）；单篇目标规模＝**≤ 5 万字**；打字机模式＝**默认关闭**；**移除原生引擎**，仅保留一条编辑实现路径。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 开箱即用的打字机写作体验 (Priority: P1)

用户打开 Weaver 即进入以全自绘编辑器呈现的正文面，无需切换任何"引擎/模式"。开启打字机模式后，当前书写段始终保持在视口垂直居中附近并随输入滚动跟随；输入字符以连贯的入场动画呈现，删除以消退动画收束，换行/回行过渡平滑。

**Why this priority**: 本特性存在的根本理由——把原生方案做不到的写作体验变为可用默认能力。缺少它，改造没有产品价值。

**Independent Test**: 打开应用新建文稿，开启打字机模式，连续输入/删除中英混合文本并多次折行，观察当前段是否保持居中、字符是否有连贯动画、已有文本是否稳定。

**Acceptance Scenarios**:

1. **Given** 应用已打开文稿且打字机模式为开，**When** 用户在某段内输入触发折行，**Then** 当前段中心与视口中心偏差始终保持在视口高度的 ±10% 以内，滚动过渡平滑无跳变。
2. **Given** 编辑区已有文本，**When** 用户连续输入 30 个以上字符，**Then** 字符以入场动画呈现，已有文本位置无可见跳动，光标稳定停在插入点之后。
3. **Given** 编辑区有多行文本，**When** 用户连续删除字符，**Then** 被删字符以消退动画收束，其余文本不跳，光标位置正确。
4. **Given** 打字机模式为关，**When** 用户常规输入与滚动，**Then** 行为与预期一致（无强制居中）。

---

### User Story 2 - 编辑正确性不逊于系统组件 (Priority: P1)

用户以中文/英文输入法正常写作，包括组合输入、候选上屏、预上屏；可用手指精确点击定位光标、长按选择、拖动选区手柄；命中字形边界与用户意图一致。

**Why this priority**: 自绘编辑器最大风险是正确性退化（点不准、光标错位、输入法不同步）。正确性不达标则不可日用。

**Independent Test**: 用中英混合、含标点与 emoji 的文本输入 200 字符，逐项验证内容、光标、选区与命中一致性。

**Acceptance Scenarios**:

1. **Given** 用户使用中文输入法组合输入，**When** 候选未提交，**Then** 预上屏文本正确呈现且不写入正文；提交后正文与光标位置准确。
2. **Given** 编辑区有文本，**When** 用户点击任意可见位置，**Then** 光标精确落在最近字形边界，无偏移或跳飞。
3. **Given** 编辑区有文本，**When** 用户长按并拖动选区手柄，**Then** 选区范围随手指连续更新，边界与字形一致。
4. **Given** 文本含 emoji/组合字符，**When** 用户删除一个字符，**Then** 整字形被删除，不留残缺码元。
5. **Given** 输入 200 字符中英混排文本，**Then** 内容与意图 100% 一致，光标全程位于插入点之后。

---

### User Story 3 - 正文富文本：行内格式 (Priority: P1)

用户可在正文中设置基础行内格式（粗体、斜体、标题/段落样式）；格式随文稿保存与再次打开保持一致。

**Why this priority**: 用户已明确要求正文支持行内格式；这是编辑器能力范围的一部分，属必须项。

**Independent Test**: 新建文稿，设置若干行内格式，保存后重开检查一致性；对格式执行撤销重做。

**Acceptance Scenarios**:

1. **Given** 用户在正文中选中文本，**When** 施加加粗/斜体/标题，**Then** 所选文本立即以对应样式呈现。
2. **Given** 正文已设置格式，**When** 用户保存并重新打开该文稿，**Then** 格式呈现保持一致。
3. **Given** 正文含格式，**When** 用户撤销/重做，**Then** 格式状态正确回退/恢复。

---

### User Story 4 - 既有写作功能零退化 (Priority: P1)

替换为唯一编辑面后，Weaver 既有的全部写作相关功能保持正常：新建/打开/关闭文稿、目录滑出面板、多标签、自动保存、字数统计、一键排版、查找替换、收藏/灵感、导入/导出、稿纸主题与深色模式。

**Why this priority**: 改造不能以牺牲既有功能为代价，这是上线底线。

**Independent Test**: 逐条执行既有编辑操作流程，对比改造前后行为一致性。

**Acceptance Scenarios**:

1. **Given** 用户处于编辑态，**When** 切换到其他文稿再切回，**Then** 正文与光标位置正确恢复，无混串或丢失。
2. **Given** 用户编辑后关闭标签页或切后台，**When** 重新打开，**Then** 自动保存生效且内容一致。
3. **Given** 编辑器显示正文，**When** 切换稿纸主题或深/浅色，**Then** 编辑区背景、文字、光标颜色立即同步。
4. **Given** 用户执行撤销/重做多次，**Then** 正文与光标回到正确状态。
5. **Given** 用户使用一键排版/查找替换，**Then** 结果与改造前一致，且可撤销。

---

### User Story 5 - 滚动与专注联动 (Priority: P2)

用户在阅读/书写时，上下滚动正文可自动隐藏顶栏与工具条以获得沉浸感，停止或反向滚动时恢复。

**Why this priority**: 提升沉浸感，属体验增强；不影响正确性，次于 P1。

**Independent Test**: 在长文中上下滚动，观察顶栏/工具条按预期隐藏/恢复。

**Acceptance Scenarios**:

1. **Given** 正文超过一屏，**When** 用户向下滚动，**Then** 顶栏与工具条隐藏；**When** 停止或向上滚动，**Then** 恢复。
2. **Given** chrome 已隐藏，**When** 用户点击屏幕上方区域，**Then** chrome 恢复且不误触正文。

---

### User Story 6 - 长文可用性与性能 (Priority: P2)

在单篇 ≤ 5 万字的写作场景下，输入、删除、滚动、定位保持流畅，无明显卡顿或掉帧；进入与内存不显著劣化。

**Why this priority**: 自绘方案主要风险之一是长文性能；长文不可用则产品不可交付。

**Independent Test**: 在 5 万字长文上执行连续输入、快速滚动、随机点击定位，测量响应与帧率。

**Acceptance Scenarios**:

1. **Given** 一篇 5 万字长文，**When** 用户连续输入，**Then** 输入响应及时且无明显掉帧。
2. **Given** 同一长文，**When** 用户快速上下滚动与随机点击，**Then** 无卡死、无白屏、定位准确。
3. **Given** 应用冷启动进入长文，**Then** 进入可编辑态时间在可接受范围内。

---

### User Story 7 - 单引擎收敛 (Priority: P3)

改造完成后，正文编辑面只保留一条实现路径，消除"双引擎"的模式切换、体验分裂与双份维护；设置中的切换入口同步移除。

**Why this priority**: 收敛是附带收益与长期可维护性要求，不直接影响当次可用性。

**Independent Test**: 检查设置不再有"编辑引擎"切换项；代码中仅存在一条可用编辑实现路径。

**Acceptance Scenarios**:

1. **Given** 应用设置页，**When** 用户查看，**Then** 不再有"正文编辑引擎"切换项。
2. **Given** 代码库，**When** 检索正文编辑面，**Then** 仅存在一条可用编辑实现路径。

---

### Edge Cases

- **输入法组合中被打断**：组合输入（未提交）时切换文稿、失焦、切后台，预上屏文本应被正确丢弃或提交，不写入残缺内容。
- **富文本边界**：格式跨段落、重叠格式的合并/拆分、纯格式无文本、格式与换行相邻。
- **超长无空格串**：无空格长串或西文长单词的折行与命中。
- **整篇操作**：全选、全选替换、整段删除、清空全文后的光标与状态。
- **文档边界**：光标位于文档首/尾、空文档、仅一个换行时。
- **视觉参数变更**：切换主题/深色、调整字号或行距时的重排与重绘。
- **滚动边界**：滚动到顶/底后的继续拖拽；打字机居中与用户手动滚动的冲突。
- **多码元字形**：emoji、组合字符、代理对的命中与整体删除。
- **历史边界**：撤销到空历史、重做到底。
- **撤销/回灌与动画并发**：撤销回灌正文时动画不产生错位或残留。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 以自绘编辑器作为**唯一**正文编辑面；完成后移除原生引擎与"引擎切换"入口。
- **FR-002**: System MUST 支持中文与英文输入法的组合输入、候选上屏与预上屏文本的正确呈现与提交。
- **FR-003**: System MUST 支持点击精确定位光标、长按选择、拖动选区手柄连续更新选区。
- **FR-004**: System MUST 在"打字机模式"开启时使当前书写段保持视口垂直居中附近并随光标滚动跟随；**默认关闭**，关闭时恢复常规滚动。
- **FR-005**: System MUST 提供字符级动画：新增字符入场、删除字符消退、换行/回行过渡连贯，且不导致已有文本跳动或光标错位。
- **FR-006**: System MUST 在正文滚动时按策略隐藏/恢复顶栏与工具条。
- **FR-007**: System MUST 在切换文稿、切后台往返、撤销/重做、导入/排版回灌后，保证正文与光标准确恢复，无错位、无丢字。
- **FR-008**: System MUST 与既有编辑状态契约保持一致（内容变更、光标变更、主动保存、撤销/重做）。
- **FR-009**: System MUST 保证既有写作功能不退化：新建/打开/关闭、目录面板、多标签、自动保存、字数统计、一键排版、查找替换、收藏/灵感、导入/导出、稿纸主题与深色模式。
- **FR-010**: System MUST 在单篇 **≤ 5 万字**的长文场景下保持输入与滚动流畅（门限见成功标准）。
- **FR-011**: System MUST 保证构建通过、无新增编译错误。
- **FR-012**: System MUST 在视觉参数（字号、行距、背景、文字、光标、选区色）变更时立即重排/重绘。
- **FR-013**: System MUST 支持正文**基础行内格式**：粗体、斜体、标题/段落样式的设置与呈现。
- **FR-014**: System MUST 使行内格式正确参与撤销/重做与回灌。
- **FR-015**: System MUST 保持正文**纯文本 + 基础行内格式**的边界：**不含图片内联与更高级富文本**。
- **FR-016**: System MUST 在数据落库与撤销/重做中保持与既有存储契约兼容，历史数据可直接打开与继续编辑。

### Key Entities *(include if feature involves data)*

- **自绘编辑器组件**：正文编辑面的核心可见组件，负责呈现与交互，对外暴露文本与光标事件。
- **编辑器控制器**：供应用层外部驱动编辑器（载入文本、设置光标、聚焦/失焦等）。
- **文本模型**：正文的字符序列与其字形/段落结构，是命中、选区、布局、渲染的共同依据。
- **富文本片段**：正文中的最小内容单元（文本，可带行内格式标注）。
- **格式标注**：施加在文本片段上的行内格式（粗体/斜体）与段落样式（标题/正文）。
- **输入法桥接**：负责与系统输入法交互（组合输入、预上屏、提交/取消）。
- **命中测试**：把屏幕坐标映射到字形边界/位置。
- **选区管理**：维护光标与选区范围及其手柄。
- **布局引擎与排版缓存**：计算行/字形位置，支撑渲染与命中。
- **渲染器**：把文本、格式与光标/选区绘制到画布。
- **动画器**：驱动字符入场/消退、光标与滚动过渡。
- **编辑器主题**：字号/行距/颜色等视觉参数集合，与稿纸主题联动。
- **编辑宿主**：应用层与自绘编辑器之间的桥接组件，维持既有对外契约。
- **编辑状态仓库**：管理已打开文稿、当前文稿、正文草稿、光标、保存态与撤销/重做历史。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在**默认**编辑面即可完成全部核心写作操作（输入、删除、定位、选择、格式、保存、撤销），**无需切换任何模式**；核心操作一次成功率 100%。
- **SC-002**: 打字机模式**开启时**，任意时刻当前段中心与视口中心偏差 ≤ 视口高度 ±10%，滚动过渡无可见跳变；**关闭时**不强制居中。
- **SC-003**: 连续输入 30 字符与连续删除 30 字符过程中，已有文本可见位移抖动为 0（位置误差 ≤ 1 个字符宽度）。
- **SC-004**: 输入 200 字符中英混排（含标点与 emoji）文本后，内容与意图一致率 100%，光标始终位于插入点之后，点击命中字形与意图一致。
- **SC-005**: 行内格式（粗/斜/标题）设置后保存并重开，呈现一致率 100%；格式操作的撤销/重做正确率 100%。
- **SC-006**: 在 5 万字长文下，输入响应 < 50ms、滚动 ≥ 50fps，无卡死/白屏。
- **SC-007**: 既有写作功能回归测试失败项为 0（覆盖新建/打开/关闭、切换恢复、自动保存、撤销/重做、排版、查找替换、主题/深色、导入导出）。
- **SC-008**: 切换文稿/后台往返 20 次，正文与光标恢复准确率 100%，无内容混串。
- **SC-009**: 设置页不再出现"编辑引擎"切换项；检索代码库仅存在一条可用编辑实现路径。

## Assumptions

- FlowText 自绘编辑器已在独立项目完成基础可用性验证（点击定位、光标、增删、输入法链路），源码可作为内联模块继续演进。
- 既有编辑状态契约与稿纸主题系统可复用；应用层对外行为不变。
- **正文范围**确定为纯文本 + 基础行内格式（粗/斜/标题）；**图片内联与更高级富文本（表格、列表嵌套、图片、复杂多媒体）不在本次范围**。
- **单篇目标规模 ≤ 5 万字**；超出规模的极端长文性能不在本次承诺内。
- **打字机模式默认关闭**，属可开关增强。
- 完成后**移除原生引擎**与切换入口，仅保留一条编辑路径。
- 不改变文稿数据模型与存储格式，历史数据可直接打开。
- **移动端优先**；平板/PC 多端适配在后续迭代处理。
- 本改造范围大，建议**分期交付**（先文本正确性 + 打字机/动画，再行内格式，最后移除原生引擎收敛），具体分期在规划阶段确定。

## Open Questions

- 无未决项。澄清结论：正文范围＝纯文本 + 基础行内格式（粗/斜/标题），**不含图片内联**；长文规模＝单篇 ≤ 5 万字（输入 < 50ms、滚动 ≥ 50fps）；打字机默认关闭且移除原生引擎（真单引擎）。
- 若分期交付，分期边界在规划阶段与干系人确认。
