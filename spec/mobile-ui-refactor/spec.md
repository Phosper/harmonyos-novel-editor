# Feature Specification: 手机端 UI 重构 —— 断点栅格驱动的移动端体验重做

**Created**: 2026-10-03
**Status**: Draft
**Input**: 用户描述："查看项目目前代码，重点进行手机端UI重构，目前的UI太丑，要求进行截图验证，同时暂且保持电脑、平板的UI不动，根据栅格系统的不同大小切换UI布局，要求严格按照华为官方文档来。"

## Overview

Weaver 是一款鸿蒙原生小说/长文本编辑器，当前采用"侧边栏 + 文稿列表 + 工作区"三分栏外壳，在平板/电脑形态下表现良好，但在**手机形态（窄窗口 `sm`）下体验糟糕**：顶部是一整条堆叠的文字按钮（`侧栏｜书名｜撤销 重做 导出 导入 设置`），工作区再叠加"文稿/素材/关系图"文字页签与编辑器工具条，一屏出现三层横向文字条，信息过载、热区不足、缺少视觉层级——这正是用户所说"太丑"的主因。

本特新聚焦**手机端 UI 重构**：按华为官方"一次开发多端部署 / 响应式布局 / 栅格系统 / 优雅简洁设计"规范，为手机形态设计以**底部页签导航 + 单列沉浸内容**为核心的新界面，并以**官方系统断点**在 `sm`（单列）与 `md`（双栏）之间切换布局，同时**严格保持 `lg` 及以上（平板/电脑）现有 UI 完全不变**。所有改动以**实机截图**逐故事验证。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机端底部页签主导航 (Priority: P1)

用户打开 Weaver 进入主界面，看到的是一个干净的单列界面：顶部只有一个高度受控的精简标题栏（应用/项目名 + 必要的返回或更多入口），底部是图标+文字的页签栏，承载「文稿 / 素材 / 关系图」等核心板块，并可从清晰入口进入「项目/文库」。用户点底部页签即可在核心板块间切换，不再面对一屏多层的文字按钮条。

**Why this priority**: 导航是手机端一切的骨架；先解决"一屏三层文字条"的信息过载，才能谈"优雅简洁"。这是本次重构最核心、最可见的价值。

**Independent Test**: 在手机断点（`sm`）冷启动进入主界面，验证：① 存在底部页签栏且可切换；② 顶部标题栏只有受控的少量元素；③ 不存在旧版一整条文字工具条；④ 项目/文库入口可达。

**Acceptance Scenarios**:

1. **Given** 手机断点冷启动应用，**When** 主界面加载完成，**Then** 屏幕底部显示页签栏（≥2 个、≤5 个页签），当前页签有明确选中态。
2. **Given** 主界面，**When** 点击底部"素材"页签，**Then** 内容区切换为素材视图且选中态同步，无横向溢出的文字按钮条出现。
3. **Given** 主界面，**When** 点击项目/文库入口，**Then** 可在项目/文库分类间浏览与切换，且返回后停留在原板块。
4. **Given** 手机断点，**When** 观察顶部标题栏，**Then** 常驻元素仅包含标题与最多 2 个操作入口，其余功能收纳至菜单。

---

### User Story 2 - 沉浸式单列写作编辑器 (Priority: P1)

用户在手机端打开/新建一篇文稿，进入专注的单列编辑视图：正文占据主要面积，编辑区左右保留符合官方栅格规范的舒适边距；格式切换（TXT/MD）、收藏/灵感、撤销/重做等**次要操作不再常驻横向占位**，而是收纳到"更多"菜单或键盘上方工具条；保存状态与字数以弱化的方式呈现。

**Why this priority**: 写作是 Weaver 的核心价值；手机端编辑器必须"退让"到只留正文，才能兑现"专注写作"的定位。

**Independent Test**: 手机端打开一篇文稿，输入中英文混合文本，验证编辑区可输入、自动保存状态更新、字数更新，且顶部无多层文字工具条。

**Acceptance Scenarios**:

1. **Given** 手机端主界面，**When** 从文稿列表点开一篇文稿，**Then** 进入覆盖式单列编辑页，正文可正常输入。
2. **Given** 手机端编辑页，**When** 用户需要切换 TXT/MD 或收藏/灵感，**Then** 可通过"更多"入口或键盘上方工具条完成，操作后状态正确。
3. **Given** 手机端编辑页，**When** 编辑停顿，**Then** 自动保存生效，保存状态提示更新，字数正确。
4. **Given** 手机端编辑页，**When** 点击返回，**Then** 回到文稿列表，正文与光标位置正确保留。

---

### User Story 3 - 手机端列表 / 素材 / 二级页统一视觉 (Priority: P2)

用户在手机端浏览文稿列表、项目/文库、素材（人物/世界观/灵感）以及二级详情页（人物详情、世界观详情、灵感记录、设置、引导页）时，页面风格统一：卡片/列表项有舒适边距与圆角，标题与摘要层级清晰，长按/点击操作可用，深色与浅色模式观感一致。

**Why this priority**: 重构后若只有主壳变好看、内容页仍旧，观感会割裂；统一视觉才能达成整体"优雅简洁"。

**Independent Test**: 在手机端依次浏览文稿列表、素材三类、一个二级详情页、设置页，验证边距/字号/热区/圆角/明暗色一致且无溢出。

**Acceptance Scenarios**:

1. **Given** 手机端文稿列表，**When** 浏览与搜索文稿，**Then** 列表项层级清晰、可点开、可长按唤出操作菜单。
2. **Given** 手机端素材视图，**When** 在人物/世界观/灵感三个标签间切换并新建条目，**Then** 呈现一致、操作可用。
3. **Given** 手机端任一二级页，**When** 打开与返回，**Then** 有统一标题栏与返回入口，且响应系统返回。
4. **Given** 手机端任一主要页面，**When** 切换深色/浅色模式，**Then** 正文对比度良好，无硬编码浅色块突兀出现。

---

### User Story 4 - 断点 / 栅格驱动的响应式布局切换 (Priority: P2)

用户在使用中改变窗口尺寸、旋转手机或开合折叠屏时，界面依据**官方系统断点**平滑切换：`sm`（手机竖屏）为单列 + 底部页签；跨入 `md`（手机横屏 / 折叠展开等中等宽度）切换为侧栏 + 内容的双栏；进入 `lg` 及以上（平板/电脑）则**保持重构前的三栏布局与视觉完全不变**。内容区使用官方栅格系统组织列表列数与正文缩进，避免正文行宽过宽。

**Why this priority**: 这是用户明确要求的"根据栅格系统的不同大小切换 UI 布局"；也是"保持平板/电脑不动"这一约束的落点。

**Independent Test**: 将窗口从手机宽度逐步放大/旋转跨过断点，验证 sm→md 处布局切换正确、lg 处与改造前截图逐像素级一致（无回归）。

**Acceptance Scenarios**:

1. **Given** 手机竖屏 `sm`，**When** 旋转为横屏或扩大到 `md`，**Then** 布局切换为侧栏 + 内容双栏，且切换过程无错乱/截断。
2. **Given** `md` 双栏布局，**When** 缩小回 `sm`，**Then** 恢复单列 + 底部页签。
3. **Given** 平板/电脑形态 `lg`，**When** 打开应用与各页面，**Then** 布局与视觉与改造前保持一致（不受本次重构影响）。
4. **Given** `md` 或 `lg` 的宽内容区，**When** 显示正文/长列表，**Then** 内容按栅格居中留白或按列排布，不出现过长行宽。

---

### Edge Cases

- **折叠屏开合**：开合过程中窗口尺寸与断点刷新必须由系统尺寸变化监听驱动，不得依赖折叠状态判断；开合前后任务连续性不能破坏（正文不丢、光标位置可恢复）。
- **分屏 / 悬浮窗**：上下分屏会显著压缩可用高度，主界面与编辑区必须可滚动，底部页签不得遮挡最底部内容。
- **系统字体放大**：将系统字号调大至 1.75 倍及以上时，页面不得错乱、组件不得叠加、文字不得截断。
- **首次启动引导页**：手机端首启引导页在不破坏既有引导逻辑的前提下统一视觉；已引导用户直接进入新主界面。
- **无文稿 / 无素材空状态**：手机端空状态需有清晰引导文案与可操作入口，不留白屏。
- **深色模式**：切到深色后不得出现浅色硬编码背景块；稿纸主题（素白/青笺/茶墨/夜读）在手机端编辑区正常呈现。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 手机形态（`sm` 断点）主界面 MUST 采用**底部页签导航**（官方 `Tabs` 底部栏范式），页签承载核心板块（至少含「文稿」「素材」「关系图」），当前页签 MUST 有明确选中态。
- **FR-002**: 手机端 MUST 提供进入「项目/文库」的清晰入口，用户可在项目与文库分类间浏览、切换，返回后回到原板块。
- **FR-003**: 手机端 MUST 移除旧版一整条堆叠的文字功能条；顶部精简标题栏常驻元素 MUST 不超过（标题 + 2 个操作入口），其余功能收纳至菜单。
- **FR-004**: 手机端打开文稿后 MUST 为**单列沉浸编辑视图**，正文占据主要面积；格式切换、收藏/灵感、撤销/重做等次要操作 MUST 收纳到"更多"菜单或键盘上方工具条，不常驻横向占位。
- **FR-005**: 手机端所有主要可点击元素 MUST 满足最小热区（推荐 48vp × 48vp，不得小于 40vp × 40vp）；文本字号 MUST 不小于 12fp（界面图标不小于 8vp）。
- **FR-006**: 手机端 MUST 使用明暗双主题的语义色，正文与背景对比度 MUST ≥ 4.5:1、图标与标题文字对比度 MUST ≥ 3:1；深色模式下 MUST NOT 出现硬编码浅色块。
- **FR-007**: 布局 MUST 以**官方系统窗口宽度断点**为唯一判据在 `sm` / `md` / `lg` 间切换；MUST NOT 通过设备类型、屏幕方向或是否可折叠等属性判断布局分支。
- **FR-008**: 布局在断点边界的呈现 MUST 为：`sm` 单列 + 底部页签；`md` 侧栏 + 内容双栏；`lg` 及以上 MUST 保持现有三栏布局与现有视觉不变（零回归）。
- **FR-009**: 内容区 MUST 使用官方栅格系统组织列表/卡片列数与正文缩进；MUST NOT 出现所有栅格子项占列恒等于父容器总列数的无效用法，占列/偏移 MUST NOT 使用小数。
- **FR-010**: 手机端主要页面尺寸 MUST 使用 vp、字号 MUST 使用 fp；MUST NOT 混用 px 与 vp 造成大屏/缩放错乱。
- **FR-011**: 手机端二级页面（设置 / 人物详情 / 世界观详情 / 灵感记录）与首启引导页 MUST 提供统一标题栏与返回入口，并响应系统返回操作。
- **FR-012**: 现有全部功能 MUST NOT 退化：新建/打开/关闭文稿、自动保存、字数统计、撤销/重做、TXT/MD 切换、收藏、灵感池、废纸篓、素材增删改、关系图、导出/导入、深浅色与稿纸主题、引导页。
- **FR-013**: 布局刷新 MUST 监听系统窗口尺寸变化；折叠开合、分屏、悬浮窗等窗口形态变化 MUST 通过断点与尺寸监听适配，不得依赖折叠状态判断。
- **FR-014**: 手机端主界面与编辑区 MUST 可滚动，底部页签 MUST NOT 遮挡可滚动内容的最底部功能；弹出/半模态 MUST 向上避让系统导航条与软键盘。
- **FR-015**: 每个用户故事 MUST 以**实机截图**进行验证（每故事至少 1 张关键界面截图），并在人工复核后记录结论。

### Key Entities *(feature involves UI state and layout)*

- **断点档位（BreakPoint）**：由官方系统窗口宽度断点派生的三档 `sm` / `md` / `lg`，是布局切换的唯一判据。
- **手机端导航壳（Mobile Shell）**：手机形态下的页面骨架，包含精简标题栏、内容区与底部页签栏。
- **底部页签集合（Bottom Tabs）**：手机端核心板块入口（文稿 / 素材 / 关系图 + 项目入口），含图标、文字与选中态。
- **沉浸式编辑视图（Mobile Editor View）**：手机端打开文稿后的单列编辑页，含弱化保存态/字数与收纳式次要操作。
- **响应式内容网格（Responsive Grid）**：用官方栅格系统组织的列表列数、卡片排布与正文缩进。
- **设计令牌（Design Tokens）**：单一来源的明暗双主题语义色、圆角、间距与关键结构尺寸（标题栏 / 页签栏高度）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 手机形态（`sm`）主界面 100% 呈现底部页签导航；任意一屏均不出现横向溢出的多层文字按钮条。
- **SC-002**: 抽查手机端 20 个主要可点击元素，热区均 ≥ 40vp（其中 ≥ 90% 达到 48vp 推荐值）。
- **SC-003**: 手机端主要页面在浅色与深色两种模式下，正文对比度均 ≥ 4.5:1，图标/标题文字对比度 ≥ 3:1。
- **SC-004**: 将窗口从 `lg` 与改造前对比，平板/电脑形态的布局与视觉差异为 **0**（无回归、无布局改变）。
- **SC-005**: 手机端核心写作流程（进入 → 选文稿 → 编辑 → 自动保存）全程无空屏、无崩溃；字数统计与自动保存结果正确。
- **SC-006**: 手机端跨断点（`sm` ↔ `md`）切换正确，无截断、错位或内容丢失；`lg` 切换不触发任何新布局。
- **SC-007**: 每个用户故事至少 1 张实机截图通过人工复核；总计 ≥ 4 张关键界面截图。
- **SC-008**: 重构后项目构建通过（无新增编译错误），现有功能逐项回归无一退化。

## Assumptions

- **"手机形态" 定义为 `sm` 断点（窗口宽度 < 600vp）**；`md`（600–840vp，含手机横屏、折叠展开、小平板）在用户选择下切换为双栏；`lg` 及以上（平板/电脑）保持重构前 UI 不变。
- 用户已确认**将连接真机或启动模拟器**，截图验证通过设备端截图能力完成；若最终无设备，需在交付说明中如实记录并降级为构建验证。
- **不引入 UI Design Kit 第三方套件**（`HdsNavigation` / `HdsSideBar` 等，仅中国境内可用且模拟器不支持其光影视效），本次重构沿用 ArkUI 原生组件（`Tabs` / `SideBarContainer` / `Navigation` / `GridRow` / `GridCol` 等）。
- 底部页签采用官方范式：底部栏位置 + 固定模式 + 图标加文字自定义页签；栏高参考官方 56vp（叠加底部系统避让区）。
- **颜色令牌沿用现有集中式机制**（`constants/DesignTokens.ets` 的明暗双主题语义色），本次以保证明暗对比达标与观感统一为目标，不扩大到全仓资源限定词改造（如改用 `$r` 系统色资源）。
- 现有三分栏架构（`SideBarContainer` + `Navigation`）在 `lg` 保持；`sm`/`md` 通过断点分支复用或新增组件实现，不改动业务状态与数据层。
- 现有 FlowText 自绘编辑器、自动保存、数据层（RDB）等核心逻辑不在本次范围内改动，仅调整其外层容器/工具条的手机端排布。
- PC 窗口控制条（自绘标题栏）与桌面形态专属行为保持不变。

## Open Questions

- [NEEDS CLARIFICATION: 手机端「项目/文库」的承载方式——作为底部页签之一（则页签为 项目 / 文稿 / 素材 / 关系图 共 4 个），还是作为标题栏入口 + 抽屉？官方建议页签 2–5 个，两种均可行，需产品拍板。]
- [NEEDS CLARIFICATION: `md` 断点（含手机横屏与"小平板/折叠展开"）切换为双栏后，是否允许其同时套用新的视觉风格？若小平板用户群重要，可能需对 `md` 采用"窄三栏或保守双栏"以免与"平板保持不动"的诉求冲突。]
- [NEEDS CLARIFICATION: 颜色令牌本次是否改为官方 `$r('sys.color.*')` 资源引用以满足 `color-value` 检查规则？改为资源引用更合规但改动面大，保持现有集中式令牌则改动小但仍有硬编码。]
