# 卡片内容：用户旅程调研（改代码前）

> 状态：调研稿，**未改代码**。
> 方法：基于当前源码的启发式走查 + 既有规格/原型对照 + 角色任务拆解；**尚未做真实用户访谈**，文中标注“待验证”的均为假设。
> 范围：思路板里“卡片内容”的创建、捕获、编辑、组织、产出、复用、维护；不覆盖视觉主题、窗口框架、备份恢复本身。

## 0. 结论摘要

1. **内容模型是完整的，编辑面是缺失的。** 卡片有标题/别名/标签/一句话，素材有引文/判断/笔记，写作卡有子卡与初稿；但除“新增”外，几乎所有内容都不可修改。
2. **捕获链路断裂。** 编辑器已有选区读数与定位 API，但没有任何“选中文字 → 加到卡片”的入口；抽屉里新建的“引文”来源字段全空，`跳回原文` 对新建引文永远不可用。
3. **结构组织依赖拖拽。** 写作卡不能直接“＋章”，必须先去卡片库建卡再拖入；对“写论文”这个主场景，这是最高频摩擦。
4. **产出后回不去。** 初稿生成后 `doc_id` 存了，但卡片上没有“打开初稿”；重生成只能新建；写作卡自己的素材不进初稿。
5. **破坏性操作不可逆。** 删素材、删卡、移出白板都没有撤销；错一个字只能删卡重建。最近两轮“残留/自动回去”问题，本质是缺少唯一约束与可视诊断。

## 1. 角色与任务

| 角色 | 典型场景 | 核心任务（JTBD） | 成功标准 |
|---|---|---|---|
| R1 研究生（主） | 国际关系/社科论文，读文献—搭框架—写初稿 | 把读到的东西变成可引用的素材，再把素材组织成能写的章节 | 一条引文 10 秒内进卡；从 0 到三层大纲不离开画布；初稿能直接接着写 |
| R2 课程报告作者 | 一学期 2–3 篇课程论文 | 快速收集观点、搭轻量结构、按时交稿 | 30 分钟内搭出 3–5 章；不必学“卡片/白板”概念 |
| R3 内容创作者 | 多项目、多平台复用素材 | 同一素材在不同项目里复用，保留出处 | 卡片跨白板复用；改一次全处生效（或明确仅此板） |

> 待验证：R2 是否真的需要“写作卡”这一层，还是只需要“大纲列表”。

## 2. 内容生命周期

```text
捕获（读/听/想） → 澄清（标题/别名/一句话） → 组织（挂到写作卡/排序）
   → 产出（写成初稿） → 回流（初稿里继续补素材） → 复用（另一块板/另一本书） → 维护（改名/合并/删除/撤销）
```

当前实现覆盖了“捕获（手打）、组织（拖拽）、产出（一次性生成）”，**澄清、回流、维护、复用后的编辑基本为空**。

## 3. 现状旅程

### J1 从零建写作卡与第一章

| 阶段 | 用户动作 | 系统现状 | 摩擦 | 严重度 |
|---|---|---|---|---|
| 进板 | 四点菜单 →「思路板」 | 全窗口打开，默认最近白板 | 无 | — |
| 建写作卡 | 顶栏「＋ 卡片」或卡片库「＋ 新建卡片」 | 只收标题 + 类型；创建后自动落在视口中心/默认点 | 不能同时填别名、一句话；标题打错不能改 | S1 |
| 加第一章 | 去卡片库建概念卡 → 拖到写作卡上 | 只能“先建后拖”；写作卡内没有「＋ 章」 | 两次上下文切换；拖拽失败时只有 toast | S1 |
| 确认结构 | 看写作卡副标题「N 章 · 含 N 张子卡」 | 有计数 | 行标题不能就地改；不能插到指定位置 | S2 |

**期望**：建写作卡时就能写一句话/别名；写作卡里直接「＋ 章」，新章默认命名“第 N 章”并立即可改名。

### J2 阅读中捕获引文

| 阶段 | 用户动作 | 系统现状 | 摩擦 | 严重度 |
|---|---|---|---|---|
| 阅读 | 在编辑器选中一段 | 编辑器有 `getSelection/getSelectedText`，`CanvasSelectionBridge` 也有，但**无任何 UI 调用** | 选中后没有任何“加到卡片”的动作 | S1 |
| 切到画布 | 关闭/返回思路板 | 思路板是全窗口分支，编辑器在另一路由；需要退出再进 | 上下文丢失；没有“带着选区进画布” | S1 |
| 加素材 | 打开卡片 →「＋ 添加素材」→ 选「引文」→ 手打/粘贴 → 保存 | `submitEvidence` 把 `docId/startOff/endOff/fingerprint/sourceLabel` 全写成空/-1 | 引文没有出处；`跳回原文` 永远提示“请先打开该文稿” | S1 |
| 回原文 | 点「跳回原文」 | 仅当 `ev.docId !== ''` 且当前文稿匹配才生效 | 新建引文永远不满足 | S1 |

**期望**：选中文字 → 浮层/工具条「加到卡片」→ 选卡或新建卡 → 自动带 `docId/偏移/出处/指纹`；从卡片可跳回并高亮。

### J3 写判断/笔记

| 阶段 | 用户动作 | 系统现状 | 摩擦 | 严重度 |
|---|---|---|---|---|
| 记录 | 抽屉 →「＋ 添加素材」→ 判断/笔记 → 输入 → 保存 | 三种类型共用一个文本框；无标签、无来源 | 判断与笔记只靠类型区分，不能打标签/关联原文 | S2 |
| 修改 | 想改一个错字 | **没有编辑入口**；只能删了重加 | 丢时间戳与上下文 | S1 |
| 整理 | 想调整素材顺序 | 按 `createdAt` 排序，无上移/下移/拖拽 | 重要素材无法置顶 | S2 |
| 删除 | 点行内「删除」 | 立即删除，无确认、无撤销 | 误触成本高 | S1 |

### J4 搭三层大纲（嵌套/排序）

| 阶段 | 用户动作 | 系统现状 | 摩擦 | 严重度 |
|---|---|---|---|---|
| 嵌套 | 把卡拖到目标卡上，等张嘴缺口，松手 | 命中/张嘴/30vp 阈值；深度上限 3 | 需要精准拖拽；失败只有 toast；最近出现过“残留/自动回去” | S1 |
| 排序 | 行尾 ▲▼；或拖行到空白再拖回 | `reorderCard(delta)` 只能上下一位；无“移到指定位置” | 大结构重排成本极高 | S2 |
| 改名 | 想改章标题 | 行标题来自子卡 `title`，不可就地改 | 只能改子卡（但也没有编辑入口） | S1 |
| 移出 | 行尾 ↗ 拖出，或抽屉「从父卡移出」 | 可用；但重复贴放历史数据会让“移出”打空 | 需要数据层唯一约束兜底 | S1 |

### J5 写成初稿并继续写

| 阶段 | 用户动作 | 系统现状 | 摩擦 | 严重度 |
|---|---|---|---|---|
| 生成 | 写作卡「写成初稿」 | 新建 MD 章节 → 写 content+format_runs → `setCardDocId` → `openChapter` → **`nav.pop()`** | 全窗口改造后 `nav.pop()` 会弹路由栈，可能回到错误页面/画布仍盖着 | S1（回归） |
| 打开初稿 | 想从卡片回到这篇稿 | 抽屉与卡片都**不显示 docId / 无“打开初稿”** | 生成后找不回 | S1 |
| 重生成 | 改了结构再点「写成初稿」 | 永远新建一篇，旧稿保留 | 用户会得到一堆近似稿；无覆盖选项 | S2 |
| 写作卡自身素材 | 在写作卡上加判断/引文 | 允许添加，但 `CanvasDraftWriter` 只遍历子卡 | 素材静默丢失 | S1 |
| 回流 | 在初稿里继续写，想补一条引文回卡 | 编辑器没有“加到卡片” | 只能再切回画布手打 | S1 |

### J6 复用卡片到另一块白板/另一本书

| 阶段 | 用户动作 | 系统现状 | 摩擦 | 严重度 |
|---|---|---|---|---|
| 找卡 | 打开卡片库，搜索标题/别名/标签 | 可搜索；列表**无类型标识、无排序** | 概念/写作分不清；卡多了难找 | S2 |
| 放卡 | 「放到当前白板」 | 已在当前板则禁用 | 不能“从当前板移除”；不能批量放 | S2 |
| 跳板 | 抽屉显示「出现在：A / B」 | 只是文本 | 不能点进去 | S3 |
| 编辑共享 | 想改一张在多板使用的卡 | 目前不能改；将来改了会影响所有板 | 需要“共享提示/仅此板覆盖”的产品决策 | S2 |

### J7 维护：改名、改素材、删除、撤销

| 阶段 | 用户动作 | 系统现状 | 摩擦 | 严重度 |
|---|---|---|---|---|
| 改标题 | 双击/菜单改名 | 无入口；`CanvasStore` 只有 `setCardDocId`，`updateCard` 在仓储层但 UI 未接 | 错字只能删卡重建 | S1 |
| 改素材 | 点素材编辑 | 无 `updateEvidence` API，也无 UI | 同上 | S1 |
| 删卡 | 抽屉底部「删除卡片」两步确认 | 可删；无撤销 | 误删不可恢复 | S1 |
| 撤销 | 误操作后想恢复 | 编辑器有 undo，画布没有 | 两套心智 | S1 |
| 诊断 | 卡“放进去了但看不到” | 只有 toast；无“这张卡在哪、父是谁”的可视诊断 | 只能靠日志 | S2 |

### 横切旅程

| 场景 | 现状 | 问题 |
|---|---|---|
| 首次使用 | 默认板 + 空态「从卡片库新建或放一张卡」 | 没有 30 秒上手路径；不知道“写作卡/概念卡”区别 |
| 失败/离线 | Store 内消化异常，`error` 字符串给 UI；无重试队列 | 保存失败只看到 error 文本；不知道哪条没保存 |
| 移动端 | 抽屉全屏、表单在底部；全局 `KeyboardAvoidMode.NONE` | IME 可能盖住输入框；底部危险按钮离“保存”太近 |
| 2in1 | 顶栏/抽屉已避让 `captionInset` | 抽屉头部的三键避让需真机确认；右键菜单缺失 |
| 无障碍 | 部分行有 accessibilityText | 编辑字段无标签；拖拽无键盘替代；焦点顺序未定义 |

## 4. 痛点登记表

| ID | 痛点 | 证据（代码/交互） | 影响 | 严重度 |
|---|---|---|---|---|
| J-01 | 新建引文没有来源 | `EvidenceDrawer.submitEvidence` 写空 docId/offsets | 引文不可追溯、不可跳回 | S1 |
| J-02 | 编辑器选区无法进卡 | `CanvasSelectionBridge` 无调用点 | 捕获必须手打/复制粘贴 | S1 |
| J-03 | 标题/别名/标签/一句话不可编辑 | 无 UI 调 `updateCard` | 错字只能删卡重建 | S1 |
| J-04 | 素材不可编辑/排序 | 无 `updateEvidence`；按 createdAt | 维护成本高 | S1 |
| J-05 | 写作卡不能直接加章 | 行区只有 ▲▼↗ | 建大纲需两界面往返 | S1 |
| J-06 | 生成初稿后回不去 | 卡片无 docId 入口 | 产出与卡片断链 | S1 |
| J-07 | 重生成总新建 | `writeDraft` 固定 createChapter | 近似稿堆积 | S2 |
| J-08 | 写作卡自身素材不进初稿 | `CanvasDraftWriter` 只遍历 rows | 静默丢内容 | S1 |
| J-09 | 删除无撤销 | `deleteEvidence/deleteCard` 直接落库 | 误删不可恢复 | S1 |
| J-10 | 连线无 UI | shell 无 `addLink/deleteLink`；`edgeLines` 永远空 | 功能“看得见代码、用不到” | S2 |
| J-11 | 卡片库无类型/排序/删除/批量 | `CardLibrary` 只有搜索+放卡 | 卡多了难管理 | S2 |
| J-12 | 空分组占位 | 抽屉固定渲染三组标题（0 也显示） | 视觉噪声 | S3 |
| J-13 | 移动端键盘遮挡 | 全局 NONE + 底部表单 | 输入不可见 | S1（待真机确认） |
| J-14 | 全窗口后 `writeDraft` 仍 `nav.pop()` | 路由时代的残留 | 生成后页面栈错乱 | S1（回归） |
| J-15 | 重复贴放无唯一约束 | `canvas_placements` 无 unique index | 残留/自动回去的根因 | S1 |
| J-16 | 共享编辑语义未定义 | 卡片跨板复用，无提示/覆盖模型 | 改一处影响全部 | S2 |

## 6. 成功指标（建议埋点）

| 指标 | 定义 | 目标（首版） |
|---|---|---|
| 首次建章耗时 | 进入空板 → 写作卡有第 1 章 | < 60 秒 |
| 引文捕获耗时 | 选中文字 → 素材出现在卡里 | < 10 秒 |
| 引文带源率 | 有 docId+offset 的引文 / 全部引文 | > 95% |
| 编辑替代删除率 | 修改素材 / (修改+删除+重加) | > 80% |
| 初稿回访率 | 生成后 7 天内从卡片打开初稿 | > 30% |
| 破坏性操作撤销率 | 撤销次数 / 删除次数 | 观测值（不设目标） |
| 结构操作失败率 | attach/detach 失败 toast / 总操作 | < 2% |

## 7. 调研计划（待执行）

- 5–8 名用户：3 名研究生、2 名课程报告作者、2 名内容创作者；每人 45 分钟情境访谈 + 任务脚本。
- 任务脚本：建写作卡→加 3 章→从一段文字捕获引文→生成初稿→改一章→再生成。
- 记录：任务完成率、步骤数、卡点、原话；对 J-05/J-06/J-07 做 A/B 偏好。
- 埋点：上述指标 + 关键路径漏斗。
- 产出：本文更新为 r2，并把确认的假设写进工程指南的“决策记录”。

## 8. 待验证假设

1. 用户是否期望“写作卡里直接写章标题”，还是接受“章=子卡”的概念。
2. 引文捕获入口：工具条按钮 / 选中浮层 / 快捷键，哪个不打断阅读。
3. 重生成初稿：覆盖 vs 新建，是否存在“保留版本历史”的需求。
4. 连线是否真的需要；如果不需要，是否删除数据层以免误导。
5. 共享卡片编辑：用户是否理解“改一张卡影响所有白板”。
