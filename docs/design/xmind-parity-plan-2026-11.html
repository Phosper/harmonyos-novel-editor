一、调研拿到了什么（事实清单）

三处来源口径不完全一致（官网按版本宣传，结构数量在 7 / 9 / 16 之间浮动），所以下面按能力族记录，不按"第几种结构"记录。

来源关键事实
首页 xmind.cn 主打三件事：AI 智能体（对话生成/改写导图）、项目管理（任务、甘特图、时间轴、矩阵视图、优先级/进度/起止日期）、协作（实时共同编辑、评论、全端同步）。
编辑能力：专业思维导图（智能布局）、演说模式、ZEN 模式（沉浸 + 今日专注计时）、大纲模式。
视觉元素分四组：标记（颜色/优先级/进度/旗帜/星星/人物/符号）、贴纸、插画、本地图片。
入门指南 xmind.cn/blog/xmind-introduction 四种主题：中心主题、分支主题、子主题、自由主题。
五种主题元素：联系、概要、外框、标注、标签（原文："联系、概要、外框、标注、标签等主题元素可以用来对主题进行分类、补充和强调"）。
绘制原则五条：关键词、清晰逻辑结构、色彩区分、图像、线条渐细（用线的粗细表达重要性）。
样式修改集中在右侧格式面板。
结构页 xmind.cn/structure 明确列出 7 种：思维导图、逻辑图、组织架构、树形表格、矩阵图、网格、鱼骨图（另有"专区"作为分组容器）。
工具抽屉：任务、概要、联系、笔记 —— 说明"笔记/备注"在官方产品里是一等公民，不是附属品。
第三方评测 techreview.com.cn/xmind-guide 宣称 16 种结构（把方向变体算进去）：思维导图、逻辑图、括号图、组织结构图、树形图、时间轴、鱼骨图、矩阵图、自由主题。
另有手绘（Sketch）风格、Pitch 演示（按分支 zoom-in 自动生成动画）、AI 扩写。
注：非官方来源，只用来交叉核对功能名，不作为"我们也必须做"的依据。
调研结论只有一句话：XMind 的护城河是"结构与表达"（9–16 种结构、五种主题元素、演说/ZEN），不是"数据"。 这对我们反而是好消息——结构和表达全是纯函数与视图，不碰正文。

二、XMind 的能力分五层

层包含特点
1. 结构思维导图、逻辑图、组织架构、树形表格、括号图、时间轴、鱼骨图、矩阵图、网格、专区纯几何：输入一棵树，输出节点矩形 + 连线图元
2. 主题元素联系、概要、外框、标注、标签、备注附加信息：要求"存得住、看得见"
3. 视觉形状/填充/边框/字体、标记（7 组）、贴纸、插画、图片、手绘风格、线条渐细每节点或全局的样式
4. 模式大纲模式、演说模式、ZEN 模式同一份数据的三种看法
5. 平台协作、云同步、AI 智能体、任务甘特、导入导出需要服务端或额外数据模型

我们第 1–3 层已经做了一半（两种结构、概要/联系/标签、节点样式/标记），第 4 层几乎空白，第 5 层按定位基本不做。

三、与我们模型的冲突点

XMind 的前提是"树是唯一真源"，我们的前提是"正文是唯一真源，导图是投影"。这决定了三件事只能取一半：

XMind 的做法直接照搬的后果我们的处理
自由主题（图里有文章没有的节点） 要回答"它存在哪、怎么进文章、删了正文怎么办"，等于养第二棵树 不做 自由摆放的需求交给思路板（已有）
多结构混搭（每条分支不同结构） 布局要按子树分派，连线/端点的方向判定翻倍 先整图统一 一篇文章同一时间只用一种结构；混搭留到 X3 之后评估
任务 / 甘特 / 负责人 / 进度 给段落挂业务字段，与"写作"关系弱，备份协议还要再扩 建议不做 只借"时间轴结构"的几何，不借任务字段
贴纸 / 插画 / 图片 / 手绘风格 要资源包与绘制管线；写作场景收益低 不做 标记（字符）已覆盖"强调"的需求
协作 / 云 / AI 智能体 需要服务端与账号体系 不做
演说 / ZEN / 大纲 纯视图，不冲突 采纳 大纲我们在正文侧栏已有，缺演说与 ZEN

X1 · 结构族（建议先做）

收益最高、风险最低：全是纯函数，可 Node 回归；不动任何数据
  • 组织架构：根在上，子节点在下，兄弟水平居中；连线从父下沿中点 → 子上沿中点，竖直贝塞尔。
  • 树形表格：同一深度一列，行高统一；连线改直角折线（父下沿 → 层间横线 → 子上沿）。
  • 线条渐细：连线粗细按深度递减，global 开关。
  • 页面把「结构：左右 / 向右」扩成四选一（左右、向右、向下、表格）。

验收：同一篇文章切四种结构，节点与连线都不错位；缩放/折叠在四种结构下都成立；回归新增"竖向下行端点、兄弟居中、列对齐"。

X2 · 主题元素补全

补上"五种主题元素"里缺的两个 + 备注
  • 外框：同层多选 → 圆角矩形把这几节框起来 + 标题（复用概要的区间判定）。
  • 备注：节点右上角一个小角标，点开右侧抽屉读/写长文本；存 doc_map_node.note。
  • 标注（待定）：气泡挂在节点旁，与节点会重叠，需要避让算法。

验收：不给正文加一个字，图上能表达"这三节是一组"（外框）与"这一条要补充说明"（备注）；关掉再开还在；备份往返不丢。

X3 · 专注与视图

长文稿（10 万字+）真正需要的
  • ZEN / 仅显示该分支：只保留当前节点的"祖先链 + 子树"，其余淡化到 0.2。
  • 视口裁剪：按滚动位置只渲染视口 ±1 屏的节点与连线（300 节点以上才开启）。
  • 缩略图：右下角小窗（componentSnapshot），点一下定位。
  • 撤销/重做按钮：直接接 EditorStore.undo/redo 与 canUndo/canRedo。
  • 缩放快捷键：Ctrl+滚轮、Ctrl+0、Ctrl+±。

验收：20 万字书稿的导图缩放/导航不卡；ZEN 下只剩当前分支；撤销按钮能一步退回刚才那次结构改动。

X4 · 演说与导出

"把结构讲一遍"
  • 进入演说：全屏 + 隐藏所有面板，从根开始逐级 zoom 到当前分支，其余淡化。
  • ← → 空格控制上一节/下一节/下一步，Esc 退出。
  • 导出 PDF（按分支分页）与 PNG（2x）。

验收：一篇文章不用做 PPT 就能讲完；导出的 PDF 每页一个分支、层次清楚。

X5 · 互通

"结构能带出去、也能带回来"
  • 先 md 导出（按层级写 - 缩进，最多三级）。
  • 再 opml（大纲的标准格式，双向都简单）。
  • 最后 xmind（zip + json；zlib 已在 EPUB 导入里用过）。

验收：导出的 md 能直接贴进别的编辑器；xmind 文件能被 XMind 打开。

五、技术要点与风险

5.1 已经踩过的坑（别再踩第二次）

  • px / vp 混用：Path.commands 是 px，Polyline.points 是 vp。新结构一律走 Polyline。
  • ForEach 键：键里必须带"布局版本号"，否则重排后复用旧子组件，节点停在旧位置。
  • HSP 编译期：ForEach 的构建函数里不能写 const（只有 HAP 增量构建不报错，打包 APP 才暴露）。
  • 画布时差：Canvas 尺寸/就绪晚于节点布局，一切"画上去"的东西都容易差一帧；能用组件就不用画布。

5.2 新结构带来的两处硬骨头

点问题对策
连线方向 现在的 OutlineConnector 只会算"父右缘 → 子左缘"或镜像；组织架构要"父下沿 → 子上沿" 给 PlacedNode 加 axis（'x' 横向 / 'y' 纵向），连线与采样按 axis 分派；outlineWires 的包围盒逻辑不变
树形表格 列宽固定 220vp 时，深层表头会挤；行高统一要放弃"节点 38vp + 行距 52"的现状 表格结构单独一套行高（44vp）+ 行距（0），列宽按深度递减；先把"能看"做出来，再谈美观

5.3 其他风险

  • ZEN 与折叠/多选叠加：焦点分支 + 折叠集合 + 多选三者都要参与可见性判定，容易互相抵消 → 先定优先级：折叠 > 焦点 > 多选高亮。
  • 视口裁剪与 ForEach 键：滚动会让可见集合频繁变化，键若随可见性变，会频繁重建 → 键只跟身份 + 布局版本走。
  • 演说与键盘：页面只有一个 onKeyEvent 入口，浮层（改名/概要/标签）已经占用优先级，演说要插在"浮层之下、结构编辑之上"。
  • 导出 PNG 的内存：2x 大图 + 长文稿可能爆内存，导出前先算尺寸，超过阈值自动降到 1x 或分块。
  • 设备不可达：拖拽类交互（X1 的树形表格重排、演说的手势翻页）在没有真机时只能写"未测"，不谎报。

六、需要你拍板的 4 件事

① X1 先做哪个结构？

建议：组织架构（向下） —— 写作里"章节层级/人物关系/论证结构"用向下看最自然，也最容易和现有左右布局共用一套连线代码。树形表格排第二（表格好看但难精修）。

备选：括号图（最省事，但只能读不能改，价值低）。

② 备注与标注，做哪个？

建议：做备注，不做标注。 备注是"这一节要补充的说明"，写作时真会用；标注是在图上贴气泡，和节点必然重叠，避让成本高、收益低。

③ ZEN 与演说，先后？

建议：ZEN 先。 ZEN 是"看自己的稿子不被打扰"，日常高频；演说是"讲给别人听"，低频但出彩。两者共用同一套"焦点分支"能力，ZEN 先做等于给演说铺路。

④ 任务/甘特、协作、AI，明确排除吗？

建议：明确排除（写进文档，以后不再讨论）。理由：这三样要么需要服务端，要么需要给段落挂与写作无关的业务字段。若你希望"写作进度"能可视化，我建议只做一个极简版：给章节挂"完成/进行中/待写"三态，落侧车，不碰正文。

七、如果只做一件事

先做 X1 的组织架构 + 线条渐细。 理由：零数据变更、零侧车、全是纯函数，回归可覆盖；但它带来的"像不像一个专业导图工具"的观感提升最大——现在只有左右和向右两种，切一下向下，整张图的性格就变了。
