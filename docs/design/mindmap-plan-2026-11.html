01一句话结论

竞品没有一个做“长文段落 ↔ 导图节点”的双向绑定。它们的模型都是「一棵主题树是唯一真源，节点挂备注/描述」； Obsidian 系是“图引用笔记”。
我们要做的这件事（导图与正文严格对应，改图就是改文章结构）在竞品里没有现成答案， 但技术上完全可以落地——因为我们已经有段落身份（paraId）和整节移动命令，缺的只是“导图上的编辑 → 一次正文命令”的通道。
建议的形态
  • 正文标题是唯一真源，导图是它的投影；
  • 导图里改名/增删/移动 = 对正文发一次命令（可撤销、可保存）；
  • 折叠、缩放、选中是“看图状态”，不写进正文；
  • 概要与关系线如果要做，另存侧车，不塞进文章。
建议的路线
  • 渲染：节点用 ArkUI 组件（白拿排版/无障碍）+ 连线用 Canvas + 相机与视口裁剪；
  • 分期：先“读得准”（M1），再“改得动”（M2/M3），最后“画得好看/能演示”（M4–M6）；
  • 手机端本期不做，桌面 / MatePad 电脑模式优先。

02现状：我们有什么、缺什么

现有导图在 structure_feature（HSP 包）里，236 行，只读。

维度现在缺口
数据来源正文按行扫标题（行内加粗切碎也能认），生成快照发布给导图页快照带 version 但从不比较，打开期间正文改了图不刷新
节点身份节点 id = 'h'+起始偏移正文一改偏移全变；P5 的 paraId 还没进契约
布局叶子排 y、父取中点、x 按深度 ×300只有“向右树”；无折叠感知、无变高、无左右均衡
渲染节点是 Row 绝对定位；连线是独立 Canvas 贝塞尔所有节点都实例化，无裁剪无虚拟化；连线每帧全图重画
交互只有“点主题 → 回正文”不能改、不能拖、不能折叠、没有快捷键、没有缩放
写回outlineService 只能 publish 快照、请求回跳没有“命令下行 + 变更通知”，导图无法让正文改一个字

已被证明可复用的资产

资产能承担什么
OutlineLayout.ets（契约包，纯函数）建树 + 布局。零 import、可 Node 回归，最适合原地扩展成“折叠感知 + 可变高 + 多布局策略”
DocumentModel 的 sectionRange / moveSection“一节 = 标题 + 到下一个同级/更高级标题之前”。拖节点就是搬这一节，段落 id 不变
大纲面板的命令链createDocument → moveSection → project → applyGeneratedContent → flushDoc，已经在用，可直接照抄
CanvasPane 的相机/手势screen = world×zoom + pan；捏合以手指为锚；命中外扩按 inflate/zoom；“缩不放容器 scale（会糊字）”
TopicCard 的 onAreaChange节点实测高度回传给父级算连线端点——可变高节点的现成做法
OutlineService（核心包）宿主导图之间唯一合法通道；改造点就是在这里加“命令 + 版本通知”
包边界不能破：结构包只允许依赖 feature_contracts + core_runtime。 它拿不到 entry 的 DesignTokens / DocumentModel / GlyphRenderer。 所以“改正文”必须走宿主命令，不能把编辑逻辑塞进 HSP。

03竞品怎么做

事实来源为官方帮助中心；标“推测”的是工程判断。

产品谁是主数据大纲 ↔ 导图关键细节
XMind主题树（.xmind 里的 topic）视图切换；桌面端大纲只支持本地文件Enter 同级、Tab 子级、Ctrl+Enter 父主题；空格进入编辑；多选加概要、拖蓝框改范围；演说模式可按主题隐藏
幕布大纲（纯文本层级）一个按钮来回切（桌面 Ctrl+Alt+Shift+M）节点有“描述区”（Shift+Enter）；折叠显示子节点数量；不支持自由主题；连接线只能调端点角度
MindNode主题树官方承诺“两视图始终同步、瞬间切换”（⌘1/⌘2）唯一把“顺序语义”写清楚的：主节点按创建顺序、一级子节点顺时针、更深层自上而下
亿图 / ProcessOn主题树F11 / 视图菜单开大纲窗格布局类型最多（单/双向、组织架构、树形表、鱼骨、时间轴…）
Obsidian Canvas画布 JSON（绝对坐标）没有大纲；卡片可“窄化到某个标题”图与文是引用关系，位置独立，改标题不影响卡片位置
Markmind 插件markdown 列表就是数据文件头声明 outline / mindmap / table 三种渲染切换=重解析一次，天然没有同步 bug；rich 模式不支持大纲

布局类型与实现难度 推测

布局适合难度
逻辑图（向右树）写作提纲、读书笔记、分析拆解低（我们现在就是）
思维导图（左右发散）头脑风暴、知识框架中（按叶子数左右分配）
组织架构图层级/职级中（自上而下 + 兄弟居中）
树形表格 / 鱼骨 / 时间轴清单、根因分析、里程碑中-高（收益低，后置）

最值得抄的 5 个交互 事实整理

  1. Enter / Tab / Ctrl+Enter 三键成树：覆盖 90% 的结构编辑，不用菜单。
  2. 多选加概要 + 拖边框改范围：把“一组的结论”挂到节点上，贴合写作。
  3. 折叠即显示数量、点数量展开：写作时不丢内容。
  4. 同一份数据多视图、由声明决定渲染：切换只是换渲染器，没有同步 bug。
  5. 演示按主题设可见/隐藏：用结构本身生成放步骤，不必另做幻灯片。
对我们最重要的结论：竞品都是“树是源、文是注”。我们要反过来——文是源、树是投影。 这决定了后面所有设计：不能存第二棵树，编辑必须回写正文。

04开源可借鉴（含许可证红线）

事实仓库、许可证、维护状态来自调研 Agent 的检索。

项目许可证渲染可借鉴什么
simple-mind-mapMITDOM + SVG布局三段式（先算子区高、再父居中）；思维导图/逻辑图/组织架构/时间轴/鱼骨全套；markdown ↔ 树、xmind 读写
mapjs（Mindmup）MITSVG多根 + 关系线与节点树分离 + 锥形区域重叠探测，纯函数链最好抽
markmapMITSVG + Canvas2D 双后端架构最值得抄：布局输出“图元数组”，Canvas 只是一个消费者；左右均衡的 splitBranches；折叠集合独立于树
jsMindBSD-3canvas 或 svg 可切布局与渲染彻底分层；viewport（缩放/边距/设备像素比）语义清楚
mind-elixirMITDOM + SVG数据结构（topic/children/expanded/direction/summaries/arrows）可直接对齐我们的节点模型
@ohos/mind-elixir（Gitee 孵化）Apache-2.0ArkTS + Canvas 画线唯一的鸿蒙现成实现，可 ohpm 安装做对照或兜底（API≥15）
KityMinder coreBSD-3SVG布局思想（左右分配、鱼骨、天盘）与模块划分（expand/drag/keynav）
Freeplane / drichard-mindmapsGPL-2.0 / AGPL-3.0Java2D / Canvas只能读思路，不能抄代码
kityminder-editorGPL-2.0SVG大纲+导图并排面板可看交互，代码不可用（与 BSD 的 core 是不同仓库，极易混淆）
许可证规则（我建议写进仓库约定）：MIT / BSD-3 / Apache-2.0 可以借鉴并保留声明； GPL-2.0 与 AGPL-3.0 只看思路、不复制代码；算法思想与数据结构形态不受版权保护，可以自己重写。

拟采用的“组合拳”

  • 架构照 markmap：布局输出纯数据（节点矩形 + 连线端点），渲染层只是消费者；
  • 左右均衡照 markmap 的“按叶子数分左右”，父节点居中照 simple-mind-map 的三段式；
  • 数据结构照 mind-elixir：topic / children / expanded / direction + 顶层 summaries / arrows；
  • 导入导出照 simple-mind-map 的 md/xmind 读写（后置阶段）。

05我们的方案与七个决策

#决策内容与理由
D1正文是唯一真源导图节点 = 正文里的 H1–H3 段落（paraId）。不存第二棵树。理由：任何“两棵树”都会漂移，ADR-002 已经定过这条。
D2编辑回写正文改名 = 改段落文本；新建 = 在节末插标题段；删除 = 删整节（二次确认）；移动 = moveSection。全部走已有命令链，免费获得撤销与保存。
D3折叠是视图态折叠集合按 paraId 存在本地视图状态，不进正文、不进版本号；打开时恢复。
D4布局可切换首期做“逻辑图（向右树）+ 左右均衡”两种；组织架构/鱼骨/时间轴后置。布局是纯函数，切换只是换策略。
D5概要/关系线另存它们表达的是“图上的附加信息”，不属于文章结构，落独立侧车表；不进正文，导出 md 时才决定怎么降级。
D6混合渲染节点用 ArkUI 组件（排版/无障碍/hover 全免），连线用 Canvas（vp 坐标，已验证），相机自算，只渲染视口内节点。
D7包边界不变导图 UI 在 structure_feature；命令与落库在宿主（entry + core_runtime）。结构包永远不 import entry。

为什么不做“图里能放正文没有的节点”

那是 XMind/幕布的模型（树是源）。如果允许，就要回答“这些节点存在哪、怎么进文章、删了正文怎么办”。 首期不做：先把“文章结构可视化并可编辑”做扎实；自由主题可以放到后续“思路板”里，而不是文稿导图。

06架构与数据模型

数据流

正文（文本 + 格式边车）
   │ OutlineExtract：按段落取标题，带 paraId / 版本
   ▼
OutlineSnapshot（可序列化，带 version）
   │  core_runtime.OutlineService.publish
   ▼
structure_feature：布局（纯函数）→ 渲染（组件 + Canvas）
   │ 用户操作：改名 / 新建 / 删除 / 移动 / 折叠
   ▼
OutlineCommand（只传基本类型 + paraId + 目标位置）
   │  core_runtime.OutlineService.dispatch → 宿主订阅
   ▼
entry：DocumentModel 命令 → project() → applyGeneratedContent → flushDoc
   │  保存时 reconcile 保住 paraId
   ▼
新的快照（version++）→ 导图刷新（结构变化后重新布局）

节点模型（在现有契约上扩展）

字段用途状态
paraId稳定身份（取代现在的 'h'+offset）新增
parentIndex折叠/布局只认父子，不再靠层级栈反复推新增
collapsed视图态，布局时跳过子树新增（不入正文）
sectionEndIndex“这一节到哪结束”，拖动搬运用新增
width / height节点实测尺寸（onAreaChange 回填），支持变高与换行新增
version与 contentVersion 比对，决定是否重排/重绘已有，需真正使用

侧车表（仅当做概要/关系线时）

doc_map_summary：chapter_id, summary_id, start_para_id, end_para_id, text, created_at

doc_map_relation：chapter_id, relation_id, from_para_id, to_para_id, label, kind, created_at

两表都不参与正文版本；删文稿时级联清理；备份时随文稿一起导出。

07交互与快捷键

操作键行为（与正文的关系）
新建同级Enter在当前节之后插入一个同级标题段
新建子级Tab在当前节末尾插入一个更低一级的标题段
升级 / 降级Shift+Tab / Tab（选中态）改该段落的 kind（H2→H1）
改名F2 / 双击 / 空格浮层输入，回车提交 → 改段落文本
删除Delete删整节（含下属正文），二次确认，可撤销
同级上/下移Alt+↑ / Alt+↓moveSectionUp/Down，整节搬
折叠 / 展开Space 或点击圆点只改视图集合，不动正文
导航方向键在树里移动选中；Enter 回到正文该节
缩放 / 适配Ctrl+滚轮 / Ctrl+0改 zoom 与字号（不缩放容器，避免糊字）
切换到正文Esc / 点击标题左侧箭头关闭导图并把光标放到当前节点
一条硬规则：任何改变结构的操作，都必须能在正文里看到同样的结果，并且能一次撤销。 如果做不到（例如概要不属于正文），就把它明确标成“图的附加信息”，不假装它是文章结构。

08分期计划与验收

按“先读得准 → 再改得动 → 再画得好 → 最后能演示”排。每期都能单独交付、单独验收。

期做什么验收（用户可感知）
M1
读得准		 契约升级（paraId/parent/collapsed/实测尺寸）；快照带版本并在打开期间自动刷新；缩放 + 适配窗口；方向键选中 + Enter 回正文；空态与错误态 开着导图改正文标题，图上立刻跟着变；200 个标题也能顺畅缩放
M2
改得动		 就地改名；Enter/Tab 新建同级/子级；Shift+Tab 升降级；Delete 删节（二次确认）；全部可撤销 只动导图，不动正文，就能把结构改对；Ctrl+Z 一次回到改之前
M3
组织		 折叠/展开（含“N 项”徽标）；拖拽重排（上/中/下三区判定，整节搬）；视口裁剪与连线增量重绘 拖一个节点到别处，正文整节跟着走；折叠后图变小但正文不动
M4
好看		 布局切换（逻辑图 / 左右均衡）；主题与字号档；连线样式；fit-to-screen 同一篇文章可以用两种结构视角看
M5
附加信息		 概要（多选生成、拖边改范围）；关系线（两点连线 + 标签）；独立侧车表 + 备份 图上能写“这三章其实是一组”“A 论证 B”，且不影响正文
M6
演示与互通		 单屏演示（按主题隐藏）；md / opml / xmind 导入导出 从文章结构直接讲一遍；结构能带出去

工作量感受：M1 小、M2 中、M3 中偏大、M4 中、M5 大、M6 中。M1–M3 是“可用”的门槛。

09风险与未验证项

风险现状 / 触发对策
高HSP 内没有自绘先例现有的 Canvas 绘制经验都在 entry 里，结构包里没有 drawing/text 的用法M1 先只画连线（已验证能工作），节点仍用系统 Text；若要自绘，先在包里做一次最小验证
高手势竞争外层滚动 vs 节点拖拽 vs 画布平移；2in1 上还有触控板照 CanvasPane 的做法分层挂兄弟节点；拖动阈值 + 长按再拖；先在桌面验证
中撤销后 paraId 变化同事文档已列：撤销回灌时恢复段可能拿到新 id导图按 paraId 找节点，找不到就按“偏移 + 标题文本”回退，并提示一次
中缩放导致重排改字号必须重排，不能只缩放容器按“档位”缩放（100/85/70/55%），每档排一次；连续手势结束再落档
中大图绘制Canvas 尺寸超过 8000px 会转 CPU 渲染（官方提示）连线只画视口内线段；地图尺寸超限时按块裁剪
待验证节点变高标题换行后高度不等，连线端点要跟着动用 onAreaChange 回填实测高度（TopicCard 已有先例）

10需要你拍板的 5 个问题

  1. 导图能不能有“正文里没有的节点”？我建议不能（D1）。要能的话，需要把图存成第二份数据，复杂度和漂移风险都上一个台阶。
  2. 删除节点 = 删除整节正文？我建议是，但必须二次确认 + 可撤销。若你希望“只从图里移除、正文保留”，那就变成视图过滤，得另做一套“隐藏”语义。
  3. 首期做几种布局？我建议两种（逻辑图 + 左右均衡）。只做一种也行，但“左右均衡”是思维导图的默认形态，缺了会显得不像导图。
  4. 概要 / 关系线进不进首期？我建议放到 M5。它们要新增侧车表、备份协议和导出降级规则，和“改结构”不是一个复杂度。
  5. 手机端本期做不做？按你之前定的“桌面 / MatePad 电脑模式优先”，我建议本期只做桌面，手机端等导图稳定后再补触摸版（长按菜单、单指平移、双指缩放）。
你回一句“按建议来”我就按 M1 → M2 → M3 推进；想调整哪条，说编号即可。 M1 的第一步是把 OutlineLayout 契约升级（paraId/collapsed/实测尺寸）， 这一步不碰 UI，风险最低，也决定后面所有布局代码的形态。
