# 06 · 可视化画布（卡片 + 连线）方案适配分析

> 目的：把「和豆包对话记录」里的产品构想与技术草稿，逐条对照本仓库的**真实代码**做可行性判定，产出一份可直接排期、可直接验收的方案。**本文不含实现代码**，只含决策、边界、验收口径。
>
> 勘查基线：`Weaver` 工作区，`targetSdkVersion` / `compatibleSdkVersion` 均为 `26.0.0`，单 `entry` 模块，`deviceTypes = phone / tablet / 2in1`。本机（OpenEuler）无 java / hvigorw / hdc / ohpm，**所有构建与装机结论均为「未验证」**。

---

## 0. 结论摘要

1. **产品内核（通用画布 + 模板 + 场景引导）成立，可以照做**；但豆包的「技术草稿」在本工程里基本不能落地，14 处会直接编译失败、运行错乱或性能塌陷（见 §2.3），必须重写而不是移植。
2. **本工程不是「从零加功能」，而是「复活一个半成品」**：`GraphNode` / `GraphEdge` / `RelationStore` / 关系 DAO / 图谱配色令牌 / `EditorViewMode.GRAPH` / `app.showGraph()` 全在，只缺 UI。历史提交 `12702e2` 里有一份 343 行的 `GraphCanvas.ets`，是纯 Canvas 的人物关系图，可作为「渲染与手势」的直接前车之鉴（含一处至今仍会复发的缩放 bug，见 §1.4）。
3. **渲染架构建议「纯 Canvas 自绘 + 原生浮层编辑」**，而不是豆包的「Canvas 画线 + 200 个原生卡片叠在缩放的 Stack 上」。理由是本工程的坐标系、缩放清晰度、手势唯一命中、性能上限、可访问性五条约束下，纯自绘代价最低（§3 D1）。
4. **信息架构必须先解决一个冲突**：2026-10 的「极简」重构已经把「素材 / 关系图」从手机与中等宽度界面**移除**（`shell/MobileShell.ets:44`、`:153`）。新画布若再挂一个常驻一级 Tab，会重蹈被砍的覆辙。建议做成「文稿的一种打开方式」+「项目级思路板」，不给手机加常驻 Tab（§3 D6）。
5. **数据上不要造第二份真相**：人物/世界观/章节已是持久化实体，画布只应新增「画布、卡片位置、通用连线」三类数据；人物关系仍以 `relationships` 表为唯一真相（§3 D4）。
6. **开工前必须补一个既有缺陷**：备份恢复给章节换新 id 时**没有记录 `chapterIdMap`**（`store/AppStores.ets:490-508` 只有 `charIdMap`），卡片一旦引用章节，恢复后必然悬空。该修复与画布功能同批做（§3 D8）。
7. **建议先做 2–3 天的技术验证（P0）**再排功能工期：200/500 节点的重绘帧率、缩放后文字清晰度、2in1 滚轮与右键、手势分派四项，本机无法验证，必须在 DevEco 机器 + 真机/模拟器上量出来才敢承诺性能指标（§4、§5）。
8. **编辑器侧有一个必须先补的地基**：`CanvasTextEditorController` 没有读选区的公开 API，`setCaretPosition` 也不会把光标滚进视口（§1.5）。所以「选区 → 卡片 / 卡片 → 原文」不是两个 UI 按钮的事，前面还有一轮「只读地基」（P3a）。
9. **导航只能加路由，不能加 Tab**：全仓只有 `workspace` / `settings` 两条路由，`pageMap` 有两份（`AppShell` 与 `MobileShell`），`ui.view` / `MobileTabBar` 都是死路径（§1.2、D6）。
10. **豆包给的工期（MVP 1–2 周）不适用于本仓库**：本工程有 7 个 Node 回归脚本（256 项）+ 19 项 ArkTS 静态守卫 + 多端自测清单，任何改动都要过这条流水线。按本仓库节奏重估见 §4。

- 三栏结构：`SideBarContainer`（项目/文库）→ `Navigation` navBar（文稿列表）→ `NavDestination`（工作区），见 `shell/Navigator.ets:8-14`、`shell/AppShell.ets:401-436`。

- **「素材 / 关系图」已被产品决策砍掉**：
  - `shell/MobileShell.ets:44`：「手机端按新设计：只保留 项目 / 文稿 —— 砍掉素材与关系图」
  - `shell/MobileShell.ets:153`：「素材/关系图已按新设计移除」

- 更关键的是：**本工程没有可扩展的「区段（section）切换器」**。`ui.view` 是**只写不读**的死状态（`store/UiStore.ets:158`，全仓无读取点），`MobileTabBar` / `MobileSectionTabs` 无任何调用方。导航只有两条路由：`workspace` / `settings`（`shell/Navigator.ets:16-20`），且 **`pageMap` 在 `AppShell`（`:543-550`）与 `MobileShell`（`:267-273`）各有一份，必须同步修改**，漏一处就是手机端白屏。
- 另一个既成事实：主界面**已不再挂载 `DesktopTitleBar`**（守卫 `tools/arkts-guard.cjs:307-308` 明确禁止 `AppShell` 内出现它），窗口拖动热区下沉到三个 pane 头部。因此任何新页面都要自己留「拖动热区 + 原生三键避让」。
- 结论：新画布功能的入口设计必须回答「为什么这次不会像上次那样被砍」。答案只能是把画布做成**正文的另一种打开方式**（用完即走、不占常驻导航），而不是新增一级板块；实现上走**新增路由 + NavDestination**，不要试图复活 `ui.view` 那套死机制。

### 1.4 前车之鉴：历史 `GraphCanvas` 做对了什么、错在哪

**做对的（值得继承）**
- 单一坐标系：`ctx.save() → translate(pan) → scale(zoom) → 绘制全部图元`，卡片与连线共享一个变换，永不漂移。
- 命中检测走逆变换：`canvasToNodeCoord` 把屏幕坐标换回世界坐标再判距，天然支持缩放。
- 平移用「基准 + 累计偏移」：`lastPanX + event.offsetX`，与官方示例一致，**没有**每帧累加的漂移 bug。
- 手势用 `GestureGroup(GestureMode.Parallel, [Pinch, GestureGroup(Exclusive, [LongPress, DoubleTap, Tap, Pan])])` 一处声明，避免父子手势竞争。
- 2in1 右键用 `onMouse` + `MouseButton.Right`，悬停高亮用 `MouseAction.Move`。

**错在哪（新实现必须避免）**
1. **缩放每帧累乘**：`canvasScale * event.scale`（Pinch 回调）。官方示例是「`onActionStart` 记基准、`base * event.scale`、`onActionEnd` 回存基准」——否则双指一开就指数放大。
2. **布局是自动半径圆环**：`performLayout()` 每次数据变化重算位置，用户拖不动、位置不保存——本质是「只读图谱」，不是「工作台」。
3. **节点是圆 + 两字缩写**：没有标题、类型 chip、摘要，无法承载「知识卡片」的信息量。
4. **滚轮未处理**：`PanGesture` 文档明确鼠标滚轮也会触发（`axisVertical/axisHorizontal ≠ 0`），历史实现把它当平移，2in1 上体验不可控。

### 1.5 编辑器侧的能力缺口（直接决定 P3 的工作量）

「选区 → 卡片」「卡片 → 原文」看起来是两条 UI 逻辑，实际卡在一个非常具体的位置：**`CanvasTextEditorController` 没有读选区的公开 API**。

| 缺口 | 事实 | 影响 |
|---|---|---|
| 取不到选区 | controller 公开方法只有 `setText/getText/setCaretPosition/focus/blur/insertTextAtCaret/deleteLeftAtCaret/toggleInlineStyle/toggleParagraphStyle/setRuns/getRuns/inlineStyleMask`（`editor/flowtext/CanvasTextEditor.ets:98-259`），**没有** `getSelection/getSelectedText` | 无法可靠实现「选中文本 → 生成卡片」；`EditorPane` 只在 `onSelectionChange` 里递增 `selectionTick`，**store 不保存选区**（`shell/EditorPane.ets:134-139`），从 UI 事件里读会拿到过期选区 |
| 选区文本实现散落 | `findSelection/shareSelection/copySelection` 三处各自 `substring`（`CanvasTextEditor.ets:561/570/639`），全是私有 | 需要统一出口，并做字素边界校验 |
| 段落范围三份重复 | `TextDocument.paragraphBounds`（私有，不处理 `\r`）、`CanvasTextEditor.paragraphStartAt/EndAt`（私有）、`selectParagraphAt` 内联（`TextDocument.ets:270-277`、`CanvasTextEditor.ets:2862-2876`、`:584-587`） | 抽 `ParagraphUtil` 并统一 CRLF，否则卡片锚点在 CRLF 文稿上偏移 |
| 定位不滚动 | `setCaretPosition → moveCaretTo → moveCaretAnimated` 只做 `ensureCaretLayout`，**没有 `ensureCaretVisible`**（`CanvasTextEditor.ets:1016-1034`） | 「跳回原文」时光标在视口外，用户看到「跳了但什么也没发生」 |
| 同稿不重载 | `TextEditorHost.reload()` 有 `docId === loadedDocId` 早退（`editor/TextEditorHost.ets:128`） | 已在当前文稿时再点卡片不会重建文档，必须走 controller |
| 命令层六处硬编码 | 枚举 / `EditorCommandRouter` 接口 / switch / `CanvasEditCommandHost` 适配器 / 编辑器落点 / 浮层菜单（`editor/interaction/EditCommand.ets:12-44`、`EditorCommandRouter.ets:54-149`、`CanvasTextEditor.ets:3452-3539`） | 新增「发送到画布」要动 6 处；浮层菜单还固定 11 项、按 5/6 两行切分（`CanvasTextEditor.ets:467,477`），加项必须同步 |
| 画布不能获焦 | `Canvas` 无法获焦（`CanvasTextEditor.ets:772-774` 注释） | 画布不得抢编辑器焦点，也不要用 IME 链路 |

**结论**：P3 之前必须先做一轮**只读地基**（controller 读选区 + `ParagraphUtil` + `revealOffset`），这三件事不改任何既有行为，可单独验收、可单独回退。

## 2. 豆包方案评审

### 2.1 产品层：可采纳（3 条）

| 观点 | 判定 | 在本工程的落法 |
|---|---|---|
| 「通用内核 + 场景模板 + 用法引导」而非绑定单一垂直场景 | **采纳** | 卡片/连线/画布零业务字段；场景差异全落在模板 JSON（卡片类型、配色、初始结构、说明文案）。与 1.2 的「极简」并不冲突：模板是**创建时**的引导，不是常驻 UI。 |
| 借 Obsidian 的「知识互联」内核，弃其「语法驱动」外壳 | **采纳** | 不做 `[[双链]]` 解析；关联靠拖拽创建；「被引用」面板由数据反查。项目已有 Markdown 导出链路（`utils/ExportService.ets`），但**不要**为双链引入语法解析。 |
| 画布分级（单文档 / 项目 / 全局）避免信息过载 | **采纳，且改写** | 本工程天然只有两级有意义：文稿级（当前章节）与项目级（整本书的人物+设定+章节）。「全局跨项目总览」不做——跨 `bookId` 的数据隔离是全仓的硬边界（`setBookScope`、`loadRev` 校验遍布各 store），打破它成本远高于收益。 |

### 2.2 技术选型层：不可移植（3 条）

| 豆包建议 | 为什么在本工程不成立 |
|---|---|
| AntV X6 / React Flow / D3 | ArkTS 无 DOM、无 SVG 运行时、无 npm 前端生态；`oh-package.json5` 只挂了 hypium/hamock。任何「引一个图引擎」的方案在此直接归零。 |

### 2.3 代码层：14 处必须重写（这是本文最该被采纳的部分）

> 判定依据：HarmonyOS 官方文档（PanGesture / PinchGesture / Canvas / 手势绑定）+ 本仓库既有约定。逐条给「后果」与「正确做法」。

| # | 豆包写法 | 后果 | 本工程正确做法 |
|---|---|---|---|
| 1 | `@Component` + `@State` + 直接改 `node.x` | V1 只观察第一层；数组元素内部赋值**不触发刷新**，拖拽后画面不动 | 全仓 V2：卡片模型 `@ObservedV2` + `@Trace x/y`；或（推荐）坐标不进状态，拖拽期只重绘画布 |
| 2 | `@Link node: GraphNode`（interface 类型） | `@Link` 要求来源是状态变量且链的是可观察对象；对 interface 字段无效，且子改父不回流 | 子组件只发 `@Event onDrag(id, dx, dy)`；父级统一改世界坐标 |
| 3 | 连续两个 `.gesture()`（Pan 一个、Pinch 一个） | 同一组件的手势槽位被覆盖/竞争，实际只有一个生效（具体以 API 26 实测为准） | `GestureGroup(GestureMode.Parallel, [...])` 一处声明，与历史实现一致 |
| 4 | `this.scale = this.scale * event.scale`（每帧） | `event.scale` 是**自手势起点**的累计比值，逐帧相乘 = 指数爆炸 | `onActionStart` 存 `baseScale`，`onActionUpdate` 用 `clamp(baseScale * event.scale)`，`onActionEnd` 回存 |
| 5 | `this.offsetX += event.offsetX`（每帧） | `offsetX` 同样是自起点的累计位移，累加=漂移加速 | `baseX + event.offsetX`（历史实现如此，官方示例亦如此） |
| 6 | 缩放不处理锚点 | 双指一捏，内容朝屏幕左上角飞走 | 以 `pinchCenterX/Y` 为锚点保持世界点不动：`pan' = anchor - (anchor - pan) * (zoom'/zoom)` |
| 7 | 卡片层 `.scale()`/`.translate()`，Canvas 按 `node.x/node.y` 画线 | 两层坐标系不一致，缩放后连线与卡片错位 | **单一变换**：要么全部在 Canvas 内用 `ctx` 变换，要么卡片位置改成屏幕坐标（则每帧重排，代价高）。见 §3 D1 |
| 8 | 每帧 `clearRect` 后重画 20px 点阵网格 | 1280×800 视口 ≈ 2560 个 `arc`/帧，必掉帧 | 网格只在缩放/平移变化时重绘，或预渲染成 `ImageBitmap`（`OffscreenCanvas.transferToImageBitmap`）后 `drawImage` |
| 9 | 未创建 `CanvasRenderingContext2D`（直接用 `graphCanvasCtx`） | 编译不过；`ctx.width/height` 也只在 `onReady` 之后才有效 | `new CanvasRenderingContext2D(new RenderingContextSettings(true))`，尺寸在 `onReady` 取 |
| 10 | `ForEach(this.nodes, ...)` 无 key | 复用失效、增删错位 | 第三参数给稳定 id；V2 场景若要复用用 `@ReusableV2`（`@Reusable` 不支持 `@ComponentV2`） |
| 11 | 无命中检测、无连线命中 | 只能点卡片，连线不可选不可删；缩放后点击坐标不换算 | 逆变换 + 点到线段距离判定（阈值按 zoom 折算 vp） |
| 12 | 无持久化设计（localStorage） | 与 `relationalStore` / 备份/恢复体系脱节 | 三表 + 备份字段 + 事务恢复（§3 D4、D8） |
| 13 | 「卡片内支持富文本/Markdown 渲染」 | 与自绘编辑器冲突，等于同时维护两套排版 | 只读用 `MarkdownRenderer`；编辑走浮层/全屏，不嵌编辑器 |
| 14 | 「一键自动布局」用「力导向」 | 力导向无稳定收敛，用户摆好的图会被打散；且无法撤销 | 先做**树形/层级**（确定性，可逆），力导向只作为「随机整理」且必须可撤销 |

补充两条**文档级**偏差：
- 豆包给的 `@Component export struct` 写法本身合法（官方示例如此），不构成问题——真正的问题是它与本仓 V2 约定不符。
- 豆包把「滚轮缩放」当默认。`PanGesture` 文档明确**鼠标滚轮会触发 PanGesture**（`axisVertical/axisHorizontal ≠ 0`）。2in1 上必须显式分流：`axis≠0` 走缩放/滚动，`axis=0` 才走平移（见 §3 D3）。

### 2.4 工期与验收现实

豆包给的是「MVP 1–2 周、完善 1 周、融合 1–2 周」。在本仓库不成立，原因不是能力，而是**质量门禁的固定成本**：

- 7 个 Node 脚本 256 项必须全绿（本机可跑，约 10 秒）；
- 19 项 ArkTS 静态守卫（禁止 `any/unknown`、禁止解构、禁止对象展开、禁止 `Object.assign`、禁止 `@Builder` 链式属性、相对导入必须存在等，`tools/arkts-guard.cjs:180-448`）；
- 设备侧 Hypium 用例 + 四形态自测清单（手机/平板/2in1/MatePad 电脑模式，`docs/refactor/multidevice-self-test.md`）；
- 构建与签名只能在 DevEco 机器上做，本机零验证能力。

**重估**：P0 验证 2–3 天 → P1 只读复活 3–5 天 → P2 可编辑 8–12 天 → P3a 编辑器只读地基 2–3 天 → P3b 编辑器联动 4–6 天 → P4 模板 3–5 天。见 §4。

## 3. 本项目适配设计（10 个决策）

### D1 渲染架构：纯 Canvas 自绘 + 原生浮层编辑（推荐）

| 方案 | 卡片内容 | 缩放清晰度 | 手势/命中 | 性能上限 | 可访问性 | 结论 |
|---|---|---|---|---|---|---|
| **A 纯 Canvas 自绘**（连卡片一起画） | 自绘标题/类型 chip/摘要，需自己排版与省略 | 每帧按当前 zoom 绘制，**清晰** | 单一坐标系、单一命中路径 | 高（可裁剪、可静态层缓存） | 需 `accessibilityVirtualNode` 补虚拟节点 | **推荐起点** |
| B Canvas 画线 + 原生卡片（豆包） | 直接复用 `Text`，i18n/字号缩放免费 | 容器 `.scale()` 会把文字**先栅格化再放大**，2× 起糊 | 两层坐标系、父子手势竞争、命中两条路径 | 中低（无虚拟化，每帧重排或模糊） | 天然可读 | 仅适合「卡片 ≤ 30 且 zoom 固定 1」 |
| C LOD 混合（远看 Canvas 色块、近看原生卡片） | 两套渲染都要写 | 近看清晰 | 切换点要处理手势/焦点交接 | 高 | 近景可读 | 演进方向，不是起点 |

**决策**：A 起步；把「卡片需要内嵌按钮/图片/输入框」这类需求挡在门外，需要时用「选中 → 原生浮层」满足。若 P0 实测发现 Canvas 文本排版质量或无障碍验收不过关，再切 C，**不要**直接切 B（B 的两种对齐方式都有硬代价：要么每帧重排，要么文字糊）。

**复用点**：`render/LayoutCache.ets` 的「版本号 + 失效起点 + 惰性追加」、`render/GlyphRenderer.ets:234` 的视口裁剪、`interaction/HitTester.ets:111` 的「几何单一来源」。**不能照抄**它的「每帧全量重绘」（`:156,196`）——文本视口最多几十行，画布元素会随场景增长。

### D2 坐标系与变换：世界坐标唯一

- 持久化只存**世界坐标（vp）**：`card.x / card.y / card.w / card.h / z`；画布存 `pan_x / pan_y / zoom`。
- 屏幕坐标 = `world * zoom + pan`；绘制时 `ctx.setTransform(zoom, 0, 0, zoom, panX, panY)`，命中时用逆变换。
- **禁止**在卡片/连线两层各用一套 `.position()` 与 `ctx` 变换混算（豆包错 #7）。
- zoom 归一化到 `[0.3, 2.5]`；`0.3` 以下切 LOD（只画色块 + 首字），`2.5` 以上限制（避免线条与文字失真）。
- **Canvas 面积上限是硬约束**：官方规定 `Canvas` 最大 `10000px × 10000px`（超限无法创建）。所以不能做「一张世界大小的超大 Canvas 再缩放到屏幕」，只能做**视口大小的 Canvas + ctx 变换**；这条约束反过来也决定了「纯 Canvas + 单一变换」是唯一自洽的做法。

### D3 手势与输入：一处声明、按起点分派

- **一个** `GestureGroup(Parallel, [Pinch(2), GestureGroup(Exclusive, [LongPress, DoubleTap, Tap, Pan(1)])])`。
- `Pan.onActionStart` 用命中结果决定模式：命中卡片 → 拖拽卡片；命中连线 → 无操作（或选中）；空白 → 平移画布；长按空白 + 拖动 → 框选（P3）。
- 所有 update 用「基准 + 累计」，`onActionEnd/Cancel` 回存基准；`Pinch` 用锚点补偿（错 #4/#5/#6）。
- **2in1 分流**（本仓 `pointerPrimary`、`isPc` 已有判据，`store/UiStore.ets:53,215`）：
  - `onAxisEvent` 或 `PanGesture` 的 `axisVertical/axisHorizontal ≠ 0` → 滚轮：默认**平移**，`Ctrl/Command + 滚轮` → 以指针为锚缩放；触控板双指滑动 → 平移。
  - 悬停高亮（`onMouse` Move）、右键上下文菜单、`Delete` 删除、`Ctrl+Z/Y`、`Ctrl+A`、`Ctrl+F`、`Esc` 取消连线。
- **手机**：单指拖卡片 / 双指缩放 / 空白拖动平移；长按卡片 = 上下文菜单（删除、颜色、连到…）。缩放不用双指也能用工具条 +/-（可访问性兜底）。
- 与编辑器共存时：画布是整屏视图，不与 FlowText 的手势层重叠，避免抢事件。

### D4 数据模型：三张新表 + 两个既有表，单一真相

```
canvases        (id, book_id, scope, doc_id?, title, pan_x, pan_y, zoom, template_id, sort_order, created_at, updated_at)
canvas_cards    (id, canvas_id, book_id, kind, ref_id?, title, content?, format?, x, y, w, h, z, color?, collapsed, created_at, updated_at)
canvas_links    (id, canvas_id, book_id, from_card_id, to_card_id, kind, label, style_bold?, created_at, updated_at)
```

- `kind ∈ { text, character, world, inspiration, chapter }`，`ref_id` 指向既有实体；**`character/world/chapter` 卡片的标题与正文从实体读取，不存快照**（避免改名后两处不一致）。实体被删 → 卡片保留但灰化，提供「清理失效卡片」。
- **连线分两类真相**：
  - 人物 ↔ 人物：仍以 `relationships` 表为准（已有 CRUD、级联删、备份），画布只做投影与编辑入口；
  - 其余（卡片↔卡片、卡片↔人物）：存 `canvas_links`。
  - 渲染时两路合并；编辑时按来源路由到对应仓储。**不要**把人物关系复制进 `canvas_links`（否则删除人物时出现幽灵边）。
- 坐标用 `REAL`（vp），不取整；`z` 用整数，插入时 `max(z)+1`。
- 现有关系图模型 `GraphNode.x/y = 0` 的问题（`store/RelationStore.ets:55-64`）由「位置查 `canvas_cards`」解决：视图模型不再持有坐标，改为 `(refId → x,y)` 查表。
- **索引**：现库**一张索引都没有**，`book_id` 全表扫。新表建 `(book_id, canvas_id)` 与 `(canvas_id, z)` 索引；是否给旧表补索引单列为一次低风险优化（不在本功能范围，但建议同批评估）。

### D5 编辑器联动：段落序号 + 指纹 + 段内相对偏移（三重锚）

**事实起点**：文档**没有段落 ID**（全仓无 `paragraphId` 类标识），段落只是 `'\n'` 切出来的偏移区间；选区是纯 UTF-16 code unit 偏移（`interaction/SelectionManager.ets:20-51`）；`caretOffset` 存库时**没有任何校验**，正文被外部改写后会静默漂移（`store/EditorStore.ets:289-295`、`TextDocument.ets:71-74`）。

- **锚点结构**（存卡片，不存正文）：

  ```
  CardAnchor { docId, paraIndex, paraHead(前 12 字), paraTail(后 12 字),
               paraGraphemeLen, offsetInPara, graphemeLen }
  ```

- **正向（选区 → 卡片）**：从 controller 新增的 `getSelection()` 同步取 `start/end` 与 `selectedText`；两端先做字素边界校验（`GraphemeUtil.isBoundary`），**末端不能直接用 `snapToBoundary`**（它只向前退，会把选区缩一个字，`GraphemeUtil.ets:70-74`），末端要用 `moveRight`。
- **反向（卡片 → 原文）**：先按 `paraIndex` 定位段落，再用 `paraHead/paraTail/长度` 校验；不符则在 `paraIndex ± 20` 段落窗口内做指纹搜索；仍失败则退化为「全文搜索 `paraHead`」并提示「原文已修改，已跳到最接近的位置」。三级降级，每级都可观测。
- **跳转必须能看见**：`setCaretPosition` 不滚动（见 §1.5），所以跳转要新增 `revealOffset(offset)`（`ensureCaretLayout → ensureCaretVisible → drawNow`）或在已绑定时走 `setDocument(text, runs, caret, preserveView=true)` 复用其可见性保证（`CanvasTextEditor.ets:1859`）。
- **同稿跳转**：`TextEditorHost.reload()` 的 `docId` 早退（`TextEditorHost.ets:128`）意味着「当前文稿内跳转」不会重建，必须走 controller，不要指望换 `docId`。
- **不引入段落 ID**：往正文塞 ID 会牵动 `format_runs`、导入导出、一键排版（`TextFormat.format` 会整体替换正文，`store/AppStores.ets:335-347`）、字数统计全链路；三重锚零侵入。
- **CRLF 归一**：段落切分必须统一处理 `\r`（`TextDocument.paragraphBounds` 目前不处理，`LayoutCache.ets:149-151` 处理了），否则 CRLF 文稿的指纹永远对不上。
- **已知失配来源**：一键排版、导入、外部回灌都会整体改写正文 → 卡片锚点失配是常态而非异常，必须有降级路径与「重新锚定」按钮。

### D6 接入方式与入口：新增一条路由，不给手机加常驻 Tab

- **不复用 `EditorViewMode`**：它是只写不读的死状态（`store/UiStore.ets:158`），复活它要同时改 store、`Navigator` 与两份 pageMap，代价大于新增路由。`MobileTabBar` / `MobileSectionTabs` 同理，是死组件，不要照抄。
- 路由：`shell/Navigator.ets:16-20` 加 `Routes.CANVAS`；页面 `shell/CanvasDest.ets` 用 `NavDestination` + 隐藏标题栏，结构参照 `pages/dest/SettingsDest.ets:17-40` 与 `shell/WorkspaceDest.ets:181-225`。
- **两处 pageMap 必须同步**：`shell/AppShell.ets:543-550`（宽屏第三栏）与 `shell/MobileShell.ets:267-273`（手机/平板整屏）。漏一处 = 该形态白屏。
- 入口分布：
  - 宽屏 / 2in1：工作区顶栏动作区加「画布」；项目级画布从 `shell/ProjectSidebar.ets` 的项目项长按/右键进。
  - 手机 / 平板：`shell/DocListPane.ets` 行菜单或 `WorkspaceDest` 的「更多」半模态加「思路板」，返回即回正文。**不加底部 Tab。**
- **画布内「打开原文」不能 `pushPath(WORKSPACE)`**：`ensureWorkspace()` 只判断存在性（`shell/Navigator.ets:36-40`），会形成重复路由。要么先 `nav.pop()` 回工作区再定位，要么新增 `Routes.CANVAS_DOC` 并复制 `WorkspaceDest` 的 `onReady → longTakeSession.init` 注册模式（`shell/WorkspaceDest.ets:198-209`）。
- 命名建议用**「思路板」/「画布」**，不用「知识图谱」「双向链接」这类术语（豆包 §4.3 的措辞建议在本工程同样适用；且本仓 UI 文案已是「极简纸墨」风格）。
- 首次进入用「模板选择 + 3 步引导」承接豆包场景化诉求（学生/创作/职场），模板只是创建画布的预设，不常驻。

### D7 性能预算与降级

- 目标：拖拽/缩放稳定 60fps（每帧 ≤ 8ms 绘制预算），静止时不重绘（`Canvas` 只在需要时 `invalidate`）。
- 三层缓存：① 网格位图（`OffscreenCanvas` → `ImageBitmap`）；② 静态卡片层（除被拖拽/选中的那一张）合成到离屏位图；③ 卡片摘要的排版结果按「文本 + 宽度 + 字号」缓存。
- **注意**：本工程的编辑器是**每帧全量重绘**（`GlyphRenderer.ets:156,196`），没有脏区/离屏分层的先例可抄——这三层缓存对画布是**新增能力**，不是复用，须在 P0 就验证收益。
- **空间索引**：项目内没有任何空间索引实现，画布需自建卡片 AABB 网格（或四叉树）支撑命中检测、框选、视口裁剪、连线相交判断；这是新代码，不要假设编辑器里有。
- 视口裁剪：只绘制与视口相交的卡片与连线（含 1.5 屏预取），节点总数上限建议 500，超过提示「建议拆分画布」。
- LOD：`zoom < 0.5` 只画卡片色块 + 标题首字；`0.5–0.8` 画标题 + 类型色条；`> 0.8` 画完整卡片。
- 降级：`zoom` 变化过程中不重排文字（用缓存的旧排版缩放绘制），停手 120ms 后再重排（与 `Motion.fast` 对齐）。
- **必须实测**：50/100/200/500 节点下的单帧耗时与丢帧率（见 §5 P0）。

### D8 迁移、备份与损坏修复

- **建表安全**：`CREATE TABLE IF NOT EXISTS` 每次 `init()` 重跑（`database/DatabaseHelper.ets:55-130`），旧库自动补表；`DB_VERSION = 2` 只是日志常量（`:8`），**不要**指望它做迁移。若给既有表加列，必须登记 `EXPECTED_COLUMNS`（`:11-15`）走 `ensureColumns`（`:144-167`）。
- **备份**：`BackupTypes.ets:17-27` 加 `canvases / canvasCards / canvasLinks` 三个**可选**字段，`version` 升到 2；导入端是 loose 解析且**完全不读 version**（`AppStores.ets:435`），旧备份天然兼容。
- **恢复时的 ID 重映射**：卡片 `ref_id` 可能指向 `character / world / chapter / inspiration`，四类都要建 map。现状只有 `charIdMap`（`AppStores.ets:509-521`），**缺 `chapterIdMap`（`:490-508`）**——这是既有缺陷，画布一上就会暴露为「卡片指向不存在的章节」。同一批修复，并补 Node 回归。
- **悬空策略**：恢复后校验 `ref_id` 是否存在，不存在则卡片灰化并提供清理入口；**不要**在恢复事务里静默删卡片（会丢用户数据）。
- **事务约束**：`BaseDao` 读永远走 store，事务内读不到未提交数据（`database/BaseDao.ets:18-20`）。恢复画布时不能「插入后回查」，映射必须在内存里维护。

### D9 主题、动效与可访问性

- 配色只取 `DesignTokens`：`graphNodeColor / graphEdgeColor / graphEdgeDashed` 已有（`:251-297`），卡片底色用 `bgCard`，描边用 `divider`；**禁止**硬编码 hex（`docs/design/ui-spec.md:155`）。
- 动效只取 `Motion`（`fast 120 / normal 200 / slow 300`，标准曲线）；卡片出现/删除用减速/加速曲线；缩放与拖拽**不做插值**（1:1 跟手），与编辑器「选区拖动禁止插值」的既有约定一致。
- 可访问性：Canvas 自绘卡片必须配 `accessibilityVirtualNode`（官方明确用于「系统无法识别的自绘制组件」），每张卡片至少播报「标题 + 类型」；连线不播报，改为在卡片详情里以列表形式给出「关联 N 项」。触屏可用的手势（双指缩放）必须有不依赖多指的替代入口（工具条按钮）。

### D10 平台外壳约束：新页面必须自己补齐的九件事

| 约束 | 事实（证据） | 画布页要做的事 |
|---|---|---|
| 窗口拖动 | 主界面已不挂 `DesktopTitleBar`（守卫 `tools/arkts-guard.cjs:307-308`），`startWindowMove` 只能在 `TouchType.Down` / 左键按下里调（`utils/WindowDrag.ets:16`） | 顶栏自己留拖动热区；**禁止** `moveWindowTo`（守卫第 7/8 项会 fail） |

| 模糊预算 | 每屏 ≤ 2 层实时模糊（`constants/LightTokens.ets:39`），卡片/列表/分段页签零模糊 | 卡片不做毛玻璃，用底色 + 1px `divider` |

### P0 技术验证（2–3 天，spike 分支，不合并主干）

| 验证项 | 方法 | 通过判据 |
|---|---|---|
| Canvas 重绘帧率 | 合成 50/100/200/500 张卡片（真实文字长度分布），连续拖拽 10s | 200 张 ≥ 55fps；500 张有明确降级方案 |
| 缩放后文字质量 | 1.0 / 1.5 / 2.0 三档截图对比 | 2.0 档无可见模糊/重影 |
| 手势分派 | 手机触摸 + 2in1 鼠标滚轮/右键/触控板 | 滚轮不平移跳变；卡片拖拽不带动画布 |
| 缩放锚点 | 以视口四角为锚双指缩放 | 锚点世界坐标位移 < 1vp |
| 无障碍 | 开启屏幕朗读，聚焦卡片 | 能播报标题与类型 |

**不通过的处理**：文字质量不过 → 评估方案 C（LOD）；帧率不过 → 提前启用静态层缓存 + 裁剪；仍不过 → 把节点上限降到 200 并在 UI 明示。

### P1 只读复活（3–5 天）：把「关系图」的门重新装上

- 用纯 Canvas 重写关系图视图，只读消费 `RelationStore.nodes/edges`（节点 `x/y` 目前恒为 0，**布局由视图内计算**，不回头改 store），确定性布局（半径环 / 树形二选一）、缩放、平移、点节点 → 打开人物详情。
- 入口：宽屏工作区视图切换 + 手机 `⋯` 菜单（**只读**，不改任何数据）。
- 验收：`arkts-guard` + 7 个 Node 脚本全绿；真机三形态各跑一遍关键路径；缩放锚点、滚轮分流与 P0 结论一致。
- **新文件必须登记进守卫白名单**（`tools/arkts-guard.cjs:20-24` 的 `T3` 数组），否则守卫不扫新代码，等于「假绿」。
- 回退：删视图文件 + 撤入口，零数据风险（不写库）。

### P2 可编辑画布（8–12 天）：三表 + 拖拽 + 连线 + 编辑

- 数据层：`canvases / canvas_cards / canvas_links` + DAO/Repository/Store（照 `RelationStore` 的 `scopeBookId + loadRev` 范式）+ 备份字段 + **`chapterIdMap` 修复**。
- 交互：拖卡片、平移、缩放、创建/删除连线、卡片编辑浮层（标题/正文/类型/颜色）、撤销重做（命令栈，作用域限于画布）。
- 验收：`tools/data-regression.cjs` 新增用例（画布 CRUD、备份往返、悬空引用）；断网/无库场景不崩；长时间拖拽后内存曲线回落（DevEco Profiler）。

- 回退：功能开关（`UiStore` 加一个 `canvasEnabled`），关掉后表仍在、不写不读。

### P3a 编辑器只读地基（2–3 天，可独立交付）

- `CanvasTextEditorController` 增 `getSelection()` / `getSelectedText()` / `getParagraphRangeAt(offset)` / `revealOffset(offset)`（内部已有 `selMgr.setSelection`、`ensureCaretVisible`，只是未暴露，见 §1.5）。
- 抽 `model/ParagraphUtil.ets` 收敛三份段落实现，统一 `\r\n`；补 `FlowText.test.ets` 用例（字素边界、CRLF、段首/段尾）。
- 验收：不改任何既有行为；`node tools/flowtext-regression.cjs` 98 项仍全绿 + 新增用例；设备侧 FlowText 26 用例不回退。
- 回退：纯新增方法，回退即删。

### P3b 编辑器联动（4–6 天）：选区 → 卡片、卡片 → 原文

- 命令层按 §1.5 的六处清单加「发送到画布」（`EditCommand` 枚举、Router 接口 + switch、`CanvasEditCommandHost` 适配器、编辑器落点、快捷键、浮层菜单）；**浮层菜单的 11 项 + 5/6 两行切分要同步解耦**。
- 卡片详情「查看原文」走 `Navigator.openChapter`（`shell/Navigator.ets:43-46`）+ `revealOffset`；「当前文稿大纲一键生成画布」按标题层级建卡 + 连线（`TextDocument.headingAt` 已有）。
- 验收：改字号/主题/窗口宽度后跳转仍准确（这三项历史上都会让自绘编辑器漂移，见 `docs/editor-drift-selection-fix.md`）；一键排版/导入后锚点失配能降级到「最近段落 + 提示」；当前文稿内跳转可见光标。

### P4 模板与引导（3–5 天）：承接豆包的产品层

- 验收：新增一个模板 = 加一个 JSON，不改任何组件代码；模板导入非法时拒绝且不污染现有画布。

## 附：与豆包方案的取舍总表

| 维度 | 豆包 | 本方案 | 差异原因 |
|---|---|---|---|
| 技术栈 | AntV X6 / React Flow / 原生 DOM+SVG | ArkTS + ArkUI + Canvas | 平台不支持 |
| 渲染 | Canvas 连线 + 原生卡片 | 纯 Canvas 自绘 + 原生浮层 | 单一坐标系、缩放清晰、性能可控 |
| 状态管理 | V1 `@State/@Link` | V2 `@ObservedV2/@Trace` | 全仓约定 |
| 持久化 | localStorage → IndexedDB | relationalStore + 备份 JSON | 已有体系 |
| 缩放 | 逐帧累乘 | 基准 + 累计 + 锚点补偿 | 官方语义 |
| 布局 | 力导向为主 | 确定性树形/环形的「一键整理」 | 可逆、不打散用户摆放 |
| 入口 | 一级功能模块 | 文稿的另一种打开方式 | 本仓极简方向 |
| 工期 | 4–7 周合计 | P0–P4 合计 22–34 个工作日（约 4.5–7 周） | 本仓回归与多端门禁成本 |
