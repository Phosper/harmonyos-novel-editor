# 鸿蒙官方文档调研：打造优雅、简洁、易用的应用

> 调研目标：为 Weaver（HarmonyOS 小说 / 长文本编辑器）梳理官方关于「优雅、简洁、易用」的可执行设计规范。
>
> 检索方式：本地官方文档库（`devecocli docs catalog` / `docs search` / `docs read`，共 6 个 catalog：harmonyos-guides、harmonyos-references、best-practices、harmonyos-faqs、harmonyos-releases、harmonyos-roadmap）。本报告所有结论均给出 `documentId` 出处。
>
> 重要说明：本地文档是**开发者向**的文档，**不含 HarmonyOS Design 视觉规范原文**（即没有官方设计网站的「设计理念 / 组件视觉规范 / 间距刻度表」）。凡是官方文档明确"详见：XXX"但本地不包含的内容，本报告均如实标注为**「本地文档中未找到」**，并说明替代依据。

## 一、结论摘要（可直接执行）

1. **颜色绝不写死**：所有颜色必须 `$r()` 引用资源（优先 `sys.color.*` 系统语义色），官方 CodeLinter 规则 `@cross-device-app-dev/color-value` 明确"禁止使用固定的值"。出处：`ide-coderlinter-recommended-rules`
2. **正文对比度 ≥ 4.5:1，图标与标题文字对比度 ≥ 3:1**（智慧屏深色正文推荐 11:1~15.1:1）；严禁低于 1.9:1。出处：`ide-app-analyzer-ag-policy`、`ide-app-analyzer-all-rules`
3. **点击热区 48vp×48vp（推荐）／不得小于 40vp×40vp（必须）**；API 26 起表单类组件默认最小触摸热区高度由 28vp 提升到 32vp。出处：`ide-app-analyzer-all-rules`、`changelogs-ux-7001`、`ts-universal-attributes-touch-target`
4. **字号不得小于 8fp/vp（必须），≥12vp 为推荐值**；字号单位建议用 `fp` 以跟随系统字体缩放。出处：`ide-app-analyzer-all-rules`、`ide-coderlinter-recommended-rules`
5. **宽屏上正文必须做"缩进布局"**：`md`（600–840vp）内容占 8 栅格的 6 列、两侧各空 1 列；`lg`（840–1440vp）内容占 12 栅格的 8 列、两侧各空 2 列。这是官方**唯一**直接对应"正文不宜过宽"的规范。出处：`bpta-multi-device-page-layout`、`bpta-multi-device-responsive-layout`
6. **断点只用系统断点**：`['320vp','600vp','840vp','1440vp']`（xs/sm/md/lg/xl）；一多规则强制"不能通过设备类型、设备方向或是否可折叠等属性来判断"。出处：`arkts-layout-development-grid-layout`、`ide-coderlinter-recommended-rules`
7. **窗口宽 ≥ 840vp 时把底部页签换成侧边导航栏**（≥1440vp 用侧边分级导航）。出处：`experience-suggestions-ux`、`bpta-multi-device-screen-layout`
8. **尺寸单位用 vp、字号单位用 fp**；`span`/`offset` 不建议用小数。出处：`ide-coderlinter-recommended-rules`
9. **动效要克制且必须有反馈**：点击后有 100ms~300ms 无反馈窗口，官方建议"按下那一刻即响应动效反馈"；Toast 单次显示**不要超过 3 秒**，"杜绝强制占位和密集弹出"。出处：`bpta-fair-use-animation`、`arkts-create-toast`
10. **做减法有官方原话**："简洁易用的设计原则是指去除冗余和复杂的功能及其元素，使用清晰明了的元素，**避免信息过载**"。出处：`bpta-smooth-application-design`
11. **性能即体验的硬指标**：点击响应 ≤100ms、滑动响应 ≤80ms（拖滑 ≤60ms）、点击完成 ≤900ms、冷启动首帧 ≤1100ms、滑动卡顿率 ≤5ms/s、转场卡顿率 0ms/s、最大连续丢帧数 0。出处：`performance-delay`、`performance-frame-rate`、`ide-app-analyzer-all-rules`
12. **节点预算**：单页 <1000 个组件节点、树深 <30 层、单节点子数 ≤60；`ForEach` item <50（超长文本列表必须用 `LazyForEach`）。出处：`ide-app-analyzer-all-rules`

## 二、UI Design Kit 覆盖范围与可用组件清单

出处：`ui-design-introduction`（开发指南/UI_Design_Kit_UI设计套件/UI_Design_Kit简介）

> 原文定位："UI Design Kit（UI设计套件）是华为提供的符合 HarmonyOS Design System 规范的 UI 界面开发套件集合。通过提供多样式的扩展组件、丰富的光影效果，支撑开发者高效构建**高端精致的界面**（参见 HarmonyOS 设计理念），确保应用在 HarmonyOS 全场景设备上达成一致的视觉体验与设计品质。"

| --- | --- |
| 扩展组件 | 多样化的组件样式（导航、侧边栏、页签、列表、操作栏、即时操作、应用内多窗） |

### 2.4 设备与限制

- 支持国家/地区：**仅中国境内**（不含港澳台）。出处：`ui-design-introduction`
- HDS 沉浸视效**模拟器不支持**（点光源、按压阴影、双边边缘流光、背景流光、自带背景双边流光、沉浸光感材质）。
- `HdsNavigation`/`HdsNavDestination`：横屏且导航栏为 Stack 模式时，不支持合并工具栏到菜单栏。

> 结论：对 Weaver 而言，**直接可用**的是 `HdsNavigation` + `HdsSideBar/HdsSideMenu` + `HdsListItem` + `HdsActionBar` + `HdsSnackBar` 五件套；`HdsTabs` 次之；光影视效**不建议**引入（与"简洁"目标相悖，且模拟器不可验证）。

## 三、布局与间距规范（数值表）

> ⚠️ 前置结论：**官方本地文档中未找到「4/8 倍数间距刻度表」或统一的 spacing 档位表**。官方只提供"命名化 token"（`sys.float.padding_levelN`、`sys.float.corner_radius_levelN` 等），其**具体数值在本地文档与 SDK 中均未给出**，需查阅线上《系统基础与语义 Token 全量表》。本节给出的是文档中**能确证的数值**。

### 3.1 断点（响应式布局的基准）

| 断点 | 取值范围 | 设备描述 | 出处 |
| --- | --- | --- | --- |
| xs | [0, 320) | 最小宽度类型 | `arkts-layout-development-grid-layout` |
| sm | [320, 600) | 小宽度（手机） | 同上 |
| md | [600, 840) | 中等宽度（折叠屏展开、小平板） | 同上 |
| lg | [840, +∞) | 大宽度（平板、PC/2in1） | 同上 |
| xl | [1440, +∞)（自定义） | 特大宽度 | `bpta-multi-device-screen-layout`、`bpta-multi-device-page-layout` |

- `GridRow` 默认断点数组为 `["320vp","600vp","840vp"]`；官方最佳实践统一使用 `['320vp','600vp','840vp','1440vp']`（xs/sm/md/lg/xl）。
- **一多规则强制**：必须使用系统断点判断，**不能**通过设备类型/方向/是否可折叠判断。出处：`ide-coderlinter-recommended-rules`（`@cross-device-app-dev/one-multi-breakpoint-check`）

### 3.2 栅格（12 列制）

| 项目 | 数值 | 出处 |
| --- | --- | --- |
| `GridRow.columns` 默认值（API 20 前） | `12` | `arkts-layout-development-grid-layout` |
| `GridRow.columns` 默认值（API 20 起） | `{ xs: 2, sm: 4, md: 8, lg: 12, xl: 12, xxl: 12 }` | 同上 |
| `gutter` 默认值 | `0` | 同上 |
| gutter 用法示例 | `gutter: 10`（行列等距）/ `gutter: { x: 20, y: 50 }` | 同上 |
| 栅格自身不提供 margin | 直接用通用属性 `margin` / `padding` 控制左右留白；`margin` 在容器外、`padding` 在容器内（`backgroundColor` 只影响 padding 区） | `bpta-multi-device-responsive-layout` |
| `span`/`offset` | **不建议使用小数** | `ide-coderlinter-recommended-rules` |
| 全部 `GridCol` 只设 `span` 且等于父 `columns` | 不推荐 | 同上 |

### 3.3 内容区宽度（★ 对应"正文不宜过宽"）

官方"缩进布局"就是宽屏正文宽度的规范：

> "缩进布局是指在空间充足时，组件居中展示并在两侧留白，通过调整内容的缩进来建立视觉层次结构，**提高可读性和美观性**。"——`bpta-multi-device-page-layout`
>
> "缩进布局**适用于纯段落文本** / 上图下段落文本 / 卡片的布局结构的场景。当栅格为 8 columns 或 12 columns 时可以使用 6 columns 和 8 columns 的缩进布局。"——`bpta-multi-device-responsive-layout`

**单列列表（正文）缩进规格**（出处：`bpta-multi-device-page-layout`）：

| 横向断点 | 窗口栅格 | 内容占列 | 两侧各偏移 | 内容实际宽度占比 |
| --- | --- | --- | --- | --- |
| sm | 4 | 4 | 0 | 100% |
| md | 8 | 6 | 1 | 75% |
| lg | 12 | 8 | 2 | **66.7%** |
| xl | 12 | 8 | 2 | 66.7% |

参考实现：

```ts
GridRow({
  columns: { xs: 4, sm: 4, md: 8, lg: 12, xl: 12 },
  gutter: 0,
  breakpoints: { value: ['320vp', '600vp', '840vp', '1440vp'] },
  direction: GridRowDirection.Row
}) {
  GridCol({
    span:   { xs: 4, sm: 4, md: 6, lg: 8, xl: 8 },
    offset: { xs: 0, sm: 0, md: 1, lg: 2, xl: 2 }
  }) { /* 正文 */ }
}
```

> ⚠️ 官方**未**给出"每行多少字"或"正文 max-width 具体 vp 值"的规定；上表是唯一的官方量化依据。Weaver 可直接采用「lg 内容宽 = 窗口宽 × 8/12」作为正文栏最大宽度，或换算成固定 `maxWidth`。

## 四、字体与排版规范（含长文阅读/书写建议）

### 4.1 字体族

| 项目 | 规格 | 出处 |
| --- | --- | --- |
| 系统默认字体族 | **`'HarmonyOS Sans'`**（ArkUI 全部文本组件默认值） | `ts-basic-components-text`、`ts-types`、`ts-basic-components-button` 等 |
| 中文字体文件 | `/system/fonts/HarmonyOS_Sans_SC.ttf`（另有 `HarmonyOS_Sans_Italic.ttf`、`HarmonyOS_Sans_Bold.ttf`、`HarmonyOS_Sans_Thin_Italic.ttf`） | `arkts-apis-graphics-drawing-typeface` |
| 多字体写法 | 逗号分隔，按顺序生效，如 `'Arial,HarmonyOS Sans'` | `ts-types` |
| 自定义字体注册 | `font.registerFont()`（TTF/OTF）/ `fontCollection.loadFontSync()`；优先从 `resources/rawfile` 加载 | `js-apis-font`、`bpta-custom-font-settings` |
| 不想跟随主题字体 | 显式设为 `'HarmonyOS Sans'` | `ts-basic-components-marquee` |

### 4.2 字号

**硬性下限**（出处：`ide-app-analyzer-all-rules`、`ide-app-analyzer-ag-policy`）：

| 规则 | 数值 |
| --- | --- |
| 推荐最小字号 | **≥12vp**（手机/折叠/平板） |
| **必须**最小字号 | **≥8vp / 8fp** |
| 界面图标最小 | ≥12vp 推荐，≥8vp 必须 |

**单位**：字号建议用 `fp`（跟随系统字体设置）；组件尺寸用 `vp`。出处：`ide-coderlinter-recommended-rules`（`@cross-device-app-dev/font-size-unit`、`size-unit`）

**官方字号 token（两套并存）**：

### 4.3 系统字体缩放档位（长文阅读必须适配）

出处：`arkui-support-for-aging-adaptation`

| 档位 | 字体大小 | 字体粗细 |
| --- | --- | --- |
| 标准 | 1倍 | 1倍 |
| 大1档 | 1.15倍 | 1倍 |
| 大2档 | 1.3倍 | 1.1倍 |
| 大3档 | 1.45倍 | 1.1倍 |
| **大4档** | **1.75倍** | 1.25倍 |
| 大5档 | 2.0倍 | 1.25倍 |
| 大6档 | 3.2倍 | 1.25倍 |

- 适配规则原文："在系统使用 **1.75 倍及以上**的大字体时，页面布局不得错乱，组件不得叠加，文字不得截断。"
- "若应用需适应系统字体大小的变化，**最大应调整至 1.75 倍**，但**部分组件可调整至 2 倍**"（通过 `Text.maxFontScale(2)` 单独放开）。
- 图标及图片**不随**字体变大而变化。
- 接入方式：`app.json5` 增加 `"configuration": "$profile:configuration"`，在 `base/profile/configuration.json` 写 `{"configuration":{"fontSizeScale":"followSystem","fontSizeMaxScale":"1.75"}}`。
- 运行时读取：`context.config?.fontSizeScale`，监听 `onConfigurationUpdate`。

### 4.4 行高与"每行字数"——★ 关键结论

- **本地官方文档中未找到**"正文行高建议倍数"（如 1.5 / 1.8 倍）或"每行多少字"的规定。
- 能查到的只有 API 层能力而非设计规范：
  - `Text.lineHeight()` / `StyledString` 的 `lineHeight`（单位 vp），`@ohos.graphics.text` 的 `TextStyle.heightScale`（**行高缩放倍数，默认 1.0**；还有 `lineHeightMaximum` / `lineHeightMinimum` / `lineSpacing` / `halfLeading`）。出处：`ts-universal-styled-string`、`js-apis-graphics-text`、`arkts-apis-graphics-drawing-typeface`
  - 组件默认行高示例：讯飞式登录按钮 `.lineHeight(48)` / `.lineHeight(19)`（仅示例值）。
- **官方给"长文可读性"的替代方案是"控制内容宽度"而非"控制行高"**：即第三节的缩进布局（lg 下正文占 8/12 栅格）。这应当作为 Weaver 正文栏设计的首要依据。
- 列宽/内容密度还有一条间接约束："**不建议一排图标数量过多导致信息过密**，折叠屏上建议一排不超过 8 个图标"（`ide-app-analyzer-all-rules`）。

> 建议做法：行高沿用行业惯例（正文 1.5~1.8 倍，1.75 倍为佳）并在 Weaver 内作为产品参数固化——**这一条没有官方数值背书**，属产品决策而非官方规范。

### 4.5 文本溢出与截断

### 6.1 官方动效体系与场景分类

出处：`bpta-fair-use-animation`

> "HarmonyOS 动效引力体系，围绕**回归本源**设计理念，打造了自然、流畅、品质一体的操作体验。"动效分为 5 类：**特征动效、转场动效、手势动效、微动效、插画动效**。

| --- | --- | --- |
| 特征动效 | 天体拟物感知、品牌效应 | 开场动画、加载动画、下载动画 |

| 手势动效 | "力的控制感" | 点击、滑动、翻动、夹捏、拖拽 |
| 微动效 | 增加生动感 | 按钮点击、图标变化、文本出现 |
| 插画动效 | 趣味性 | 空状态、引导 |

| 滑动白块率 | ≤ 6.1 ms/s | 同上 |

> 对 Weaver 的结论：**动效只保留 3 处**——页面转场（左右位移）、面板/工具条出现（上下位移或淡入淡出）、按压反馈（按下即响应）。其余全部删除。

### 7.4 手势使用场合与禁忌

出处：`bpta-gestures-practice`（手势事件冲突解决方案）、`experience-suggestions-ux`

**默认优先级（禁忌的根源）：**

1. 父子组件绑定同类型手势时，**子组件优先**于父组件
2. 同一组件绑定多个手势时，**先达到触发条件**的优先
3. 同一组件同时绑定系统手势与自定义手势（同为单击），**系统手势优先**（`onClick` 优先于 `TapGesture`）
4. "除非显式声明允许多个手势同时成功，否则**同一时间只会有一个手势响应**"

**控制手段**：

| 方法 | 行为 | 约束 |
| --- | --- | --- |
| `gesture` | 父子交叠区域响应子组件 | 与通用事件抢占 |
| `priorityGesture` | 父组件优先识别 | 与通用事件抢占 |
| `parallelGesture` | 父子相同手势都可触发 | 无 |
| `GestureMask.IgnoreInternal` | **屏蔽子组件手势，包括 List 内置滑动手势** | 仅屏蔽交叠部分 |

**官方明文禁忌 / 要求：**

- "**避免与系统手势冲突**：应用自定义手势与系统手势无冲突"（`experience-suggestions-ux`）
- "**典型手势时长设计**：应用使用的典型手势时长合理"（同上）
- 侧滑返回：主窗可用 `window` 接口启用手势侧滑返回；**禁用后当前应用禁用手势热区**（`arkts-apis-window-window`）
- List 的横滑删除：系统返回键生效时默认收起划出组件（`ts-container-list`）

### 7.5 弹窗选型（避免模态叠模态）

出处：`arkts-dialog-overview`

| 场景 | 官方推荐组件 |
| --- | --- |
| 需展示用户当前需/必须关注的信息或操作（如二次退出） | **Dialog**（弹出框） |
| 给用户提供可执行操作（如长按图标出选项） | **Menu / openMenu** |
| 给用户提示（如点击问号弹出帮助） | **Popup / openPopup** |
| 新界面覆盖旧界面且旧界面不消失（如点缩略图看大图） | **bindContentCover / bindSheet** |
| 小窗口简单反馈（如"文件保存成功"） | **Toast** |
| 完全自定义内容/行为/样式（如音乐悬浮球） | **OverlayManager** |

**官方禁忌：**

- "**不建议在非前台状态下，调用弹窗显示接口**"
- "系统弹窗出现时，调用非系统弹窗的显示接口（如 `openCustomDialog`、`CustomDialogController.open`），**禁止该类弹窗显示**"
- "对于**复杂或者冗长的用户流程，建议考虑其他的转场方式替代半模态**（如全模态转场和 Navigation 转场）"
- 规格约束："多个弹窗组件先后弹出时，后弹出的层级高于先弹出的层级，退出时按层级从高到低逐次退出"
- 半模态内嵌 UIExtension 时，**不支持**再在其中拉起半模态/弹窗

## 八、易用性与无障碍

### 8.1 无障碍开发指导要点

出处：`arkts-universal-attributes-accessibility`

**屏幕朗读聚焦原则（5 条，官方原文）：**

1. **浏览顺序**：焦点浏览遵循界面**从上至下、从左至右**的视觉布局顺序依次切换
2. **聚焦范围**：仅支持对界面**可见**组件聚焦，隐藏内容不纳入
3. **焦点数量**：可视界面内有且**仅有 1 个焦点**
4. **焦点热区大小**：需合理设置，避免过小难以触摸，或过大遮挡其他节点、引发焦点丢失
5. **默认焦点**：新应用界面、同应用新页面、新弹窗弹出时，**自动聚焦至页面首个元素**

**播报原则**：按"**组件状态 → 文本内容 → 组件类型 → 操作提示**"优先级组合播报，仅播报实际存在的属性。

| 播报内容 | 配置接口 | 示例 |
| --- | --- | --- |
| 组件状态 | `accessibilityChecked` / `accessibilitySelected` | "已选中"、"未选中" |
| 文本内容 | `accessibilityText` | "首页"、"设置" |
| 组件类型 | `accessibilityRole` | "按钮"、"编辑框" |
| 操作提示 | `accessibilityDescription` | "单指双击即可播放" |

**`accessibilityText` 配置原则（重要）：**

- "建议配置的文案**简洁、精准且表意完整**"
- "**请勿**在 `accessibilityText` 中设置组件状态、组件类型、操作提醒等信息"（会与默认播报重复）
- "如果组件本身已有可视文本内容且同时配置了 `accessibilityText`，屏幕朗读将**仅播报** `accessibilityText` 的内容"

**聚焦顺序控制**：

- 用 `accessibilityNextFocusId` 指定下一个聚焦组件；**建议按画面显示的自上而下、自左向右设置**
- 禁忌 1："**避免焦点移动陷入死循环**"（A→B→A→B…）
- 禁忌 2："非必要情况下，需**避免出现节点无法被焦点遍历到的情况**"
- 隐藏/非交互内容用 `accessibilityLevel('no')` 禁止聚焦
- 无实际节点的交互区域用 `accessibilityVirtualNode` 配虚拟节点

**动态播报**：`sendAccessibilityEvent('announceForAccessibility')`（如"已下载 50%"）；无焦点时用 `'requestFocusForAccessibility'` 指定默认聚焦目标。

## 九、官方明确的"避免清单"（原话摘录）

### 9.1 关于"简洁 / 信息过载"

> "**简洁易用的设计原则是指去除冗余和复杂的功能及其元素，使用清晰明了的元素，避免信息过载。过多的元素会分散用户的注意力，使用户无法集中在主要功能上。简洁易用的设计能降低用户的认知负担，提高使用效率，使用户更专注于完成任务，提升用户体验。**"
> —— `bpta-smooth-application-design`

> "**一致性**是指交互界面的呈现形式和交互元素的操作保持一致，以便用户在不同页面或模块间轻松理解和使用。"
> —— 同上

> "**反馈清晰**：用户操作后，应用需立即响应。"
> —— 同上

### 9.2 关于"边距 / 信息密度"

> "**一般不建议用边距的方式来控制信息量，左右边距的留白不要太大。同一个应用内不同的页面建议保持相同的边距。同一个应用在不同端上，可以根据设备屏幕的宽度进行适量的边距调整。**"
> —— `ide-app-analyzer-all-rules`（边距适中，权重 5，UX 最高权重之一）

> "**不建议一排图标数量过多导致信息过密，折叠屏上建议一排不超过 8 个图标。**"
> —— 同上（图标文字大小适中）

### 9.3 关于"提醒 / 弹窗"

> "**合理使用弹出场景，避免过度提醒用户。**"
> —— `arkts-create-toast`

> "**注意文本的信息密度**，即时反馈展示时间有限，应当避免长文本的出现。"
> —— 同上

> "**杜绝强制占位和密集弹出的提示。**…应当避免内容布局占用界面内的其他元素信息，如遮盖弹出框的展示内容…再或者频繁性的弹出信息内容，且每次弹出之间无时间间隔，影响用户的正常使用。**也不要在短时间内频繁弹出新的即时反馈替代上一个。即时反馈的单次显示时长不要超过 3 秒钟，避免影响用户正常的行为操作。**"
> —— 同上

> "**遵从系统默认弹出位置。**…作为系统性的应用内提示反馈，请遵从系统默认效果，**避免与其他弹出类组件内容重叠**。"
> —— 同上

> "**不建议在非前台状态下，调用弹窗显示接口。**"
> "系统弹窗出现时，调用非系统弹窗的显示接口…**禁止该类弹窗显示**。"
> —— `arkts-dialog-overview`

> "对于**复杂或者冗长的用户流程，建议考虑其他的转场方式替代半模态**。"
> —— `arkts-sheet-page`

### 9.4 关于"层级 / 节点 / 嵌套"

> "**避免过大组件树节点数目。建议一个页面使用少于 1000 个组件树节点，节点树深度少于 30 层，子节点数不大于 60 个。**"
> —— `ide-app-analyzer-all-rules`

> "**ForEach 中 item 数量要小于 50。**"
> —— 同上

> "**避免滑动类容器组件区域超出屏幕显示范围 10%。**滑动类容器组件的渲染范围与容器大小相同，超出屏幕的不可见部分为冗余渲染。"
> —— 同上

> "**避免冗余嵌套，尽量使用扁平化布局优化层级。**"
> —— `bpta-click-to-click-response-optimization`

> "组件复用时应**避免**在 `aboutToReuse` 中执行耗时操作。"
> —— `bpta-time-optimization-of-the-main-thread`

> "**应避免在自定义组件的生命周期内执行高耗时操作。**"
> —— `bpta-pptimized-component-drawing`

> "在实现文本浮层、按压遮罩或颜色叠加等场景时…**推荐优先使用组件属性代替嵌套组件**。"
> —— `bpta-component-nesting-optimization`

> "**使用扁平化布局减少节点数。**…通过一些高级组件如 `RelativeContainer`、`Grid` 等容器，可以让元素在平面上展开。"
> —— `arkts-layout-optimization-guidance`

### 9.5 关于"动效 / 光效"

> "在设计动画时，需要考虑到设备的性能和资源消耗，**避免过多的动画效果导致性能下降或者卡顿**。"
> —— `bpta-fair-use-animation`

> "**合理运用能显著提升应用质感**"…"应遵循"**内容为先、体验至上、灵动交互**"的原则，确保沉浸光感增强 UI 的同时**不牺牲操作效率**。"
> —— `bpta-spatiality-immersive`

> "**强行在低端设备上开启可能导致卡顿和发热。**"
> —— 同上

### 9.6 关于"颜色 / 沉浸式"

> "在沉浸式 UI 中**应避免出现纯白色或者纯黑色的色调背景**，防止服务卡片的其他组件及内容受到影响。"
> —— `bpta-music-card`

> "颜色值应当使用 `$r` 从 `color.json` 中引用…**禁止使用固定的值**。"
> —— `ide-coderlinter-recommended-rules`

### 9.7 关于"深色模式"

> "深色模式**并非简单地将页面背景变为黑色、文字内容变为白色**，而是提供一整套适配深色模式的应用配色主题。"
> —— `bpta-dark-mode-adaptation`

> "**开发者在使用资源时，未采用监听系统深浅色模式变化的方式，而是在属性设置中，通过函数返回值实现深浅色切换**"被列为"**不推荐方法**"。
> —— `ui-dark-light-color-adaptation`

### 9.8 关于"一多 / 状态栏"

> "一多特性必须使用系统断点判断是否开启，**不能通过设备类型、设备方向或是否可折叠等属性来判断**。"
> —— `ide-coderlinter-recommended-rules`

> "布局适配应优先基于响应式断点，而非设备折叠状态。…**切勿直接以设备折叠状态作为布局判断依据**。"
> —— `bpta-matext-guide`

> "采用沉浸一体化的背景设计，保证效果的整体性，**避免状态栏区域被单独切割**。"
> —— `ide-app-analyzer-all-rules`

```

│   ├── element/float.json      # 尺寸/字号/间距/圆角档位
│   ├── media/
│   └── profile/configuration.json   # fontSizeScale 等

```

### 10.7 性能相关的资源使用建议

- 优先级：匹配 移动国家码/网络码 > 区域 > 横竖屏 > 设备类型 > **颜色模式** > 屏幕密度（`resource-categories-and-access`）
- 深浅色切换优化：`module.json5` 加 `"metadata": [{"name": "configColorModeChangePerformanceInArkUI", "value": "true"}]`，可避免深浅色切换全量重绘；但要求"属性设置中**没有**通过函数返回值实现深浅色切换"；`HdsNavigation`/`HdsNavDestination`/`HdsTabs`/`HdsListItemCard` 四个组件**暂未适配**。出处：`ui-dark-light-color-adaptation`

## 十一、对 Weaver 的具体建议（现状 → 建议 → 依据）

### 建议 1（★ 最高优先级）：正文栏做"缩进布局"，宽屏不再铺满

| 项 | 内容 |
| --- | --- |
| **现状** | 正文/编辑区在平板、PC/2in1 上大概率铺满窗口宽度，行长过宽，阅读与书写体验差 |
| **建议** | 用 `GridRow`/`GridCol` 实现官方"单列列表缩进布局"：`sm` 占 4/4 列；`md` 占 8 列中的 6 列（offset 1）；`lg`/`xl` 占 12 列中的 8 列（offset 2）。即宽屏下正文宽 ≈ 窗口宽 × 66.7%。断点固定用 `['320vp','600vp','840vp','1440vp']` |
| **依据** | `bpta-multi-device-page-layout`（"单列列表布局"）、`bpta-multi-device-responsive-layout`（"缩进布局适用于纯段落文本"）、`arkts-layout-development-grid-layout`（断点定义） |

### 建议 2（★）：调色板全面对齐官方 token 语义，并把 ThemeColors 的 Light/Dark 值作为基准

| 项 | 内容 |
| --- | --- |
| **现状** | 已按 `ThemeColors`（brand / fontPrimary~Tertiary / backgroundPrimary / compBackgroundTertiary / compDivider / compEmphasizeTertiary·Secondary / warning / alert / confirm）重建了调色板，但具体色值可能自定 |
| **建议** | ① 直接采用官方缺省 token 色值（见 5.1 全表）作为 base/dark 双目录的取值；② 优先 `$r('sys.color.*')` 而不是自建；③ 若必须自建，命名沿用官方体系（`font_*`、`background_*`、`comp_background_*`、`comp_divider`、`comp_emphasize_secondary/tertiary`、`interactive_*`）；④ 全文禁止硬编码色值 |
| **依据** | `theme_skinning`（系统缺省 token 色值表）、`arkts-apis-uimaterial`（表1）、`ide-coderlinter-recommended-rules`（`color-value` 禁止固定值） |

### 建议 3（★）：字号与行高——字号用 fp + 系统 Token，行高作为产品参数固化

| 项 | 内容 |
| --- | --- |
| **现状** | 已计划字号档位；行高与每行字数尚无官方依据 |
| **建议** | ① 字号一律用 **fp**，禁止 < 8fp，UI 正文默认 ≥12vp（推荐 16~17fp）；② 字号取自 `sys.float.Body_L/Body_M/Body_S` 等语义 Token；③ 长文正文行高设 1.5~1.8 倍（建议 1.75 倍）——**注：无官方数值背书，属产品决策**；④ 通过"正文栏宽度缩进"（建议 1）而非行高来控制长文可读性 |
| **依据** | `ide-app-analyzer-all-rules`（12vp 推荐 / 8vp 必须）、`ide-coderlinter-recommended-rules`（`font-size`、`font-size-unit`）、`resource-categories-and-access`（`sys.float.Display_L` 等 Token 用法）、`bpta-multi-device-page-layout`（可读性靠宽度控制） |

### 建议 4：适配系统字体缩放（适老化），长文尤其重要

| 项 | 内容 |
| --- | --- |
| **现状** | 未确认是否接入 `configuration.json` |
| **建议** | 在 `base/profile/configuration.json` 配置 `fontSizeScale: "followSystem"`、`fontSizeMaxScale: "1.75"`；对正文文本额外 `maxFontScale(2)`；大字体下 V 轴流式布局须验证"不错乱、不叠加、不截断"；图标/图片不随字体放大 |
| **依据** | `arkui-support-for-aging-adaptation` |

### 建议 5：所有可点击元素热区 ≥ 48vp

| 项 | 内容 |
| --- | --- |
| **现状** | 编辑器工具条图标按钮通常按视觉尺寸给 24~32vp |
| **建议** | 视觉尺寸可保持 24vp，但用 `responseRegion` 把热区扩到 ≥48vp×48vp（硬底线 40vp）；工具条按钮间距与热区需协调避免互相吞并（相邻热区重叠会引发误触） |
| **依据** | `ide-app-analyzer-all-rules`（点击热区）、`ide_touch-target-size`、`experience-suggestions-ux` |

### 建议 6：给正文/界面文字定对比度门槛并纳入自测

| 项 | 内容 |
| --- | --- |
| **现状** | 二级/三级文本色（`font_secondary` `#99000000`、`font_tertiary` `#66000000`）在浅色背景下对比度可能不足 4.5:1 |
| **建议** | 正文文字对比度 ≥ 4.5:1、图标/标题 ≥ 3:1；三级及以下文本只用于**非正文**（辅助信息、占位符、禁用态）；上线前跑一次对比度自测（DevEco Studio AppAnalyzer / DevEco Testing UX 测试） |
| **依据** | `ide-app-analyzer-ag-policy`（正文 >4.5:1，图标/标题 >3:1，避免 <1.9）、`ide_color-contrast`、`bpta-dark-mode-adaptation` |

### 建议 7：把"长按/滑动"手势收敛到官方允许的范围

| 项 | 内容 |
| --- | --- |
| **现状** | 长文本编辑器易引入"长按拖拽选中""左右滑动换章""双指缩放字号"等自定义手势 |
| **建议** | ① 左右滑动换章与系统侧滑返回冲突时，用 `parallelGesture` 或收敛到边缘外区域，**避免与系统手势冲突**（UX 体验建议硬性项）；② 双指缩放与系统手势冲突概率高，字号调节建议改为设置面板而非手势；③ 自绘编辑器的手势用 `gesture`/`priorityGesture` 明确优先级，避免"同一时间多个手势响应" |
| **依据** | `bpta-gestures-practice`（优先级与冲突规则）、`experience-suggestions-ux`（避免与系统手势冲突、典型手势时长设计） |

### 建议 8：用 `HdsSnackBar` 替代 Toast 做轻反馈，并严格限制弹出频率

| 项 | 内容 |
| --- | --- |
| **现状** | 保存成功/同步完成等大概率用 Toast |
| **建议** | ① 非关键反馈（自动保存成功）用极轻的 `HdsSnackBar` 或内联状态，**不要每条都弹**；② 必须弹时单次 ≤3 秒、短文本、不含交互元素、不遮挡其他内容、不叠加多个；③ 文档编辑场景建议"保存成功"改为主界面角落状态点，而非弹窗 |
| **依据** | `arkts-create-toast`（"避免过度提醒用户"、"单次显示时长不要超过 3 秒钟"、"杜绝强制占位和密集弹出的提示"）、`ui-design-introduction`（HdsSnackBar 定位） |

### 建议 9：弹窗尽量非模态，禁止模态叠模态

| 项 | 内容 |
| --- | --- |
| **建议** | ① 编辑器内设置、导出选项等用 `bindSheet` 半模态或非模态 Popup，不用全屏模态；② **禁止**在半模态内再拉起弹窗（官方限制）；③ 复杂/冗长流程（如"导入小说"多步向导）**用 Navigation 转场替代半模态** |
| **依据** | `arkts-dialog-overview`（选型表、禁忌）、`arkts-sheet-page`（"复杂或冗长的用户流程建议考虑其他转场方式替代半模态"） |

### 建议 10：宽屏用"侧边栏 + Navigation"替代底部 Tab；窄屏底部页签固定 56vp

| 项 | 内容 |
| --- | --- |
| **建议** | 窗口 ≥840vp 时底部页签 → 侧边导航栏（≥1440vp 用侧边分级导航）；底部页签高度 56vp + 底部系统规避区；标题栏 78vp + 顶部规避区。建议采用 `HdsNavigation` + `HdsSideBar`/`HdsSideMenu` 直接获得官方样式 |
| **依据** | `experience-suggestions-ux`（侧边导航栏）、`bpta-multi-device-screen-layout`（56vp / 78vp）、`ide-coderlinter-recommended-rules`（`sidebar-navigation`）、`ui-design-introduction` |

### 建议 11：编辑器渲染层的节点与刷新预算（长文场景生死线）

| 项 | 内容 |
| --- | --- |
| **建议** | ① 单页 <1000 节点、树深 <30、单节点子数 ≤60；② 段落列表用 `LazyForEach`（`ForEach` item <50）；③ 单帧脏组件：滑动 ≤30 个、非滑动 ≤500 个；④ 单帧属性更新：滑动 ≤300、非滑动 ≤1500；⑤ 滚动容器不得超出屏幕 10%；⑥ 渲染时用 `RelativeContainer` 扁平化，禁止 Row 套 Row |
| **依据** | `ide-app-analyzer-all-rules`、`arkts-layout-optimization-guidance`、`bpta-click-to-click-response-optimization` |

### 建议 12：RichEditor 技术选型对齐官方最佳实践

| 项 | 内容 |
| --- | --- |
| **现状** | Weaver 用富文本编辑，需处理样式、序列化、段落操作 |
| **建议** | ① 官方结论：**"无需复杂样式操作、需频繁增删" → 选基于 Span 的 `RichEditor(value: RichEditorOptions)`；"样式更新灵活性优先" → 选基于 StyledString 的方式**；长文本编辑器两者都要（频繁编辑 + 富样式），需明确主次；② 自定义内联对象（如脚注、批注）用 `addTextSpan()` 而非 `addBuilderSpan()`（后者**无法折行**、**无法取回内容**）；③ 用 `customKeyboard(..., { supportAvoidance: true })` 支持避让；④ 光标用 `getCaretOffset()`，插入后需手动维护 `spanRange` |
| **依据** | `bpta-rich-text-editor`（含两套内容管理选型对比表、`addBuilderSpan` vs `addTextSpan` 对比表） |
