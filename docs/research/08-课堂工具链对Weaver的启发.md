# 08 · 课堂工具链对 Weaver 的启发

> 来源：2026-11-02《国际关系研究方法》实时转写（胡王云），主题为文献综述与文献管理。
> 定位：产品方向研究，不改代码；与 `06-可视化画布-方案适配分析.md`、`07-知识单元与跨书画布-统一方案.md` 配套。
> 转写为语音识别稿，工具名按上下文校正（幕布、Connected Papers、Zotero、Web of Science）。

## 0. 结论摘要

1. 老师推荐的工具有一条共同流水线：**检索 → 管理 → 结构化 → 关系洞察 → 成稿**。Weaver 的思路板已经覆盖后两段，缺的是**来源**和**洞察**。
2. 因此启发不是“做一个 Zotero”，而是把“来源”和“关系”补进现有的卡片模型，让“读完 → 整理 → 写”在一个界面里闭环。
3. 最高性价比：**来源实体 + 参考文献导出 + 捕获收件箱**。这三件事直接对应课程论文的痛点，且不动现有卡片/嵌套结构。
4. 第二层：**大纲/导图双视图、来源-观点关系图、对话矩阵/综述模板**。它们把老师讲的方法论变成可操作的视图。
5. 不学：PDF 文献库/全文检索、自动爬虫、力导向自动布局、AI 代写、先做云同步。

## 1. 老师实际推荐了什么

| 工具/资源 | 课堂用法 | 关键点（转写时间） |
|---|---|---|
| **幕布** | 读报告时顺手记概念，读完按自己的逻辑分级，再一键生成思维导图 | 多端同步；“先自由记、后结构化”；具象化整理思路（49:22–54:28） |
| **Connected Papers** | 输入关键词得到引文网络图，判断哪篇最重要、下一篇读什么 | 用引用/被引关系找“必读”；免费额度有限（54:28–56:54） |
| **Zotero** | 浏览器插件一键抓题录+全文；文件夹/标签分类；笔记关联；按期刊体例生成引文和参考文献表 | 抓取、组织、笔记、**引文格式自动化**；免费开源（1:02:55–1:09:38） |
| **CNKI / WoS / Scopus / JSTOR** | 检索文献；WoS 的引文网络做梳理与对话 | 布尔逻辑、精确短语、字段限制；中英文互补（57:13–1:01:42） |
| **社会网络分析（SNA）** | 国家=节点、关系=边，调一个节点看全网变化 | 多主体同时研究；方法论缺口的补充（21:10–22:34） |
| **智库报告/数据库** | 找素材、灵感、最新动态 | **报告不是论文**：可借素材，不可借学理框架（31:50–39:15） |
| **AI** | “外挂大脑”，辅助但不能代替产出 | 最终生成环节要靠自己；学校有 AI 使用声明要求（00:50） |

老师反复强调的两条方法论，比工具本身更重要：

- 文献综述不是“某某说、某某说”的**清单**，而是让文献**对话**；在争论最激烈或空白处找自己的 niche。
- 找缺口有四类入口：**理论缺口、实证缺口、方法缺口、争论点**；也可以顺着论文结论里的“未来展望”和综述性文献走。

## 2. 和 Weaver 现状对照

| 能力 | 课堂工具 | Weaver 现状 | 判断 |
|---|---|---|---|
| 知识单元 | Zotero 条目 / 幕布节点 | 概念卡、写作卡（`topics`） | 已有 |
| 结构 | 幕布大纲/导图 | 三层嵌套 + 自动编号 + C 型子卡 | 已有，且更贴论文体例 |
| 素材 | Zotero 高亮/笔记 | 引文/判断/笔记三类，带原文锚点、可跳回 | 已有，是差异点 |
| 关系 | Connected Papers 引文图 / SNA | 6 类语义连线（前提/因果/对比/例证/顺序/相关）+ 人物关系表 | 有“观点关系”，缺“来源引用关系” |
| 来源 | Zotero 题录 | 只有 `source_label` 字符串（书名·第 N 段） | **缺口** |
| 产出 | Zotero 引文格式 | 初稿生成 + TXT/MD/HTML/JSON 导出 | 缺参考文献表与体例 |
| 捕获 | 浏览器插件、剪贴板 | 编辑器选区 → 选卡/新建卡 | 有捕获，但**捕获即分类** |
| 洞察 | 中心性、引文网络 | 只有视觉连线，无统计/提示 | **缺口** |
| 同步 | 幕布多端 | 本地 relationalStore | 无云同步 |

一个具体的数据层事实：`topic_evidence.topic_id` 是 `NOT NULL`，素材必须挂在某张卡上；`EditorPane` 的捕获流程也是“选中文字 → 选择/新建卡片 → 加入”。所以现在做不到“先记下来、回头再归类”——这正是幕布和 Zotero 收件箱的价值所在。

## 3. 八个可借的启发

### 3.1 来源实体：把 `source_label` 升级为 Source（P0）

- 现在一条引文只知道“引自《书名》第 N 段”，不知道作者、年份、期刊、URL、类型，也无法回答“这篇文献被哪些卡引用”。
- 建议新增 `sources(id, book_id, type, title, authors, year, venue, url, doi, note)`，`topic_evidence` 增加可空 `source_id`；卡片可挂多个来源。
- 一旦有了结构化来源，参考文献导出、来源筛选、引文网络、重复检测都成立；小说场景则对应“设定来源”（神话/历史/访谈/网页）。
- 成本中低：不动卡片和 placement，只加一张表和一列；备份升 v3。

### 3.2 参考文献导出：把“写成初稿”补成“可交作业”（P0）

- 老师花了大量时间讲 Zotero 的引文格式：不同期刊体例、一键生成、100 篇一次导出。这是学生感知最强的“效率翻倍”。
- Weaver 的 `CanvasDraftWriter` 目前只写“原文 +（引自…）”，导出也没有参考文献表。
- 建议：按 source 去重、按正文出现顺序编号，支持 GB/T 7714、APA、Chicago 和自定义模板；导出 Markdown/HTML 时附在文末。先做“按出现顺序 + 一种默认体例”，不要一上来做格式市场。

### 3.3 捕获收件箱：幕布“先记后整理”的启发（P0/P1）

- 幕布好用在于读的时候不用想“这属于哪一章”，先顺手记，读完再归类。Weaver 现在捕获时就要选卡，认知负担前置。
- 建议加一个全局“收件箱”：允许暂存无卡引文/速记（或先落到一张“未整理”卡），之后再拖进卡片。卡片库已有“待整理”筛选，可以复用为入口。
- 这是低成本、高感知的改动，也是“边读边写”体验的关键。

### 3.4 大纲/导图双视图：幕布的“一键导图”（P1）

- Weaver 已有结构（placement 的 parent/order）和 `canvasFlatten/outlineRows`，缺的是同一份数据的另一种看法。
- 建议视图切换：**画布**（空间记忆）/ **大纲**（线性扫读）/ **导图**（树形自动布局）。导图用确定性树布局，可撤销；不做力导向（06 已论证会打散用户手工摆放）。
- 不学：把 Weaver 变成纯大纲工具——空间画布才是差异点。

### 3.5 来源-观点关系图：Connected Papers 的启发（P1）

- 老师的用法是“用引文网络找关键文献、决定读的顺序”；Weaver 的连线是“观点关系”，两者可以并存：
  - 卡片-卡片：前提/因果/对比/例证/顺序/相关（已有）。
  - 来源-来源：引用/被引（新）。
  - 来源-卡片：支撑/反驳（可复用素材的 kind）。
- 分析视图：节点大小=被引/被链接次数，颜色=主题/立场；孤立节点=还没进入论证的卡。只做只读分析或“建议整理”，不自动改布局。

### 3.6 对话矩阵/综述模板：老师方法论的直接产品化（P1）

- 老师给的批判性阅读五问（核心问题、理论框架、概念操作化、研究设计、结论新意）可以直接变成“来源卡模板”的五个字段；引文捕获时挂到其中一个维度。
- “综述视图”按主题分组，把 `contrast` 连线的卡两两配对，提示“这两篇在争什么”；导出的不是 quote 清单，而是“A 认为…；B 则认为…；分歧在于…”的对话式草稿。
- 这比“再加一个 AI 总结”更贴合课程要求：**判断必须由用户写**（07 已明确判断型素材只能手动添加，这是核心价值）。

### 3.7 卡片库的结构化检索：WoS/CNKI 高级检索的轻量版（P1）

- 现在搜索是标题/别名/标签的 `includes`；建议加筛选：类型、标签、来源类型、有无素材、有无连线、出现在几块白板；排序：最近/标题/被链接数/被引数。
- 不做全文检索或布尔表达式解析：100–1000 张卡的规模不需要，ArkTS 也没有现成引擎。

### 3.8 多端同步：幕布的真正壁垒（P2）

- 老师夸幕布的第一点是多端同步。Weaver 面向手机/平板/2in1，但数据在本地库；“手机上读到、电脑上写”的链路目前会断。
- 这是战略级工程（账号、冲突合并、隐私、备份），不要作为第一枪；先把来源、导出、收件箱做扎实，再评估 HarmonyOS 分布式数据/云同步。

## 4. 不建议照搬

- **不做 Zotero 替代品**：PDF 阅读/批注、全文库、浏览器插件生态，投入大且偏离“写作工具”。
- **不做自动爬虫/在线抓取**：离线、版权、维护成本高；先做“粘贴链接/DOI → 解析元数据，失败手填”。
- **不做力导向自动布局**：06 已判定不可逆、会打散手工摆放；自动布局只做“建议/可撤销”。
- **不把 AI 放在代写位置**：老师明确“外挂大脑可以，最终产出靠自己”；AI 生成内容要与用户判断分开标注、可追溯。
- **不把报告当论文**：来源类型要显式；报告可以给素材和灵感，不能给学理框架。

## 5. 先用起来：三个零代码验证

1. 用现有白板手工搭一个“文献综述模板”：研究问题 / 主要议题 / 理论缺口 / 实证缺口 / 方法缺口 / 争论点 六张写作卡；把 10 篇文献做成概念卡 + 引文素材，跑一遍“写成初稿”，看卡在哪。
2. 给 3 篇文献手工补来源字段，按 GB/T 7714 写参考文献表，检查格式、去重、顺序是否够用。
3. 统计当前白板的孤立卡与枢纽卡（连线数排序），看“分析视图”是否真的能提示缺口，而不是制造噪音。

## 6. 结论

老师的工具链验证了 Weaver 的方向：**知识单元（卡）+ 结构（父子）+ 对话（连线）+ 成稿（初稿）** 是对的，而且比 Zotero/幕布更贴近“从读到写”。下一步不是加更多“管理”功能，而是补 **来源** 和 **洞察** 两块——让文献进得来、引得出、看得见关系，最终仍然由用户写出判断。
