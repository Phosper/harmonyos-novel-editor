# 竞品调研：Effie 与同类优雅写作工具

> 调研对象：**Effie**（主线）、iA Writer、Bear、Typora、Ulysses、Notion 专注写作场景。
> 目的：提炼"以简洁优雅著称"的写作工具在**产品结构 / 交互模型 / 排版规格 / 信息架构**上高度一致的做法，供 Weaver（HarmonyOS 小说编辑器）借鉴。
> 约定：正文中标 `[S#]` 的句子对应"八、来源清单"中的条目，属**有来源支撑的事实**；标"（推断）"的为本报告基于事实的推理，未获直接来源。查不到的项如实写"未查到"。
> 说明：本文件为只读调研产物，不含任何源码改动。

---

## 一、结论摘要（≤10 条，可直接执行）

1. **"简洁"不等于"功能少"**：Effie 官方明确说"盲目地大量做减法导致的结果可能是简陋，而不是简洁"，它是靠大量复杂工作换来"看不见的简单" `[S3]`——Weaver 应追求"功能够用但默认不显"，而非砍功能。
2. **沉浸靠"自动退出"而非"手动进入"**：iA Writer 一开写就收起菜单与窗口装饰，只留正文与字数 `[S14]`；Effie 写作时把左侧栏自动调暗、鼠标移回才恢复 `[S3]`。**不需要用户点"专注模式"**。
3. **打字机模式（光标行固定在屏幕中央偏上）是多款工具的标配**：iA Writer、Typora、Effie、Ulysses 都有 `[S3][S14][S18][S21]`，解决"视线追光标导致颈椎弯"的隐蔽痛点，且实现成本极低（推断）。
4. **"稿纸感"用行号实现**：Effie 只保留"行号"这一个弱存在元素来让界面像一张稿纸（定位光标 / 看已写行数 / 构图重心右移）`[S3]`；对 Weaver 的"稿纸主题"是直接可抄的一招。
5. **正文行宽/字号/行高/段间距必须可调**：Effie 设置面板含 字体、行高、段间距、首行缩进、标题与正文字号、行宽（=改稿纸大小）`[S3][S5]`；Ulysses 提供主题下载与自定义 `[S21]`。**没有一款是写死排版的**。
6. **中文正文的"每行字数"应比英文更窄**：WCAG 1.4.8 建议拉丁文每行 ≤80 字符、而**中日韩文字每行 ≤40 字符** `[S16]`——这条常被忽略，恰是 Weaver（中文小说）最该守的数值。
7. **小说/长文工具都强调"大纲 ↔ 全文"双向同步与"看全局"能力**：Effie 大纲一键转思维导图且**导图编辑与大纲同步** `[S3]`；Ulysses 支持无限层级文档组 + 卡片写作 + 目标统计 `[S21]`。小说编辑器的竞争力在"结构化导航"，不在花哨样式。
8. **文件组织一律是"多层级文件夹 + 置顶/收藏 + 手动排序 + 回收站 + 全局搜索"**：Effie、Ulysses、iA Writer 高度一致 `[S3][S14][S21]`（推断：这是 Long-form 写作的行业标准解）。
9. **数据安全是一等功能，不是附加项**：Effie 有自动保存 + 历史版本（可恢复到原文稿或恢复成新文稿）`[S6]`；Ulysses 有 每小时/每天/每周 全库备份 + 文档级时间点还原 `[S21]`。Weaver 的自动保存应升级为"可回溯版本"。
10. **默认字体就是品牌的一部分**：iA Writer 只用自研字体（Mono/Duo/Quattro）并把字重、行高、字距随窗口宽度自动适配 `[S11][S12]`；Effie 默认字体选开源中文楷体「霞鹜文楷」以求"可读且优雅" `[S7]`——Weaver 应显式选定一款中文正文默认字体，而不是跟随系统。

## 二、Effie（事实 + 来源）

### 2.1 定位与它宣称解决的问题

- 官方 meta 描述：**"Effie 是思想家专用的写作软件。无论是严肃写作，随手记录，亦或是把逻辑完善成思维导图，Effie 都是您明智的选择。"** 官方关键词：*思维导图、大纲笔记、专注写作、极简、Markdown、脑图、灵感* `[S1]`。知识库标题为"**多平台云同步无干扰写作｜思维导图｜大纲笔记软件**" `[S2]`。
- 官网首页把价值拆成四块：**随心记录 / 沉浸创作 / 整理逻辑 / 轻松输出** `[S1]`：
  - 随心记录：手机、平板、电脑三端 + 自动云端同步 + 离线可用；"无需等待，快速记录，不错过每一次乍现的灵光"。
  - 沉浸创作：**"遵循最小阻力原则，没有任何多余的按钮"**；采用标记语法"两分钟即可上手，无需伸手够鼠标的多余动作"。
  - 整理逻辑：大纲功能"文字大纲自由混排"；**一键转换思维导图**，导图可增删/移动节点。
  - 轻松输出：导出 PDF、DOCX、Markdown、EffieSheet；另可导出多种风格的图片。
- 出身：由投资人/自媒体人**李自然**（Effie CEO）先自费数十万请团队做"专属写作软件"，后发现需求普遍，遂产品化，早期为 H5 版本、后期用原生代码重写 `[S3][S8]`。官方强调不做团队协作 `[S8]`。

### 2.2 它**明确放弃了什么**（本报告最看重的一问）

以下均来自 Effie 主创署名的设计哲学文章《Effie 的极简退让设计哲学》`[S3]`（内容整理自其 B 站发布会）：

| 放弃/收敛的东西 | 官方理由（原话/要点） |
|---|---|
| **没有品牌主色调** | "一个好软件，不需要有很强的存在感，甚至最好没有主色调。Effie 本身没有主色调。决定 Effie 主色调的是电脑系统的色调。所以，你的注意力不会被不必要的东西吸引走。" |
| **编辑器顶部没有工具栏/标题栏按钮** | "非常激进地删去了写作区的所有按钮"；标题栏"只有一个最基础的功能：窗口的拖动和位移"，随鼠标出现隐藏，**全屏时彻底隐藏**。 |
| **承认"做减法不等于简洁"** | "盲目地大量做减法导致的结果可能是简陋，而不是简洁。而简洁的背后，反而是复杂：我们需要通过大量的工作去达到简洁的效果。" |
| **只为新手保留一个按钮，且可关** | 大纲↔思维导图切换按钮"乍一看似乎违背了编辑区没有按钮的设计原则"，是"担心对新手不友好"才留，**可在设置中关闭**。 |
| **不做团队协作** | 官方表示（回应产品定位）不考虑加入团队协助功能 `[S8]`。 |
| **免费版留水印（代价）** | 免费用户可长期使用，但**左下角常驻"试用版"三字** `[S8]`——这是"免费+订阅"模式的取舍，对体验是负面的。 |

### 2.3 编辑体验与排版规格取向

- **纯文本标记 + 样式化呈现**：Effie 支持 Markdown 标记（多级标题、粗体、斜体、标注、删除线、评论、代码、代码块、引用、注释、分隔线等），并给出三种输入方式：**① 打字时直接敲标记符 ② 标记面板生成 ③ 选中后经面板设置** `[S6]`。官网称"采用标记语法…轻松锁定格式" `[S1]`。
- **可调的排版参数**（设置 · 常规）`[S5][S6]`：**外观/主题（多套配色）、字体、行高、段间距、首行缩进、字体大小（标题 / 正文）**；另有独立文章说明可在偏好设置中**调整"行宽"来改变写作区稿纸大小** `[S4]`（官方未公布行宽的默认数值）。
- **一键排版**：可一键清理多余空格/空行、在**中英文之间插入空格**、把**标点转为全角** `[S5][S6]`——面向中文写作的实用能力。
- **默认字体 =「霞鹜文楷」**：官方说明选用该开源字体，"兼有仿宋和楷体的特点，可读性高，也更为优雅"，图片导出的字体也同步更换 `[S7]`。
- **括号/引号自动补全**（默认开，可在"设置 > 高级 > 自动"关闭）`[S7]`。
- 未查到 Effie 公布的**具体字号/行高倍数默认值**（如其正文默认字号、行高倍率）——官网与知识库只呈现"可调"，未给数字。

### 2.4 沉浸/专注设计（界面如何"消失"）

- **侧栏可整体隐藏**：快捷键 **⌘+1** 或左上角按钮隐藏文稿管理区，只留写作区 `[S3]`。
- **左侧区域自动变暗**："即便你不隐藏文稿管理区，只要你在写作区进入了创作状态，左侧区域的亮度也会在不知不觉中黯淡下去。只有当你的鼠标重新移动到左侧，它才会瞬间恢复到原本的亮度。" `[S3]`
- **化鼠标操作为键盘输入**：`#`+空格=一级标题、`**`=粗体、`_`=斜体、`---`=分隔线、`-`+空格=进入大纲模式 `[S3]`；官方称"支付平均一分钟的学习成本后，手指完全不离键盘"。
- **打字机模式**：开启后"当前光标所在的那一行，始终保持在屏幕中央偏上的位置"，且**可把光标行滚动到你最舒适的位置**（不只居中）`[S9]`。
- **微交互增强确认感**：鼠标移动时阴影跟随光标、点击按钮颜色加深、文稿卡片悬停轻微放大 `[S3]`。

### 2.5 大纲与长文组织

- **大纲 ↔ 全文混排**：输入 `-`+空格进入大纲编辑；写完点按钮一键转思维导图，可改导图样式；**导图内可增删/拖动/改层级，改完回写作区，导图与大纲修改同步** `[S3]`。
- **目录（TOC）**：编辑区可"查看目录列表"并跳转 `[S6]`。
- **文件结构**（移动端/桌面端一致）`[S6]`：多层级文件夹（可移动/改层级/改名/改图标）、文件夹加锁、**排序方式可选（手动排序 / 按标题 / 按修改时间 / 按创建时间）**、回收站（可恢复/彻底删除）、**收藏夹与置顶**、全局搜索。
- **文稿详情**：创建时间、修改时间、**字数**、复制全文、导出；**历史版本**可查看并恢复（恢复到原文稿或恢复成新文稿）。
- **长篇小说的官方方法论** `[S10]`：以文件夹搭"小说骨架"（分卷/章节/人物/灵感分文件夹）→ 用大纲理结构、一键转导图看全局 → **开两个窗口边看大纲/人物表边写正文** → 把常查文档置顶/收藏 → 用版本记录替代"第三章-改2-最终版"式多份存档 → 导出 Word/PDF/纯文本交稿。文中点出长篇五大需求：**集中管理、层级清晰、快速定位、随时看全局、稳妥备份**。

### 2.6 多端策略

- 官方支持 **Windows / Mac / iOS / Android（含 iPad、Android 平板）** `[S1][S6][S10]`；**未查到 HarmonyOS 版本**（截至调研时）。
- **移动端保留了绝大部分能力**，交互换成触屏手势：长按卡片/左滑唤出操作菜单、卡片编辑态可多选批量操作、编辑区**键盘上方工具栏**（文稿内查找、撤销重做、标记面板、插链接/图片/表格、大纲左右缩进、AI 助手、一键排版、文稿详情、上下滚动把手快速定位、目录）。
- **系统小组件**（iOS/Android）：新建文稿 / 问 AI / 头脑风暴三个入口 `[S6]`——把"捕捉灵感"降到一次点击。
- 免费版 + Pro 订阅制：Pro 权益含 **10 台设备同步、更多主题配色、一键排版、表格、收藏夹、置顶、文件夹加锁、本地文件夹存储、更多自定义** 等 `[S6]`。（早期定价 18 元/月、168 元/年、998 元/十年，`[S8]`；当前以会员中心为准。）

## 三、同类对照：共性规律（5–8 条，每条含做法 / 依据 / 反例）

### 共性 1：把"排版自由"收敛为"少量可调 + 一套好默认"
- **做法**：默认只给一套精心调过的排版；把可调项限制在 字号 / 行高 / 段间距 / 首行缩进 / 行宽 这几个，而不是字体族、颜色、对齐全开放。
- **依据**：Effie 设置项恰为上述几项 `[S5][S6]`；iA Writer 只用自己的字体并让字重/行高/字距**自动**适配窗口宽度 `[S12]`；Ulysses 是"增强型纯文本 + 主题可下载" `[S21]`。
- **反例**：Typora 允许用户直接写 CSS 改一切主题 `[S18]`——自由度最高，代价是**配置成本与"折腾排版"的注意力消耗**，与"专注写作"相冲突（推断）。

### 共性 2：沉浸 = 界面自动退场，而非"专注模式开关"
- **做法**：一开始输入就隐藏菜单/窗口装饰/侧栏高亮，只留正文与字数；不要求用户主动进入某种模式。
- **依据**：iA Writer"一旦开始打字，菜单与窗口装饰即从视线中移除，你只剩下文本与字数" `[S14]`；Effie 写作时左侧栏自动调暗、鼠标移回恢复 `[S3]`；iA Writer 用 **Command Palette（⇧⌘P）** 把格式/导出/功能收进一个可被搜索的入口，减少常驻按钮 `[S13]`。
- **反例**：Notion 等"万能工作区"把 AI、评论、属性面板常驻在写作界面（推断）——适合协作，但**对沉浸写作是干扰源**。

### 共性 3：打字机模式 + 焦点淡出，是"低成本的专注机制"
- **做法**：光标行固定在屏幕中央偏上；或把非当前句/段淡出。
- **依据**：Effie 打字机模式且光标位置可自定义 `[S9]`；iA Writer Focus Mode"高亮当前句/段、其余轻微淡出"，浅色深色都可用 `[S14]`；Typora 有"对焦模式和打字机模式" `[S18]`；Ulysses 支持打字机模式 `[S21]`。
- **反例**：传统 word processor 与多数笔记软件**没有**这两者——正是因为它们默认"页面即成品"，用户要自己滚动找光标（推断）。

### 共性 4：用"行号 / 段落标记"制造稿纸的"微弱存在感"
- **做法**：在极简编辑区里保留一个弱存在元素（行号），既定位又能感知产出量。
- **依据**：Effie 明确写"行号的存在感不强，但一直陪伴在你旁边"，作用为①知道光标位置②看到写了多少行③让构图重心右移更稳定；并且"极简主义的精髓，不在乎你拿走了什么，而在乎你留下了什么" `[S3]`。
- **反例**：纯白无锚点的编辑器（如部分极简 app）在长文中容易"迷失在虚空"（推断，Effie 文中亦持此论）。

### 共性 5：Long-form 结构与文件组织高度同构
- **做法**：多层级文件夹 + 手动/按时间排序 + 置顶/收藏 + 回收站 + 全局搜索；且区分"书稿（大项目）"与"单篇文稿"。
- **依据**：Effie 全套具备 `[S6]`；Ulysses 支持无限层级"文档组-子文档组-文章列表-文章"、独立"项目"、标签与过滤器 `[S21]`；iA Writer 有文件库、收藏（星标）、紧凑库视图 `[S13]`。
- **反例**：以"标签/双链"为唯一组织手段的工具（如纯 Roam 式大纲笔记）在**线性小说**场景下不如文件夹直观（推断；Effie 主创亦批评纯导图工具"不支持写文章" `[S3]`）。

### 共性 6：导出是"写作的最后一公里"，被当作一等功能
- **做法**：多格式导出 + 合并导出 + 面向分享的图片导出。
- **依据**：Effie 导出 PDF/DOCX/Markdown/TXT/EffieSheet + 多风格图片 `[S1][S6]`；Ulysses 导出 MD/PDF/HTML/ePub/DOCX/纯文本/TextBundle + 多选合并 + 主题市场 + 一键发布 WordPress/Ghost/Medium `[S21]`；Bear 导出 PDF/HTML/DOCX/JPG `[S15]`。
- **反例**：只把"分享链接"当唯一出口的在线文档工具，作者**无法交出规范稿件**（推断）。

### 共性 7：数据安全 = 自动保存 + 可回溯版本 + 多端同步（缺一不可）
- **做法**：编辑即保存；保留历史版本可回滚；跨设备同步。
- **依据**：Effie 历史版本可恢复（原文稿/新文稿）、多端自动云同步 `[S6]`；Ulysses 每小时/天/周全库备份 + 文档级时间点还原 + 自动界面加密 `[S21]`；Typora 有"自动保存、版本控制和恢复" `[S18]`。
- **反例**：Ulysses 唯一被点名的槽点是 **iCloud 同步不稳** `[S21]`——说明"同步"若不可靠，反而成为负资产。

### 共性 8：Markdown（或轻标记）被选中，但"是否隐藏标记"存在明确分歧
- **做法**：几乎都采用 Markdown/轻标记作为**结构表达**（而非样式表达）；分歧在"标记符是否可见"。
- **依据**：iA Writer 坚持**不隐藏**标记符，只做样式化（加粗/斜体真样式、标题 `#` 外挂），并引用 Gruber 反对隐藏标记 `[S12]`；Ulysses 称"增强型纯文本" `[S21]`；Typora 则走**所见即所得**（实时预览、不显示源码）`[S17]`；Effie 支持 Markdown 标记但呈现为排版样式 `[S1][S6]`。
- **反例**：iA 文中的"jiggle（光标进出时显示/隐藏标记）"被其批评为"常导致文本被重排，令人不快、分心" `[S12]`——即"半隐藏"是最不讨好的折中。

## 四、排版规格汇总

### 4.2 可读性研究给出的通用数值（回答"每行 45–75 字符"是否成立）

- **Baymard Institute（基于大规模可用性测试）**：正文字数最优 **50–75 字符/行**；引 Emil Ruder《Typographie》为 **50–60 字符/行**；"最多到 75 字符可接受" `[S16]`。
- **WCAG 2.1 成功标准 1.4.8（视觉呈现）**：为可访问性，拉丁文字**每行 ≤80 字符**；**若为中文/日文/韩文，则每行 ≤40 字符** `[S16]`。
- **可访问性文本样式（同页给出）**：行高 **1.5 倍**字号、段间距 **2 em**（作为无障碍要求）`[S16]`。
- **关于常见说法"45–75 字符"**：该区间通常被追溯到 **Robert Bringhurst《The Elements of Typographic Style》**（常引"45–75 字，理想约 66 字"）。**本次调研未能抓到该书的可引用在线一手页面**（多个排版参考站如 practicaltypography.com 在本环境反复抓取失败），故**该具体数字"45–75"未能核实到原始出处**，请勿直接写入宣传或规范。可稳妥引用的是：**拉丁文 50–75（Baymard/Ruder）** 与 **中文 ≤40（WCAG）**。

**对 Weaver 的直接推论**（推断）：中文小说正文建议**每行 24–36 个汉字**（对应"中英混排下约 40 字符"上限），行高 **1.6–1.8**，段间距约 **0.5–1 行**；手机端因视口窄，行宽约束主要作用于平板/PC 端。

## 六、值得 Weaver 借鉴的做法（做法 / 为什么 / 在 Weaver 落地的大致形态）

> 按 Weaver 现有痛点（信息密度 vs 简洁、编辑区排版、分章组织、干扰控制、三端布局）排序。

1. **确立"退让"设计宪法：界面无品牌主色、内容优先**
   - *做法*：界面使用中性/系统色，不设强品牌色；除正文与必要弱元素外不常驻图标。
   - *为什么*：Effie 的无主色 + 毛玻璃让"注意力不被非文本元素牵走" `[S3]`，且能天然适配深浅色。
   - *落地形态*：把 `PcDesignTokens.ets` 收敛为"语义令牌 + 一个强调色"，强调色默认取自系统；编辑区背景/文字用语义变量，主题切换只改令牌不改布局。

2. **打字机模式 + 焦点淡出（不做"专注模式"按钮，做自动机制）**
   - *做法*：编辑时把光标行滚动到视口中央偏上；可选把非当前段落降不透明度；侧栏在输入时自动淡出。
   - *为什么*：多款工具验证有效且成本低 `[S9][S14]`；Effie 的"左侧自动变暗"正是自动化的专注 `[S3]`。
   - *落地形态*：在编辑区加"打字机"开关（默认开）；输入事件触发侧栏 `opacity` 过渡，点击侧栏恢复；不做全屏"专注模式"页面。

3. **把"稿纸感"落到行号上（直接支撑 Weaver 的稿纸主题）**
   - *做法*：编辑区左侧常驻细分隔线 + 行号，弱对比。
   - *为什么*：Effie 用行号同时解决"定位 / 产出感 / 构图稳定"三问题 `[S3]`，且是"留下了什么"的极简注脚。
   - *落地形态*：稿纸主题启用时显示行号列（`LazyForEach` 或按视口渲染当前行范围，避免长文卡顿）；行号颜色取"文本色 × 低透明度"，不抢正文。

4. **排版参数"少而可调"：字号 / 行高 / 段间距 / 首行缩进 / 行宽**
   - *做法*：只暴露这 5 项 + 主题，其余写死；给出中文优化的默认值。
   - *为什么*：Effie 的设置项就是这组 `[S5][S6]`；WCAG 给出 1.5 行高 / 中文 ≤40 字 `[S16]`。
   - *落地形态*：设置页新增"正文排版"分组；默认 **字号 17、行高 1.7、段间距 0.6 行、首行缩进 2 字符、正文最大宽度 ≈ 34 汉字**（平板/PC 生效，手机单列铺满）；行宽用"每行字数"而非 px 表达，便于跨端一致。

5. **选定并内置一款中文默认正文字体**
   - *做法*：默认字体显式选择，不随系统漂移。
   - *为什么*：Effie 用「霞鹜文楷」把"优雅"写进默认观感 `[S7]`；iA Writer 只用自己的字体 `[S11]`。
   - *落地形态*：评估在 ArkUI 中内置开源中文字体（注意字体包体积与首屏加载），默认提供"楷体（优雅）/ 黑体（清晰）"两档；字体作为令牌，主题可切换。

6. **"一键排版 / 整理"命令（面向中文）**
   - *做法*：清理多余空格与连续空行、中英文之间补空格、标点转全角、统一引号。
   - *为什么*：Effie 的"一键排版"是其 Pro 核心卖点之一 `[S5][S6]`；中文小说作者对"全角标点 / 中英混排空格"需求极强。
   - *落地形态*：编辑区命令"整理排版"（幂等、可撤销），纯文本规则放 `common` 层便于单测（对应现有重构计划的"纯逻辑层可测"）。

7. **章节大纲 ↔ 结构图双向同步（复用 Weaver 已有的人物关系图能力）**
   - *做法*：章节/场景的多层级列表可一键转为结构图；在图里增删/拖动节点后**回写大纲**。
   - *为什么*：Effie 的"大纲与导图混排 + 修改同步"是它区别于纯导图工具的核心 `[S3]`；长篇小说正需要"跳出细节看全局" `[S10]`。
   - *落地形态*：`features/editor` 的章节模型（book/chapter）+ 现有人物关系图组件共用一套"节点树 ↔ 视图"映射；图节点编辑走同一 Repository 写回。

8. **把"长篇小说工作流"做成产品的一等场景（而非泛笔记）**
   - *做法*：以"一部作品 = 一个项目文件夹"为默认心智模型，内置 分卷/章节、人物、设定、灵感 的推荐结构；支持**双窗对照**（左看大纲/人物，右写正文）。
   - *为什么*：长篇五大需求（集中管理/层级清晰/快速定位/看全局/稳妥备份）已被官方总结 `[S10]`；Weaver 的"素材库 + 章节"正好对齐。
   - *落地形态*：新建书籍时生成推荐文件夹骨架；PC/平板支持"编辑区 + 素材窗"并排（对应重构计划的 `PcEditorZone` 拆分：`EditorPane` / `MaterialPane`）。

9. **统一的"定位入口"：章节大纲 + 全文搜索合并为一个面板**
   - *做法*：一个可搜索入口，同时给出"文档结构（跳到任意章/场景）"和"全库/全文命中"结果。
   - *为什么*：iA Writer 8 把 Search 与 Outline 合并，因为写作时的问题其实是"我在哪 / 我说过什么 / 那个词在哪" `[S13]`。
   - *落地形态*：编辑区顶部/快捷键唤出"导航面板"，上半是章节树，下半是搜索结果，键盘上下选择回车跳转。

10. **自动保存升级为"可回溯版本" + 明示状态**
    - *做法*：定时/事件式快照，提供"恢复到原稿 / 另存为新稿"，并在界面弱提示"已保存/已存 X 分钟前"。
    - *为什么*：Effie 历史版本 `[S6]`、Ulysses 多层备份 `[S21]` 都把"数据安全"当一等功能；这是长文作者的信任基础。
    - *落地形态*：RDB 增 `chapter_revision` 表（按章节存快照 + 时间戳 + 触发原因），编辑区状态栏显示保存态；恢复提供两种入口（对齐 Effie）。

11. **字数/进度作为轻量激励（状态栏，不弹窗）**
    - *做法*：常驻显示本篇/本章字数与今日增量；可选目标。
    - *为什么*：iA Writer 的 on-page word count 与目标体系被其作为对抗分心的手段 `[S14]`；Ulysses 有目标 + 每日统计 `[S21]`；Effie 有字数统计与写作冲刺。
    - *落地形态*：编辑区右下角弱化显示"本章 1,234 字 · 今日 +567"；目标设置放设置页，不做打断式提醒。

12. **行内标记"样式化而非显示标记符"（对小说场景的折中）**
    - *做法*：支持少量行内语义（粗体/斜体/分隔/引用）但**默认不显示 `**` `#` 等符号**；高级用户可切"显示标记"。
    - *为什么*：iA Writer/Typora 的分歧说明"显示 vs 隐藏"各有拥趸 `[S12][S17]`；而小说作者关心的是叙事而非标记，**隐藏标记是更友好的默认**（推断）。
    - *落地形态*：编辑区用富文本/属性化文本实现粗斜体，键盘快捷键触发；把"显示标记"作为设置项留给技术型用户。

## 七、明确不该学的做法（含理由）

1. **不要为"简洁"把小说必需能力砍掉** —— Effie 自己警告"盲目做减法=简陋" `[S3]`。对 Weaver，**章节、大纲、人物/设定素材、版本记录是必需项**，不能为了"界面上干净"而删除功能；应做"默认不显、按需唤出"。
2. **不要照搬"必须登录账号 + 云端同步"的重度账户模型** —— Effie 需微信扫码登录、核心价值依赖自建云同步 `[S3][S8]`。Weaver 当前是端侧 RDB 本地优先；**应保持"无需账号即可写作"**，云端作为可选增强。
3. **不要用"免费版打水印"来变现** —— Effie 免费版左下角常驻"试用版" `[S8]`，直接损害"优雅"的品牌承诺。若需商业化，用"功能分级"而非"污染作品界面"。
4. **不要把 Markdown 标记符默认暴露给小说作者** —— 小说作者不需要看到 `#`/`**`/`-`；iA Writer 的"不隐藏"是为技术写作/可移植性服务的选择 `[S12]`，不该直接搬到小说编辑器（推断）。Weaver 应默认"样式化"，把"显示标记"留给少数高级用户。
5. **不要做"完全开放 CSS / 任意主题"** —— Typora 允许用户写 CSS 改一切 `[S18]`，自由度最高但把"折腾排版"的注意力成本转嫁给用户，也与 HarmonyOS ArkUI 的样式模型不契合（推断）。Weaver 应给**少量精选主题 + 受限令牌调整**。
6. **不要引入"块化万能工作区"（Notion 式 block/属性面板/AI 常驻）** —— 会同时抬高复杂度上限与运行时成本，背离"优雅简洁易用"的定位（推断；iA 亦批评 Word 式"格式按钮诱惑" `[S12]`）。
7. **不要让"导出/分享/订阅"占据写作主界面的一等位置** —— 这些是"最后一公里"功能，进命令面板或设置即可（对齐 iA Writer 的 Command Palette `[S13]`）。
8. **不要把同步做成"唯一真相源"而不稳** —— Ulysses 唯一被点名的槽点就是 iCloud 同步不稳 `[S21]`。Weaver 应以本地存储为真相源，同步失败不应阻塞写作。
