# 竞品调研：纯纯写作

> 调研对象：纯纯写作（Pure Writer，包名 `com.drakeet.purewriter`，开发者 Drakeet / 苏州小白迷雾科技）
> 调研目的：为 HarmonyOS 上的小说 / 长文本编辑器 Weaver 提炼可迁移的产品结构、交互模型、排版规格与信息架构做法。
> 调研时间：2026-09-29
> 说明：本文严格区分「有来源支撑的事实」与「我的推断」。第三节专门存放推断。
> 检索限制：本次调研期间 `WebSearch` 接口持续返回 429（Exa 免费额度耗尽），知乎 / 豆瓣 / 晋江原文页面对抓取返回 403 或编码异常，因此部分用户讨论只能依赖搜索引擎摘要。凡此类情况均在文中如实标注为「仅有搜索摘要」或「未找到可靠来源」。

## 一、结论摘要（每条一行，可直接执行）

1. 用「书 → 卷 → 文章」三级结构组织文稿，并明确「卷仅在手动排序下显示」——不要把分卷做成强绑定结构，否则最轻的随手记也会被强制分卷拖累。
2. 编辑器正文用**纯文本**，Markdown 作为**每篇可切换的开关**而非全局模式；不要做富文本，这是竞品用十年时间坚持的取舍。
3. 段首缩进固定为**两个全角空格**（中文环境），条目标题级缩进用标题字号控制；缩进不设"宽度"选项，避免用户调出手感不一致的排版。
4. 把「行距 / 段间距 / 左右边距 / 字号」四个变量收进一个抽屉式面板（"排版"面板），拖动即时预览，而不是各给一个设置页。
5. 打字机模式只做一件事：**高亮当前正在写的段落**（其余淡出），并且**滚动时自动隐藏顶栏**——不要同时叠加"居中光标""背景变暗"等多重效果。
6. 顶部栏采用「滚动即隐藏、输入即隐藏」的双触发规则，把"专注"做成默认行为而不是一个需要用户手动进入的模式。
7. 键盘上方常驻一条**快捷输入栏**：既可放常用词句 / 人名，也可放"撤销、重做、段首缩进、一键排版、查找、光标移动"这类动作按钮；点击长按可管理顺序。
8. 字数统计做成**悬浮**的，并支持三种口径（含/不含空格换行、排除标点），另外提供"选中文字单独计数"。
9. 章 / 文列表用**两行元信息**：字数 + 最后修改（相对时间或具体时间），不显示正文摘要（小说场景下摘要意义低且挤占竖屏宽度）。
10. 数据结构层就把"废纸篓"当成一等公民（可移回原书），把"重建卷 / 移回书"做成常规操作，而不是藏在开发者菜单里。
11. 一键排版（整理空行、段首缩进、中英文之间加空格、半角标点转全角）是中文长文场景的刚需，成本低、体感极强，优先级应高于"写作目标打卡"。
12. 导出把「合并成书」作为一等场景：一套内容导出多个格式（TXT / MD / DOCX / EPUB / 长图 / PDF），EPUB 自动生成目录与扉页。

## 二、事实与来源（逐条，附链接）

### 2.1 产品定位与总体结构

- **事实**：官方定位为"极速的纯文本编辑器"，核心诉求是"纯粹、有安全感、随时可写、不丢失内容"；图标是"时光机"，对应「历史记录」与「自动备份」。来源：官网 <https://writer.drakeet.com/>
- **事实**：官方首页描述的整理结构是**「书、卷、文章」三级**；书架支持单列 / 双列；书籍支持标签与组合筛选；文章与卷可拖动排序；卷可展开收起且**卷标题吸顶**；详细列表显示摘要、时间与字数；支持创建文章副本、文章与整卷跨书移动。来源：<https://writer.drakeet.com/>（功能一览 · 书籍与文章整理）
- **事实**：存在**废纸篓**，"误删的文章可以移回书中"（即废纸篓保留原书归属信息）。来源：<https://writer.drakeet.com/>（安心保存与找回）
- **事实**：**「大纲」功能已被移除**。官方 Q&A 原文解释：「因为大纲已经不再存在了，打开书籍列表的目的是提醒您，可以创建一本书作为大纲并且在第二编辑器中打开它以一边写作一边对照大纲。」来源：<https://writer.drakeet.com/wiki>
- **事实**：**分卷仅在「手动排序」下启用**；把排序改为非手动时，已建的卷不删除但会隐藏，恢复手动排序后重新出现。来源：<https://writer.drakeet.com/wiki>（为什么不能新建卷/原本建立的卷消失了？）
- **事实**：有**文章加锁**（指纹锁）能力；「文章加锁」在授权渠道的功能对比表中列为免费版即可用。来源：<https://lizhi.shop/products/pure-writer-drakeet>；<https://www.appinn.com/pure-writer/>（"指纹加锁"列入官方关键词）
- **事实**：有**只读模式**（近似阅读模式），官方描述其价值是"随意滑动、翻阅你的文章而无需担心误触带来的文字误删"；高级只读模式的交互是：光标不可见时需双击编辑器才能落下光标，光标可见时单击即可。来源：<https://writer.drakeet.com/wiki>（什么是只读模式 / 如何打开只读模式）
- **事实**：右下角 `⊕` 是"插入位置 + 只读模式"等操作的统一入口（长按可弹出列表，插入位置支持"列表底部 / 卷末尾 / 当前文章后"）。来源：<https://writer.drakeet.com/wiki>（如何在其他位置插入新文章）
- **事实**：素材 / 灵感侧不是独立模块，而是一个叫**「时光机」**的页面，形态"类似聊天界面"，进入方式是从编辑界面**向左滑**；已支持搜索。来源：少数派评测 <https://sspai.com/post/51173>；更新日志"时光机支持搜索了" 见 <https://www.mfunz.com/soft/3971.html>
- **事实**：有**双编辑器**（"正文与参考资料各占一处，左右切换"），官方建议把"大纲"另建一本书放进第二编辑器对照写作。来源：<https://writer.drakeet.com/>；<https://writer.drakeet.com/wiki>
- **推断标注**：本次检索**未找到任何"人物关系图""世界观卡片""人物档案库"类的功能证据**（官网功能一览、用户手册全文、第三方介绍均无此项）→ 该产品**基本可以认定没有**结构化的设定管理模块（详见第三节）。

### 2.2 编辑器本体

- **事实**：纯文本编辑器；官方明确拒绝富文本与图片：「纯纯写作是一个纯文本编辑器……加粗文字或插入图片等功能属于富文本的范畴……**很抱歉，纯纯写作从一开始就没有计划支持富文本，以后也不会计划做相关支持。如果支持富文本或图片，会使得编辑器的复杂度大幅上升，复杂就意味着容易出错且难以做到完美，只有专注才能做到极致。**」来源：<https://writer.drakeet.com/wiki>（可以在纯纯写作中加粗文字/插入图片吗？）
- **事实**：Markdown 是**逐篇可切换**的开关："每篇文章都能在纯文本与 Markdown 之间切换"；顶栏 `TXT` / `M↓` 按钮切换；Markdown 模式下自动停止段首缩进。来源：<https://writer.drakeet.com/>；<https://writer.drakeet.com/wiki>
- **事实**：Markdown 遵循 CommonMark 规范，支持部分 HTML 标签、LaTeX 行内/行间公式、表格、选择框、脚注（脚注会跳浏览器，官方自评"实用性较差"）。来源：<https://writer.drakeet.com/wiki>
- **事实**：**拒绝 Markdown 实时渲染**：「纯纯写作曾经尝试过支持 Markdown 实时渲染，但是测试后发现，现今移动设备的性能尚不能满足预期，因此……将不会提供这个功能。」来源：<https://writer.drakeet.com/wiki>
- **事实**：段首缩进实现是**两个全角空格（U+3000）**；并且缩进规则**随语言变化**：英文环境 4 个半角空格，日 / 韩语环境 1 个全角空格。来源：<https://writer.drakeet.com/wiki>（缩进宽度出现问题是怎么回事？）
- **事实**：**不支持两端对齐**，原因是"Android 的原生 TextView 无法实现文本的两端对齐，只有 WebView 可以做到，但 WebView 的性能表现很差，因此纯纯写作选择了使用 TextView。性能与两端对齐，二者不可得兼"，且官方明确表示"无法修复安卓系统的问题"。来源：<https://writer.drakeet.com/wiki>
- **事实**：**不支持修改字体颜色**（仅支持在主题中强制切换黑白字体），并明确"并无支持相关功能的计划"。来源：<https://writer.drakeet.com/wiki>
- **事实**：可调排版项：字号（标题与正文分别设）、行间距、段间距、左右边距、文字透明度；入口统一在顶栏「更多」→「**行间距|左右边距**」面板。来源：<https://writer.drakeet.com/wiki>（关于横屏下的使用 / 如何使文字变为半透明 / 如何调整文字的左右边距 / 如何调整行段间距）
- **事实**：未找到任何**具体数值**（如默认字号 px/sp、默认行距倍数、最大阅读宽度 px）；官方只描述为"行距、边距、段间距与字号自由调整，拖动时即时预览""宽屏与横屏下正文保持舒适的阅读列宽"。多张第三方截图（如 <https://www.mfunz.com/soft/3971.html>）显示正文约占屏宽 80% 上下、两侧留白明显，但**这属于截图观察，不是官方规格**。→ **未找到可靠来源给出具体排版数值。**
- **事实**：默认字体是**霞鹜文楷 GB**（内建，随版本更新），可关闭以使用系统字体，或导入自定义 TTF / OTF。来源：<https://writer.drakeet.com/wiki>（为什么默认字体不是系统字体？/ 纯纯写作默认字体会更新吗？）
- **事实**：超长文章会**自动临时禁用段间距**以保证流畅（阈值可在"少数派选项"调整）。来源：<https://writer.drakeet.com/wiki>（关于超长文章中临时禁用段间距）
- **事实**：单章"无限字数"，但**建议编辑时单章控制在两万以下**（部分设备超过一万编辑会有轻微卡顿）；官方称浏览千万字不卡顿。来源：<https://writer.drakeet.com/wiki>（单个篇章有字数限制吗？）

### 2.3 专注写作

- **事实**：有**打字机模式**——"只会高亮显示当前正在编辑的一段文字"，官方还提到它"可以在一定程度上躲过来自身后的窥视者"。开启 / 关闭入口都在顶栏「更多」菜单。来源：<https://writer.drakeet.com/wiki>（打字机模式是什么？/ 码字的时候只有一段/一行文字高亮是怎么回事？）
- **事实**：打字机模式在滚动时**自动隐藏顶栏**（官网功能一览：专注写作 · "打字机模式，滚动时自动隐藏顶栏"）。iOS 版描述为"打字机模式聚焦当前段落，其余段落柔和淡去"。来源：<https://writer.drakeet.com/>
- **事实**：有**沉浸模式**（iOS）："开始输入时自动收起顶栏"。来源：<https://writer.drakeet.com/>
- **事实**：另有**状态栏专注模式**——用于"隐藏状态栏的大多数通知图标"，入口在「行间距|左右边距」菜单中段间距开关右侧；小米 / 红米因 MIUI 限制默认隐藏该入口。来源：<https://writer.drakeet.com/wiki>（状态栏专注模式的简介与问题）
- **事实**：屏幕常亮；可用手指下滑快捷栏收起软键盘；重新打开时恢复此前的滚动位置。来源：<https://writer.drakeet.com/>；<https://www.appinn.com/pure-writer/>
- **推断标注**：官方未使用"沉浸模式（Android）"这一说法，Android 侧的"隐藏顶栏"主要通过打字机模式 + 状态栏专注模式组合实现（详见第三节）。

### 2.4 写作辅助（含刻意克制之处）

- **事实**：**悬浮字数统计**：支持"选中文字单独计数""查看光标前字数"；计数口径可选（是否计入标点、空格与换行）；英文环境可切换为"视一个单词为一个计数"。来源：<https://writer.drakeet.com/>；<https://writer.drakeet.com/wiki>
- **事实**：字数统计在中文环境下有**三种模式**：不含空格与换行 / 包含所有符号和文字 / 排除所有标点符号、空格和换行符。来源：<https://writer.drakeet.com/wiki>
- **事实**：有**「每日统计」**功能（更新日志条目）。来源：西西软件园更新日志摘要 <https://www.cr173.com/>（经 360 搜索摘要获得，原文页未直接打开，标注为**仅有搜索摘要**）
- **事实**：少数派作者评测中提到一个"时刻变动的数字，提醒我我在不断靠近今天的**目标数字**……这是传玉格外喜欢的功能……尤其是在执行千字文计划的时候"。来源：<https://sspai.com/> 上的第三方评测《纯纯写作——专注于安卓端写作的 App》（作者"传玉制作"），**经 360 搜索摘要获得**，原文页未直接打开。→ 说明存在"当日目标 / 当日进度"类显示，但具体形态（是否可设目标值、是否含连续天数）**未找到官方文档确认**。
- **事实**：**未找到**"码字时长统计""写作冲刺计时""连续打卡""章节字数分布图"等功能的任何来源。官网功能一览、用户手册全文均无对应条目 → 可判定为**不做**（见第三节推断）。
- **事实**：光标前字数显示格式为 `1/1000`（表示全文 1000 字、光标位于第一个字之后）。来源：官方更新日志 <https://m.app.mi.com/details?id=com.drakeet.purewriter>

### 2.5 素材与设定管理

- **事实**：没有独立的"人物 / 世界观"页面；实际做法是把素材**丢进「时光机」**（类聊天流），左右滑动在"素材"与"编辑"之间来回；快捷输入栏也被用来放人名。来源：<https://sspai.com/post/51173>（"我将所有文字素材全部都扔到了时光机"）；<https://writer.drakeet.com/>（快捷输入栏"常用词句、人物名字与符号一键输入"）
- **事实**：评测者在 2018 年就建议"加上添加图片（方便查看人物关系之类）和搜索时光机的功能"。**后续更新日志显示"时光机支持搜索了"（搜索已实现），但图片 / 人物关系图未见于任何更新日志**。来源：<https://sspai.com/post/51173>；<https://www.mfunz.com/soft/3971.html>
- **事实**：官方对"没有大纲"给出的替代方案是"另建一本书当大纲，用第二编辑器对照"。来源：<https://writer.drakeet.com/wiki>

### 2.6 备份、同步与导出

- **事实**：**本地自动备份不可关闭**（官方理由：否则无法保证文本安全）；自动备份维持 25 份最新，旧的自动删除；手动点「立即备份」产生的备份永久保留。路径分别为 `Documents/PureWriter/Backups`（手动）与 `Documents/PureWriter/Backups/Auto`（自动）。备份包扩展名 `.pwb`。来源：<https://writer.drakeet.com/backups>；<https://writer.drakeet.com/wiki>
- **事实**：官方公开的本地"防丢失防线"共 6～7 条，包括：①文章一变即自动保存，保存失败立即警告；②**每 2 秒**主动校验文章是否正常入库且与数据库一致；③保存失败时无法真正退出应用（按退出等于按 Home）；④每次切后台 / 退出且内容有变化就整库自动备份，恢复前再自动备份"恢复前的内容"；⑤每篇都有历史记录、撤销与重做；⑥废纸篓；⑦WebDAV 云备份。来源：<https://writer.drakeet.com/protections>；<https://sspai.com/post/51173>
- **事实**：**历史记录**支持与当前版本做差异对照、预览后再恢复；另有"写作缓存"作为历史记录之外的第二道找回手段。来源：<https://writer.drakeet.com/>
- **事实**：**不做全自动云同步**，官方理由原文："完全自动化的云同步必然要伴随着同步冲突、同步失败、覆盖丢失等问题，这基本上是无解的……想想最经得起考验的 git，都需要很多程序员参手和繁琐解决各种冲突"。实际提供手动同步与半自动同步（半自动同步的触发条件是**内容有变更且收起键盘**，两次同步间隔**至少 4 秒**）。来源：<https://writer.drakeet.com/wiki>（纯纯写作为什么没有全自动同步？/ 纯纯写作支持自动同步吗？）
- **事实**：云备份 / 同步支持：WebDAV（文档中主要推荐坚果云，也提到 TeraCloud、Yandex Disk）、Dropbox、Google Drive（**只能备份、不能云读写**）、OneDrive、阿里云盘。**不支持百度网盘**（因不开放 API）。**不支持同时接两个云盘**，官方理由是会造成两个云端备份不一致、误恢复。来源：<https://writer.drakeet.com/wiki>（关于纯纯写作支持的云备份方式 / 可以同时备份到两个云盘吗？）
- **事实**：备份包**不加密**，官方理由："因为这样会严重影响打开与编辑文章的速度……如果有人想要窃取你的文章，并且能从你的手机本机/云盘供应商那里获取到备份包，那么对于此人来说加密也是形同虚设的。"**文章只保存在本机备份文件夹与用户自己的网盘两处**，服务端不存用户内容；云备份账号与 Pro 激活账号**互相独立**。来源：<https://writer.drakeet.com/wiki>（使用纯纯写作有文章被窃取的风险吗？/ 关于云备份）

### 2.10 「简洁」的具体取舍（官方原话，最有价值的一节）

以下全部来自官方用户手册 <https://writer.drakeet.com/wiki> 与官网 <https://writer.drakeet.com/>，是作者**主动解释过"为什么不做"**的清单：

| --- | --- |

| 字体颜色自定义 | "目前纯纯写作只支持……强制切换黑白字体，不可以修改字体颜色，也并无支持相关功能的计划。" |
| 两端对齐 | TextView 与 WebView 的性能取舍，"性能与两端对齐，二者不可得兼"。 |
| 自定义导出长图的背景 | 长文 + 固定长背景图 → 拉伸难看、平铺体积爆炸。 |

**藏起来而不是删掉的做法（同一份手册）**
- 一批"更少人选择或开发者不推荐打开"的选项被集中放进「**少数派选项**」：关闭顺滑光标、关闭标题居中、隐藏快捷输入栏、改动超长文章阈值等。入口不在常规设置里显眼位置。
- 「**平板设定项及指引**」把大屏相关开关打包在顶栏右侧一个入口内。
- 右下角 `⊕` 统一收纳"在其他位置插入新文章""只读模式"等低频动作。
- 「更多」菜单里收纳了打字机模式、历史记录、查找替换、行间距|左右边距、重做等。

## 三、推断与不确定（明确标注是推断）

1. **【推断】没有结构化的设定管理（人物 / 世界观 / 关系图）是该产品的主动选择，而非能力缺失。** 依据：官方对富文本的拒绝理由（"复杂就意味着容易出错"）、对"大纲已移除"的处理方式（改为建一本书 + 第二编辑器），以及"拒绝所有设置项可自定义"的同一套设计哲学。它把"设定"降级为"普通文本内容"，用通用容器（书、时光机、第二编辑器）承载。
2. **【推断】Android 端没有统一的"沉浸模式"开关，"专注"是多个开关的组合**：打字机模式（高亮当前段 + 滚动隐藏顶栏）+ 状态栏专注模式（隐藏通知图标）+ 屏幕常亮。官网只在 iOS 版明确写了"沉浸模式：开始输入时自动收起顶栏"，Android 版功能一览中该条带 iOS 标记。
3. **【不确定】"每日统计 / 今日目标"的确切形态。** 更新日志条目与第三方评测都提到"每日统计""靠近今天的目标数字"，但官网功能一览与用户手册正文都没有它的说明页，无法确认是否支持自定义目标值、是否含连续天数、数据保留多久。
4. **【不确定】是否有 AI 功能。** 检索到名为"纯纯写作 AI"的第三方产品介绍页（<https://www.xmdass.com/>），但**与 drakeet 的纯纯写作无任何关联证据**，属于同名蹭词，不应视为该产品的功能。
5. **【不确定】第三方下载站的"更新日志 / 功能介绍"存在串号污染。** 例如某些 360 摘要中出现"多人在线拼字，设定目标谁先达成""敏感词功能"字样，但官网与官方手册均无此功能，判断为**下载站把多个 App 的特性混在一起**，不可采信。凡以 `cr173 / kkx / itmop / 25pp / 3dmgame` 等下载站为唯一来源的功能描述，本文均已标注。
6. **【推断】"更新频繁 + 强制弹窗催更"是它长期口碑里最真实的痛点**，且与"开发者勤快"是同一枚硬币。对一个"优雅简洁"为卖点的编辑器来说，任何打断写作流的模态提示都是设计缺陷——这条对 Weaver 有直接警示意义。
7. **【推断】排版的具体数值（字号 / 行距 / 列宽）在这个产品里是"用户自己拖出来的"，官方不给默认规格。** 未找到任何数值，这本身就是一种设计立场：给可调范围 + 即时预览，而不是给一套权威参数。
8. **【不确定】价格与授权**：少数派 2018 年的软件页标注售价 ¥16（<https://sspai.com/post/51173> 文末），当前实际价格随渠道与活动变化（官方称"每年的双十一都会有降价活动"），**不应把 ¥16 当作现价**。
9. **【推断】它的"废纸篓"是产品级设计而非技术兜底**：废纸篓保留原书归属（"误删的文章可以移回书中"）、有独立的加载与性能问题说明，说明它是被当成一级信息架构来对待的。但同一份手册也暴露了它的实现缺陷（无全选 / 清空，文章过多会假死）。
10. **【不确定】检索本身受限**：知乎、豆瓣、酷安、Google Play、bilibili 的正文页均未能成功抓取（403 / 编码 / 网络），用户差评的样本主要来自搜索引擎摘要与官方自曝。因此"差评分布"这一节的**代表性弱于"功能事实"**，需要谨慎引用。

## 四、值得 Weaver 借鉴的做法（做法 / 为什么 / 落地形态）

### 4.1 信息架构

**A. 三级结构「书 → 卷 → 文章」，且卷是"手动排序时才出现"的可选层**
- 为什么：小说作者需要"卷"来分组章节，但随手记、灵感、素材不需要。纯纯写作让卷依附于"手动排序"这一模式，避免了给所有用户强加一层结构。
- 落地形态：文稿列表默认是扁平的「书 → 章」两级；当用户切到"手动排序"模式时，才出现"新建卷 / 拖动成卷"的能力，卷标题在列表滚动时吸顶。数据模型里卷是一个可选字段，不是必填层级。

**B. 废纸篓作为一等公民，且保留"原书"归属**
- 为什么：小说写作中"删错了整章"是致命事故；纯纯写作的废纸篓支持"移回书中"，把误删变成可逆操作。
- 落地形态：文稿列表侧栏固定一个"废纸篓"入口（与书籍列表平级，不藏在设置里）；每篇被删文章记录 `originalBookId`，废纸篓条目提供"移回原书"一键操作；废纸篓列表**惰性加载**（避免纯纯写作踩过的"废纸篓文章过多导致界面假死"的坑），并给出"清空"与"多选"（纯纯写作没有，这是它的缺陷）。

**C. 不做"人物关系图"式的结构化设定库，先用通用容器顶上**
- 为什么：这是纯纯写作用十年给出的答案——把设定降级为普通文本，用"书 + 第二编辑器 + 素材流"承载，复杂度大幅下降。
- 落地形态：Weaver 计划中的"素材库（人物 / 世界观 / 灵感）"建议这样切分优先级：一期只做**素材条目列表 + 正文双栏对照**（对应"双编辑器"），把每条素材当成一篇普通短文稿，复用编辑器本身；"人物关系图"放到后面，且必须能"不打开也不影响写作"。切忌在首版就把关系图做成核心界面。

**D. 用"大纲"这件事别做成独立子系统**
- 为什么：纯纯写作曾经有「大纲」，后来**直接移除了**，理由是"可以创建一本书作为大纲，在第二编辑器中打开对照"。
- 落地形态：把"大纲"实现为"一篇普通文稿 + 在右侧第二栏并排显示"，而不是专门的大纲数据结构和专属页面。用户既能写大纲，也能写章节细纲，还能贴参考资料，一套机制通吃。

### 4.2 编辑器与排版

**E. 正文 = 纯文本，Markdown 是逐篇可切换的开关**
- 为什么：纯文本让自动保存、历史记录、跨端同步、导出全部变简单；把 Markdown 做成"每篇可选"，就同时照顾了写小说的（不需要标记）和写自媒体的（需要标记）。
- 落地形态：文稿实体上存纯文本；每个文稿一个 `format: plain | markdown` 字段；顶栏一个小按钮 `TXT / M↓` 切换；Markdown 模式下自动关闭段首缩进（纯纯写作的做法），因为 Markdown 的列表 / 标题语法与全角缩进会互相打架。

**F. 段首缩进 = 两个全角空格，不做"缩进宽度"选项**
- 为什么：中文排版的事实标准就是两个全角空格；一旦开放宽度设置，用户设成 1.5 个空格后反而会抱怨"排版不对"，且字体把 U+3000 做坏时会出现只有半个字宽的诡异缩进（纯纯写作专门有一节 Q&A 解释这个坑）。
- 落地形态：缩进用两个 U+3000 直接写入文本（而不是靠渲染参数），保证导出 TXT / 复制到别处仍然是缩进状态；设置里只给"段首缩进 开 / 关"，不给宽度。

**G. "排版抽屉"：行距 / 段间距 / 左右边距 / 字号四项集中在一个面板，拖动即时预览**
- 为什么：这四项是同一个心智动作（"让正文看起来舒服"）。纯纯写作把它们统一在「行间距|左右边距」一个入口里，避免了设置页里散落四个开关。
- 落地形态：`排版` 面板（底部抽屉或右侧浮层）内含四个滑杆 + 一个实时预览的正文区域；数值改完即生效、无需"确定"；每个滑杆附一个"恢复默认"。

**H. 不做富文本、不在编辑器里塞图片**
- 为什么：这是竞品用"以后也不会计划做相关支持"级别的措辞给出的判断。富文本会让"自动保存 + 历史记录 diff + 导出 TXT + 纯文本跨端"这四件事全部复杂化。
- 落地形态：正文区只渲染文本 + 选区高亮 + 当前段高亮；图片、表格一律走 Markdown 语法或导出环节（长图 / HTML），编辑区里不出现内嵌图片块。

**I. 明确的排版取舍要写进文档并坚持**
- 为什么：纯纯写作对"不支持两端对齐""不能改字体颜色"给出技术 + 设计理由并拒绝修复，反而被用户接受为"这个 App 有主见"。
- 落地形态：在 Weaver 的交互文档里显式列出"我们不做的 10 件事及理由"（对应本文第二节那张表），作为后续需求评审的挡箭牌。

### 4.3 专注与干扰控制

**J. 打字机模式只做一件事：高亮当前段落，其余淡出**
- 为什么：竞品的打字机模式是"只高亮当前正在编辑的一段文字"，没有做居中光标、没有做背景变暗、没有做逐字上移动画。功能越单一，越不容易出错、越不容易让人反感。
- 落地形态：一个布尔设置；开启后当前段落不透明、其余段落给一个固定透明度（而非模糊）；实现上靠文本选中/装饰而非重排布局，以保证长文滚动性能。

**K. 顶栏"滚动即隐藏、输入即隐藏"**
- 为什么：纯纯写作把"隐藏顶栏"绑定到打字机模式和滚动行为上，专注成了默认动作，而不需要用户主动进入某个"专注模式"页面。这是"简洁"最容易被低估的一招。
- 落地形态：编辑区滚动时顶栏自动收起（留一条细边或完全隐去），停止滚动或向上回滚一小段后淡入；进入输入状态立即收起；顶部采用 `Swiper`/`bindContentCover` 之外的轻量动画实现，避免长文掉帧。

**L. 冒号：把"催更 / 提示 / 错误提示"清出写作界面**
- 为什么：这是竞品**最真实的差评来源**——不更新就反复弹窗；官方也承认过"避免底部的黑色错误提示干扰用户写作"是特意修过的。
- 落地形态：编辑器全屏状态下**禁止任何模态弹窗**；更新提示只在文稿列表页展示且可"本周不再提醒"；错误提示改为非阻塞的顶部细条 + 自动消失，并在有未保存内容时永不打断输入。

### 4.4 写作辅助

**M. 悬浮字数统计 + 三种口径 + 选中单独计数**
- 为什么：中文写作者对字数极度敏感（稿费、平台要求），且"含不含标点"会带来数百字差异。纯纯写作把这做成一个悬浮组件而非状态栏文字，既不占版面又随时可见。
- 落地形态：编辑区右下角一个低对比度的小字数胶囊（点击展开详情）；口径三选一（不含空格换行 / 全含 / 排除标点空格换行）；选中文字时胶囊切换为"选中 N 字"；光标在文中时显示 `光标前字数/全文`。

**N. 一键排版（整理空行、段首缩进、中英文间距、半角转全角）**
- 为什么：手机写作最容易积攒的就是空行和半角标点；这是"低成本高体感"的功能，评测者称其为"手机写作的福音"。
- 落地形态：编辑区工具条上一个"排版"按钮，弹出勾选项（整理空行 / 段首缩进 / 中英文之间加空格 / 半角标点转全角），执行前给出"将修改 N 处"的预估并支持撤销。

**O. 每日统计要克制：显示进度，不做打卡游戏**
- 为什么：竞品有的"靠近今天的目标数字"是激励，但**没有**码字时长统计、连续打卡、勋章、排行榜——这正是"克制"的体现。
- 落地形态：一期只做"今日新增字数"一个数字（进入应用时在列表页顶部轻量展示）；不做连续天数、不做成就、不做分享；写作目标如果需要，做成可选的"今日目标字数"，仅在字数胶囊里显示一个进度环。

**P. 章 / 文列表用两行元信息，不用摘要**
- 为什么：纯纯写作在"详细列表"里显示摘要 + 时间 + 字数（三种都显示），但小说章节的第一行常常就是重复的"第 X 章"标题或对话引号，摘要信息量极低却占掉竖屏最宝贵的一行。
- 落地形态：列表项 = 标题（一行）+ "1,234 字 · 3 分钟前"（第二行小字）；字数与时间可分列左右两端；摘要只在用户长按或详情页里展示。

### 4.5 数据安全与导出（Weaver 最容易做出差异化的地方）

**Q. "自动保存永不关闭 + 定期一致性校验 + 保存失败时不急着退出"这套组合拳值得整体照搬**
- 为什么：竞品公开的防线里，最值得学的是第 2 和第 3 条——**每 2 秒校验内容是否真的落库**、"保存失败时按退出等于按 Home"。这两条把"我写了但没存上"的概率压到极低，而它恰恰是写作类应用最致命的失败模式。
- 落地形态：编辑器有变更即写本地 KV / 数据库；一个定时器（≥2 s）校验内存中的正文与持久化内容是否一致，不一致则重写并记录告警；保存失败时拦截返回键并给出显式提示；每次切后台再整库快照一次。

**R. 历史记录要给"版本对照 + 预览后再恢复"**
- 为什么：只给一个"恢复"按钮会让人不敢点。纯纯写作的旧稿与当前版本差异对照 + 预览，把恢复变成安全操作。
- 落地形态：历史记录列表项显示时间 + 字数差；进入详情为左右 / 上下对照视图；恢复按钮下方注明"恢复前会先自动备份当前版本"。

**S. 导出：先做 TXT / Markdown / HTML / JSON 备份，再做"合并成书"**
- 为什么：竞品的导出清单里，**"合并成书导出"**（EPUB 自动目录与扉页、Word 保留大纲层级）是小说作者最认的一条龙能力；但它的实现依赖"书 / 卷 / 章"三级结构已经稳定。
- 落地形态（结合 Weaver 已规划格式）：一期做单篇导出 TXT / MD / HTML + 全书 JSON 备份（保证数据可带走）；二期做"合并成书"导出——按 书 → 卷 → 章 生成带目录的单一文档（HTML 目录锚点 / EPUB 章节），并在导出对话框里显示"将导出 3 卷 42 章"。

**T. 备份策略：自动备份不可关、保留固定份数、手动备份永久**
- 为什么：纯纯写作的"自动 25 份 + 手动永久"是一个被验证过的平衡点，既防住"昨天写坏今天想回滚"，也防住用户关掉备份后丢数据。
- 落地形态：自动快照保留最近 N 份（滚动删除，N 取 20～30）；"立即备份"生成的文件永不自动删除；恢复前自动为当前状态再存一份"恢复前"快照；在设置页显示备份保护状态（最近一次备份时间 + 备份位置）。

**U. 云同步：宁可半自动，也不要制造静默冲突**
- 为什么：竞品拒绝全自动同步的理由（冲突、失败、覆盖丢失"基本上无解"）对 HarmonyOS 多端场景同样成立。它的半自动方案是"内容有变更且收起键盘时同步，间隔 ≥ 4 秒"——这个触发条件对手机写作非常贴切。
- 落地形态：手机 / 平板 / PC 三端同步先做"手动同步按钮 + 离开编辑页时同步"；冲突时**绝不静默覆盖**，而是保留两份并提示用户选择；同屏显示"上次同步时间 / 是否落后"。

### 4.6 三端与外观

**V. 大屏策略：功能不减，只加"平板设定项"**
- 为什么：竞品在平板上没有砍功能，而是开了一个"平板设定项及指引"入口，把大屏特有开关（如垂直居中编辑、栏宽）打包；同时在窄屏横屏上坦承"兼容不友好"，直接建议用平板或电脑。
- 落地形态：ArkUI 断点（sm / md / lg）驱动同一套布局：手机 = 单栏 + 抽屉式文稿列表；平板 = 双栏（列表 + 编辑）；PC = 双栏 + 侧栏（列表 / 素材 / 大纲三选一）。**功能集三端一致**，只调整布局与栏宽；窄屏横屏给一句"建议使用平板或电脑获得更好体验"的温和提示而不是硬性限制。

**W. 稿纸只做"背景 + 横线"两层，且用"历史用过"降低选择成本**
- 为什么：竞品的稿纸选项是 纯色 / 内置风景图 / 自定义照片 + 横线（实虚、浓淡、位置），并且会记忆"曾经用过"（只留 2 张自定义）。选项有限但覆盖了需求，避免变成一个主题商店。
- 落地形态：主题 = 背景（纯色 / 渐变 / 内置图 / 用户图）+ 横线（关 / 实线 / 虚线 + 不透明度）+ 文字色（浅色主题下黑、深色主题下白，**不给任意色**）；用户自选图自动进入"最近使用"。

**X. 深色模式要主动防御系统强制反色**
- 为什么：竞品明确承认国产 ROM 的"强制深色"会导致异常反色且无法规避——这是中文 Android 生态的通用坑，HarmonyOS 上同样要提前处理。
- 落地形态：主题颜色全部由应用自己渲染（不依赖系统自动反色）；检测到系统深色切换时由应用自行切换主题；对背景图与横线也提供深色变体，避免出现"白底黑字被反成黑底黑字"。

## 五、明确不该学的做法（含理由）

1. **不要学它的"更新催更弹窗"**。这是被用户明确吐槽过的行为（"每分钟给你跳一个弹窗"），对一个以"不打断写作"为卖点的编辑器来说是自毁口碑。Weaver 应把更新提示限制在文稿列表页且可长期静默。
2. **不要学它的桌面端"投屏式同步"**。桌面版 1.9 走局域网实时同步、开发者自己反复警告"可能完全不能用"，并因此被用户要求退款。三端如果不做同一套同步协议，宁可不做，也不要用一个体验极差、需要用户"手机别被系统杀掉后台"的方案占位。
3. **不要学它把常用功能放进付费墙**。查找替换、导出、自定义稿纸被划入高级版，虽然官方解释了动机（希望用户为核心体验买单），但从产品体验角度，这些是长文写作的基础设施，做成付费项容易被理解成"功能阉割"。Weaver 若要商业化，更适合在"云存储容量 / 主题包 / 高级统计"这类非核心能力上做区分。
4. **不要学它把"大纲"先做后删**。竞品曾经有「大纲」，后来直接移除并要求用户"另建一本书当大纲"。这种功能级的删除会伤害早期的重度用户。宁可一期就不做大纲子系统（用"第二栏并排显示另一篇文稿"这种通用能力顶替），也不要先上线一个专属大纲再回退。
5. **不要学它"没有人物 / 设定结构"就把素材全塞进一个聊天流**。时光机在单人素材堆积时很爽，但它没有分类、没有字段、检索能力弱（评价者在 2018 年就要求加图片和搜索），对"人物档案 / 世界观条目"这类需要反复查阅的结构化设定，纯文本聊天流会很快失控。Weaver 的素材库应至少有"分类 + 标题 + 正文"三层，而不是一条时间线。
6. **不要学它"什么都不让配"也不要学"什么都让配"，要分清哪些是审美、哪些是工作流**。它的"拒绝飞机仪表盘式设置页"是对的，但它连字体颜色都拒绝开放（因为怕"杀马特风格"）——理由是审美而非功能。Weaver 的判据应该是：**影响写作正确性的（缩进、计数口径、保存）不给或少给选项；纯粹影响观感的（字号、行距、边距、主题色）给足选项并即时预览。**
7. **不要学它默认开启"状态栏专注模式"这类与系统强耦合的开关**。它在 MIUI 上直接失效、在其他 ROM 上效果不一，属于"看起来高级但适配成本极高"的功能。HarmonyOS 上应先确认 API 层是否支持，再决定要不要做。
8. **不要学它对"数据全量备份不加密、且不做增量"**。自动备份整库 + 25 份保留在网络网盘上会产生很大流量（官方专门有一节讲"备份包很大使坚果云流量迅速用完"）。Weaver 的备份应考虑增量或压缩，并把单次备份体积作为一项可观测指标。
9. **不要学它的废纸篓"无全选、无清空"**。这是官方自曝的缺陷，直接导致大废纸篓会假死并可能引发闪退。Weaver 的废纸篓从第一天起就要支持多选、全选、清空。
10. **不要学它对"大文档"的硬性封锁**。纯纯写作禁止导入 300 KiB 以上的 TXT（因为会让应用假死）。对 Weaver 而言，这是性能问题而非产品问题——应该用分页 / 虚拟列表 / 后台解析去解决，而不是把用户的合法数据挡在门外。

### 附：对 Weaver 最值得优先采纳的 3 条（一句话版）

1. **顶栏"滚动即隐藏、输入即隐藏" + 打字机模式只高亮当前段**——用最低的实现成本把"专注写作"变成默认行为，直接回应 Weaver 当前"专注写作的干扰控制"痛点。
2. **两行式章列表（字数 + 相对时间）+ 悬浮字数胶囊（三口径 / 选中计数）**——直接回应"界面信息密度与简洁的张力"，同时不牺牲小说作者最在意的字数信息。
3. **"自动保存 + 每 2 秒一致性校验 + 保存失败不退出 + 恢复前自动备份"这一整套防丢失组合**——"绝不丢失"是竞品最被称道、也最容易建立用户信任的能力，且完全是工程实现，与 UI 复杂度无关。
