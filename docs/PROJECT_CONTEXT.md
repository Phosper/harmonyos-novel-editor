## 4. 产品目标与模型

一句话：把一门课里散落的观点与材料收进卡片，通过拖入嵌套拼出章、节、目的大纲，再生成一篇初稿，到既有编辑器继续写。

### 卡片、素材与章节

- 只有两种卡：**概念卡**和**写作卡**。两者都能装素材，也都能装子卡；写作卡额外提供“写成初稿”。
- **素材不是卡，章节就是子卡本身。** 不能把章节降为写作卡内的一行普通文本。
- 写作卡是论文容器，不是一块独立“论文白板”；旧“论文卡 / 独立论文白板”方案已被 r2 替代。
- 三层组织为章 `一、` → 节 `（一）` → 目 `1.`；这是当前默认中文编号体例。写作卡自身是第 0 层。
- 任何卡都可嵌套；检查深度必须算被拖动的整棵子树，并拒绝循环和跨白板父子关系。

### 卡片身份与贴放分离

- 卡片内容只存一份；同一张卡可在多块白板出现。
- 每块白板上的位置、父节点、同级排序、折叠状态属于该次 **placement（贴放）**。
- `parent_id` 指向同一白板中的另一个 placement，不能指向 topic，也不能把父子关系放在卡片实体上。
- 因此同一张卡在甲白板可以自由摆放，在乙白板可以成为某篇写作卡的第二章；内容修改共享，摆放互不干扰。

### 白板和卡片库

- 白板库包括课程白板与自由白板。课程白板绑定一门课，自由白板没有归属；写作卡不属于白板类型。
- 卡片库独立于单块白板，可搜索、放到当前白板、统计出现于多少块白板。
- 从白板移除只删该次贴放；删除卡片会删除所有白板的贴放；删除白板保留卡片内容。
- 子卡不随父卡被级联删除，应保留并重新安排位置；到底上提一层还是到顶层，原规格有冲突，见第 9 节。

## 5. 交互与视觉共识

- 入口固定为文稿列表中栏 **四点菜单 → 思路板**，不增加常驻一级 Tab；进入默认最近使用的白板。
- 手机是整屏白板；宽屏占据主工作区。整体可理解为左侧白板库、中间画布、右侧素材抽屉。
- 视觉延续内容优先、极简纸墨、克制色彩、清晰层级、深浅主题。原型的纸色与暖色提示用于表达方向，实现复用项目主题/动效令牌，不照抄 HTML 色值、阴影和 px。
- **C 型“张嘴”**：空卡没有占位；有子卡时出现左侧脊线；只有正在拖动并靠近合法目标时，才显示一个虚线嵌入口。
- 正式阈值：卡外扩 30vp，行外扩 8vp，行命中优先；嵌入口高 30vp，同一时刻最多一个，目标未变化不反复重建。
- 子卡显示为缩进行与自动编号，不是缩小卡片；行高 30vp，每层缩进 14vp，提供上移、下移、移出操作。
- 顶层卡拖入另一卡成为子卡；子卡可换父，拖到空白成为顶层；父卡移动带整棵子树；回当前父不变；自己和子孙不能成为目标。
- 右侧素材抽屉展示标题、别名、标签、我的一句话、素材、所在白板和层级；宽屏 392vp，手机全屏 sheet，支持 Esc 关闭。
- 有键盘与菜单替代操作；行可聚焦、Enter 打开，卡片提供标题、层级、子卡和素材数量的读屏说明。
- 原生 ArkUI 卡片配世界坐标是 r2 默认方向，`screen = world * zoom + pan`；研究 06 的纯 Canvas 推荐不作为当前选择。

## 6. 素材与写成初稿

- **引文 quote**：必须有原文锚点，保持原文并实时读取，带出处，可跳回原文。
- **判断 judgement**：用户的转述或论断，原文锚点可选。手工形成判断是核心价值，不能用关键词命中替代用户判断。
- **笔记 note**：完全自撰，不带原文锚点。
- 失效素材应灰化并支持重新绑定；“跳回原文”应定位、滚动并选中，不能只移动到不可见的光标位置。
- 写作卡按 `ord` 深度优先遍历，三层分别映射标题 1/2/3；素材成为正文并保留出处，每个节点下留 `【待展开】`。
- **首次生成新建一篇文稿，原稿不动**。标题记在 `format_runs`；Markdown 标记由导出层合成，不把 `#` 写入正文。
- 归属跟随写作卡所在课；自由白板生成稿进“未归类”。
- r2 §6.6 还规定保存生成稿 `doc_id`，再次生成前提示覆盖上一版初稿并可撤销。这里记录首次新建、再次更新关联生成稿的文档意图；真正实施时需把提示、覆盖对象和撤销能力一起验收，不能误伤素材原文或其他文稿。

## 7. 首版边界与后续空间

- 首版范围是**一门课**。多白板复用、自由白板及预留空归属字段不等于首版跨课/跨书汇聚。
- 首版不做图片/截图素材、跨书白板、自动连线、AI 生成、协作、导出图片、第四层嵌套。
- 原型里的均势、维也纳体系等案例只是演示，不是内置模板；示例连线也不自动构成额外需求。
- 旧六级 Unit、global/book/doc 作用域、独立论文白板、跨书快照、复习模式、旧工期和纯 Canvas 方案均不能重新当作首版要求。
- 可延续的设计思想是：正文不重复造一份真相、知识内容与呈现分离、观点和关系由用户确认。

## 9. 已知冲突与待统一细节

1. **删除非顶层父卡后的子卡位置**：r2 §2.4、研究 07 与原型规格写“上提为顶层并散开”；r2 §4.2 写“上提一层，继承被删 placement 的父亲”。两种结果不同。实施删除逻辑前集中澄清并同步三份材料，不能静默选定。
2. **编号是当前默认，不等于最终体例决定**：采用中文 `一、/（一）/1.` 理解原型；原文 Q1 仍允许后续确认英文体例。图片、图片导出与第四层虽也列在 Q 表，但首版范围已明确不做，不反复重问。
3. **初稿再次生成需要完整交互验收**：详细规格有覆盖上一版且可撤销的要求；原型只演示“新建一篇”的提示，没有真正保存、覆盖或撤销能力。
4. **引文失效恢复需细化**：规范要求实时读原文，表结构又预留 fingerprint / quote_text。摘要不据此擅定静态快照策略；实现时要明确锚点失效和重新绑定行为。
5. **原型与正式存储不能等同**：原型以 card id 表示父节点；正式模型必须以 placement id 表示。原型排序、尺寸和操作均有简化，实现以规格约束为准。
6. **原型不证明功能完成**：它演示内存中的拖嵌套、排序、移出、删除、板切换和卡片搜索；新建白板、素材、回原文、生成稿等部分仅提示，且无真实持久化、缩放和 Esc 处理。

这些细节不改变已经确定的卡片模型与首版范围。本轮不要求用户逐项决策；进入对应实现任务时再集中处理。
